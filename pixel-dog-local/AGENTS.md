# 개발 작업 지침

## 현재 화풍 기준: B2·C2 비교 정본

2026-11-02 사용자 지시에 따라 [B2·C2 규격](docs/b2-c2-style-spec.md)과 [정본 manifest](references/styles/b2-c2/v1/manifest.json)를 적용한다. B2는 원본 왼쪽, C2는 오른쪽이며 두 안 모두 비교 정본이다. 최종 단일 제품 화풍은 미선택이다. 이미지 모델을 사용하는 작업은 실제 참조 파일·해시·영역·style ID를 일치시켜 전달한다. 눈꺼풀·얼굴형·귀·무늬는 개체 프로필을 따르고, 과거 P1의 점눈·크레용 채움은 B2/C2에 공통 적용하지 않는다. 수치는 제작 기본값이며 실제 자산 검증 완료로 표시하지 않는다.

## 먼저 읽을 파일

`README.md` → `docs/decisions.md` → `docs/handoff.md` → 해당 작업의 연구 문서 순서로 읽습니다. 사용자 지시가 이 파일과 다르면 사용자 지시를 따릅니다.

## 제품 범위

- 개를 대상으로 실제 외형과 관찰된 행동을 반영합니다. 고양이는 후속 범위입니다.
- 픽셀 캐릭터의 기본 애니메이션은 8fps, 기본 프레임 간격은 125ms입니다. 동작당 프레임 수는 별개입니다.
- 픽셀 정본은 프레임당 64×64px입니다. 96×96 제작기 출력과 고해상도 화풍 시안은 참고 자료이며, 정본은 실제 64×64 격자에서 검수합니다.
- 첫 구현은 Android G0입니다. Kotlin 네이티브 표시 검증이 기본안이며 최종 공통 UI 프레임워크는 미정입니다.
- G0은 임시 캐릭터, 걷기·쉬기·잠든 자세, 탭·드래그·표시·종료를 검증합니다. 서버나 AI 연결은 G1 범위입니다.
- iOS와 Android의 표시 기능을 동일하다고 가정하지 않습니다. 홈 위젯을 연속 애니메이션 표면으로 전제하지 않습니다.

## 이미지 제작과 비교

사용자가 해제할 때까지 이 프로젝트에서 생성·수정한 모든 이미지는 전달 전에 현재 세션과 같은 모델의 새 적대적 리뷰어에게 보냅니다. 시안·비교판·애니메이션 모두 저장된 파일을 열어 **규칙 준수와 제작 방법론만** 검토합니다. 개체 자료 출처와 추정 구분, 파라미터 격리, 해상도·색 수·겹침·동공 범위, 재현성과 파일별 검토 여부를 확인합니다. 리뷰어가 닮음이나 미감에 순위를 매기거나 보호자 대신 후보를 승인하지 않습니다.

타당한 지적은 수정하고 최종 파일을 다시 검토받습니다. 미통과나 미검토 결과를 완료본으로 제시하지 않습니다. 리뷰어의 통과와 보호자의 닮음 승인은 구분합니다.

반복 작화 라운드는 같은 기준안에서 작은 파라미터 차이를 둔 시안 세 개를 병렬로 제작합니다. 각 시안의 변경점과 비교 조건을 기록합니다. 리뷰어는 세 파일에서 선언한 변경만 발생했는지 확인합니다. 규칙 위반은 수정하고, 표현 선택은 보호자가 결정할 수 있도록 분리해 제시합니다. 합친 파일에도 같은 검토를 적용합니다.

새 픽셀 작화에는 전신 외곽선 1색과 내부 최대 4색을 사용합니다. 광원을 정하고 덜 밝은 면을 어둡게 그립니다. 원본 1배에서 움직임과 개체 식별에 필요한 각 신체 부위가 음영이나 윤곽으로 구분되는지 확인합니다.

새 자산을 1배로 기존 자산 옆에서 확인하고, 비교판과 앱의 픽셀 장면은 최근접 이웃·정수 배율로 표시합니다. [격자·윤곽 제작 규격](docs/b2-c2-style-spec.md)의 4.1절을 기준으로 원본, 확대 보기, 실제 기기의 검수 결과를 구분합니다.

개체 이미지 제작은 [화풍 참조 분리 정책](docs/style-reference-policy.md)을 따른다. 현재 구현 순서는 [제작기 로드맵](docs/roadmap.md)이다. 계획된 제작기 실행은 검수된 개체 구조와 버전이 고정된 제작 패키지를 사용하고, 정본 이미지는 패키지 개발·회귀 검수에 사용한다. tools/static_maker에 정적 출력 프로토타입이 있다. 재현성 기술 검사는 통과했지만 정본 미감·개체 닮음은 미승인이므로 전체 제작기 완료로 표시하지 않는다. 다음 실제 이미지 모델 작업에서는 기존 참조 규칙을 유지한다. 사진과 실제 화풍 이미지의 역할·적용 영역을 나누어 도구에 전달하고, 텍스트 화풍 지시만으로 기존 화풍 준수를 주장하지 않는다. 결과의 개체 닮음과 화풍 일치 여부를 별도로 검수한다.

## 구현 기준

- 애니메이션 그림 교체, 입력 처리, 위치 이동, 행동 상태의 시간을 분리합니다. 이동·대기 시간을 프레임 호출 횟수에 종속시키지 않습니다.
- 좌우 비대칭 털무늬를 무조건 반전하지 않습니다. 기준점·캔버스 크기·접지선을 동작 사이에 유지합니다.
- 원본 관찰, 보호자 보고, 파생값, 제작 기본값을 구분합니다. 임시값은 실제 개의 습관으로 표시하지 않습니다.
- AI 후보는 보호자 확인과 근거 검사를 거친 뒤 사용합니다. 확인되지 않은 감정·의도·진단을 추론 결과로 확정하지 않습니다.
- 원본 영상 시각은 실제 타임스탬프를 사용합니다. VFR 영상을 고정 fps로 환산해 측정했다고 주장하지 않습니다.
- 실제 사용자 사진·영상·키·서명 파일은 Git에 넣지 않습니다. 외부 분석용 API 키는 모바일 앱에 내장하지 않습니다.
- 설치·실행하지 않은 코드의 동작, 실측하지 않은 비용·배터리·성능을 완료 결과로 보고하지 않습니다.

## 연구와 선택

관찰·형태와 렌더링·규격 검토는 현재 세션과 같은 모델로 병렬 진행한다. 별도 방법론 자문이 필요하면 `gpt-6-astra`의 `xhigh` 추론 강도를 사용한다.

기술 지원, 라이브러리, 모델 ID, 가격, OS 정책처럼 변할 수 있는 사항은 공식 문서와 실제 사용 버전으로 확인합니다. 조사 저장소의 기능 설명과 프로젝트에서 검증한 성능을 구분하고 출처를 남깁니다. 현재 AI 모델명은 기획 가정이며 G0의 의존성이 아닙니다.

## 변경 관리

리뷰 결과를 받으면 의견별로 사용자 요구, 현재 규격, 실제 변경 내용과 재현 가능한 사례를 대조합니다. 타당하고 현재 작업 범위에서 필요한 수정은 별도 확인을 기다리지 않고 반영한 뒤 검증합니다. 결과를 보고할 때는 반영한 내용과 검증 결과를 밝히고, 채택하지 않은 의견이 있으면 이유를 함께 설명합니다.

작업이 끝나면 `docs/backlog.md`와 `docs/handoff.md`의 상태를 갱신합니다. 새로운 결정은 근거와 함께 `docs/decisions.md`에 기록합니다. `docs/archive`와 `provenance/pages`는 가져온 기록으로 유지하고, 현재 설계 변경은 활성 문서에 작성합니다.

관련 없는 기존 파일을 변경하지 않습니다. 외부 저장소는 참고·도입 후보이며 아직 채택된 의존성이 아닙니다. 프레임워크·라이선스·서비스 범위를 임의로 확정하지 않고, 현재 목표에 필요한 작은 구현부터 진행합니다.
