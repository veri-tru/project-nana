## 자료를 읽는 순서

1. Excel의 **대표행동**에서 공통 행동과 연결된 세부 코드를 찾는다.
2. **행동기록**에서 출처·근거 유형·채택 상태와 K–Q열의 대표 행동, 종류, 통합 상황, 수집 방식, 속성, 근거 단위, 분류 주의점을 확인한다.
3. 행동 간 연결은 **행동관계**, 설계한 반복 단계는 **행동연쇄**에서 본다.
4. **개인화항목**에서 중복 제안과 사용자 요구의 연결을 확인한다.
5. 정정 전후 값과 조건부 통합 경계는 **필드설명**에 있다.

행동 종류는 자세·상태, 동작, 전환, 복합 활동, 종합 지표, 합산 행동, 과제 결과로 나눴다. 앉은 자세와 앉는 전환, 몸 털기와 잔떨림, 입 벌림과 헥헥거림은 구별한다. 머리 지지·높이·받침, 앞발·뒷다리 배치는 필요한 속성으로 연결한다.

## 이번에 바로잡은 내용

- 산책하자는 말에 반응한 C_KQ01_01과 실제 산책 중 E150–E154를 분리했다.
- 머리를 스스로 유지하는지와 외부 지지면에 맡기는지를 구별했다. 머리 높이만으로 휴식·수면을 판정하지 않는다.
- E070은 접촉·비접촉 앞발 동작의 합산 범주, E071은 입 조작의 합산 범주로 정정했다.
- E019는 독립 옆눕기 정의가 아닌 본문 언급으로 정정하고 근거 후보에서 제외했다. 별도 출처의 옆눕기 정의는 유지했다.
- C_KQ03_03은 자기 몸 핥기로 구체화했으며 건강 맥락 제외 상태를 유지했다.
- E171의 뒷다리 뻗기와 E192의 얼굴 긁기 범위를 명시했다. 부드러운 얼굴 문지름은 확인 대기 요구로 남겼다.

파기와 긁기, 기다림과 대기 과제 지표, 앞발 접촉과 물체 조작, 머리 돌림과 외면은 조건부 관계로 연결하고 코드를 유지했다. 출처가 합쳐 관찰한 범주는 임의로 분해하지 않는다.

| 저장 구조 | 역할 |

| behavior_nodes / behavior_concepts / node_concept_map | 기존 위계, 대표 행동, 세부형 대응과 사용 상태 |

| context_assessments | 긍정·부정·일상 평가의 공통 구조 |

기존 positive_assessments·negative_assessments·neutral_assessments는 공통 평가 테이블을 읽는 호환 조회다. 이전/후속·동시·대안의 양방향 조회는 v_relations_expanded로 제공한다. 실제 관계를 셀 때는 relations를 사용한다.

evidence_units의 303개 연결 단위는 독립 연구·표본 수가 아니다. E183/E184처럼 같은 표 항목을 나눈 경우와 반복 설계 정의를 묶었다. 나머지는 기록 기준의 대응이며 독립성을 확인한 것으로 보지 않는다.

## 결측과 근거 구분

NULL 또는 ‘미기재’는 정보가 없다는 뜻이며 행동 부재·0초가 아니다. 개별 지속시간·지연·반복 수·개체 식별값은 계속 비워 두었다. 연구 표본 수·집단 비율을 개인 행동 확률로 바꾸지 않았다. 속성의 근거가 기존 분류인지, 기록의 명시 내용인지, 설계 제안인지 따로 저장한다.

일상 평가는 중립 감정이나 정상성 판정이 아니다. 같은 기록에 긍정·부정 평가가 함께 있을 수 있고, 평가가 없는 경우도 부정 또는 중립으로 채우지 않는다. 사용자 요구를 포함했다는 사실과 실제 행동 관찰·자산 제작 상태는 별개다.

## 생성과 이력

원자료는 catalog.seed.json과 기존 커뮤니티 observations.json, 정정과 재조직화 기준은 organization.seed.json이다. 원자료의 버전은 1.3.1로 보존하고, 보완을 적용한 생성본은 2.0.0이다. 프로젝트 루트에서 `python tools/build_behavior_db.py`를 실행하면 임시 DB에서 무결성·참조·원본 보존·정정 이력을 검사한 뒤 SQLite와 JSON을 갱신한다. Excel은 별도 생성 과정이다.

[보완 전 1.3.1 스냅샷](archive/1.3.1/catalog.json)에 원기록·출처·관계·평가를 보존했다. 같은 폴더에 이전 seed·스키마·SQLite·Excel도 있다. 종전 조사 보고서의 수치는 당시 스냅샷을 설명한다.

대표 행동별 조회 예시:

```sql
SELECT record_id, concept_name, context_domain, collection_method,
       facets_text, claim_type, inclusion_status, source_url
FROM v_organized_records
WHERE concept_id = 'REST'
ORDER BY record_id;
```
