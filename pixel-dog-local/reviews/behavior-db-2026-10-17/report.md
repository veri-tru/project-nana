# 반려견 행동 DB 중복과 재조직화 검토

기준일: 2026-10-17. 대상: 누적 기록 307건, 행동 분류 187개, 출처 91개, 관계 83행.

**원자료와 출처별 기록은 보존하면서, 대표 행동과 속성·상황·연쇄를 다시 조직하는 것이 적절하다.** 먼저 고칠 것은 산책 상황의 잘못된 묶음, 머리 지지와 높이의 혼합, 앞발 행동의 과도하게 좁은 대응, 옆눕기 정의의 출처 연결이다. 내용이 같은 행을 일괄 삭제하면 설계한 연쇄의 반복 단계가 사라진다.

이번 결과는 검토안이다. DB 원자료·SQLite·JSON·Excel은 변경하지 않았다. 현재 자료의 무결성과 SQLite–JSON 일치를 확인했으며, 해석이 중요한 L04·L05·L32는 원문을 다시 확인했다. 모든 논문과 커뮤니티 진술을 새로 검증한 작업은 아니다.

## 권장하는 재조직화

### 행동의 종류와 자세 속성

R09에 따라 기존 8개 영역은 찾아보기용 분류로 유지하되, 그 안의 항목에 종류를 붙인다.

| 종류 | 현재 예시 | 관리 방식 |
| --- | --- | --- |
| 자세·상태 | 앉아 있음, 누워 있음, 입 닫힘, 수면 보고 | 지속하는 형태와 상태 판정 근거를 기록한다. |
| 동작·전환 | 앉기 전환, 고개 돌림, 재채기 | 시작·끝 상태와 움직이는 부위를 기록한다. |
| 복합 활동 | 가져오기 놀이, 물건 문 채 피하기, 자기 몸단장 | 구성 행동 또는 원연구의 합산 범주를 연결한다. 관찰하지 않은 순서를 만들지 않는다. |
| 종합 지표·과제 결과 | 활동량, 보상 대기 지표, 안내 따르기 | 단일 애니메이션 동작과 별도로 관리한다. |

자세는 몸통 방향, 앞발 배치, 뒷다리 배치, 머리 지지·위치를 조합할 수 있게 한다. 그러면 ‘엎드린 채 뒷다리를 뻗음’ 같은 개체 특징을 긴 설명 속에만 보관하지 않아도 된다. 원문이 특정하지 않은 속성은 빈값으로 둔다.

상위 행동과 세부 행동에 기록이 함께 붙는 것 자체는 오류가 아니다. 예를 들어 출처가 누웠다고만 보고하면 LIE에 남겨야 한다. 상위 분류 수와 하위 분류 수를 더해 서로 독립적인 행동 개수로 보고하지 않는 것이 중요하다.

현재 147개는 기록 가능한 코드 수이며, 그중 실제 연결이 있는 코드는 145개다. 직접 연결된 자료가 제안뿐인 코드는 10개이고, 근거 후보 조회에 나타나는 코드는 120개다. 이 120개도 정의·보호자 보고·학습 가능 보고를 포함하므로 검증된 습관 120종을 뜻하지 않는다. 정리 후 코드 개수는 대응표를 완성한 뒤 산출해야 한다.

### 상황과 수집 방식

R10에 따라 다음 축을 분리한다.

- 상황과 활동: 산책 중, 휴식 중, 재회, 놀이
- 직전 자극: 산책하자는 말, 보호자 움직임, 보상 중단
- 대상: 사람, 다른 개, 장난감, 먹이, 이불
- 수집 방식: 직접 영상, 보호자 보고, 실험 과제, 문헌 정의
- 표본 조건: 새끼·성견, 연령, 품종 등 출처가 제시한 범위

현재 S_SLEEP_REPORT는 수면과 보호자 보고, S_ROUTINE_CODING은 행동 정의라는 방법, S_PUP_OBJECT_PLAY는 연령과 물체 놀이를 함께 담고 있다. 공통 축으로 조회할 수 있게 바꾸되 기존 상황 문구는 원자료로 보존한다.

### 근거 기록과 대표 행동

R11의 핵심은 근거 기록과 행동 코드의 관계를 명시하는 것이다.

**출처 → 원문 근거 단위 → 행동 대응 → 상황과 속성 → 개인화 후보**

원문 근거 단위에는 표·행동명·문단 위치를 붙이고, 행동 대응에는 정확히 일치·더 넓음·일부만 해당·합산 범주 등의 구분을 둔다. E183과 E184는 L32의 같은 Lie on Object 정의에서 눕기와 구르기를 나누어 만든 기록이다. 둘을 별도 동작으로 사용할 수 있지만 독립 근거 두 건으로 세어서는 안 된다. [L32 Table 1](https://pmc.ncbi.nlm.nih.gov/articles/PMC10135149/)

같은 원칙으로 출처별 다른 정의와 같은 연구의 재사용을 보존한다. 논문 수, 원문 근거 수, 행동 코드 수, 실제 발생 수는 각각 집계한다.

### 행동 연쇄와 양방향 관계

R06의 반복 단계에는 연쇄 ID와 단계 순번을 둔다. 하나의 ‘걷기’ 정의를 여러 단계가 참조할 수 있게 하되 시작과 재개 단계는 서로 다른 단계로 보존한다.

R12의 관계 83행은 역방향과 대칭 표시를 정리하면 43개 관계 주장이다. 이 가운데 설계 제안 21개, 보호자 보고 관계 18개, 문헌 관계 4개다. 한 관계의 근거와 원본 방향을 저장하고 이전·후속 조회는 여기서 생성하면 수정 불일치를 줄일 수 있다. 같은 행동 코드로 이어진다는 이유만으로 서로 다른 출처의 관계까지 합치지 않는다.

### 맥락 평가와 출처 이력

R13에서는 긍정·부정·일상 평가를 공통 필드 구조로 묶고, 조사 분야와 해석 상태는 보존한다. E057·E058·E079·E080은 긍정과 부정 조사에 모두 등장한다. 두 평가가 있다는 것은 중복 오류도 감정 모순도 아니다. 일상 조사에 포함됐다는 이유만으로 중립 감정을 부여해서도 안 된다.

R14에서는 자료 확인 이력과 연구 결과를 분리한다. L32의 출처 정보는 원표를 읽은 상태로 갱신됐지만 E066–E071에는 예전 ‘원표 미추출’ 설명이 남아 있다. 과거 추출 시점과 현재 확인 범위를 각각 보존하면 이런 차이를 이해할 수 있다. F17과 F19는 행동 연구 결과보다는 자료 추가·포함 범위에 관한 작업 이력이므로 별도 이력으로 옮길 대상이다.

직접 기록이 없는 JUMP는 하위 JUMP_HIND를 묶는 역할이 있다. FRONT_SUPPORT는 기록 없는 후보, S_THREAT는 현재 미사용 상황이다. 이들은 상태를 표시해 관리한다. 기록이 없는 L15·L21·L24·L45·L51·L60은 종합 결과에, C011은 원수집에 연결돼 있으므로 자동 삭제 대상이 아니다. D04는 사용 여부를 정리할 수 있는 로컬 출처다.
