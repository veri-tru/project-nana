# 개체 프로필 기반 생성과 사용자 흐름

## 2026-11-02 보완: 실제 화풍 이미지의 필수 전달

[화풍 참조 분리 정책](style-reference-policy.md)을 생성 입력과 검수에 추가한다. identity_photo는 개체 외형, style_reference는 선·색면·생략 규칙을 담당한다. 실제 화풍 파일·버전·해시·참조 순서·사용 영역을 기록하고 생성 도구에 전달한다. 화풍 이미지의 얼굴·눈꺼풀·귀·무늬는 새 개체 프로필에 편입하지 않는다.

텍스트만의 “픽셀풍” 요청이나 정책 프롬프트의 존재는 화풍 준수 증거가 아니다. 결과는 개체 유지와 화풍 유지로 나누어 확인한다. 이후 사용자 지시로 [B2와 C2를 각각 비교 정본](b2-c2-style-spec.md)으로 등록했다. 각 정본의 파일·해시·사용 영역과 style ID/version을 전달한다. 전체 얼굴 승인이나 최종 단일 제품 화풍 선택은 아니다.

기준일: 2026-11-02. 상태: 설계 보완, 앱·저장소·생성 엔진 미구현.
사용자 지시: 사용자는 사진 제공, 표현할 털 선택, 행동 설정·결과 확인 정도만 수행한다. 외형과 동작은 프로필로 저장되어 같은 개체의 모든 후속 제작에 따라다녀야 한다.
이 문서의 사용자 단계·프로필 버전·선택 범위 규칙은 이전 문서의 다단계 사용자 입력 설명을 구체화한다. 외형 관찰·근거는 [개인화 설계](personalization-spec.md), 가림·접지·프레임 규격은 [자산 규격](asset-spec.md), 동작 충돌·복귀는 기존 얼굴·상황 정책을 따른다.

## 1. 사용자가 수행하는 세 단계

| 단계 | 화면과 사용자 행동 | 내부 처리 | 다음으로 넘어가는 기준 |
| --- | --- | --- | --- |
| 1 사진 등록 | 사진을 올린다. 새 개체 등록과 기존 개체 사진 추가를 구분한다 | 고유 개체 ID 생성 또는 기존 ID 선택, 자료 연결, 외형 후보 추출, 사진별 시점·가림·충돌 기록 | 자료 사용 가능 여부 확인. 보이지 않는 모든 부위를 채우도록 강제하지 않음 |
| 2 털 선택·모습 보기 | 짧게·중간·길게 등 지원되는 털 표현을 고르고 생성 모습을 본다. 필요 시 “귀가 너무 길어요”처럼 수정 | 같은 개체 외형에 털 설정 적용, 전신 후보 생성·일관성 검사, 수정의 대상 속성과 범위 기록 | “이 모습으로 계속” 또는 수정. 미확인 속성을 모두 확정할 필요 없음 |
| 3 행동 설정·결과 확인 | 평소 행동·자세를 고르거나 모름·나중에를 선택하고 움직이는 결과를 확인한다 | 보호자 응답을 행동 프로필에 저장, 지원 자산 연결, 동작별 외형·전환 검사 | 사용 가능한 결과를 확인하고 사용 시작. 선택하지 않은 개인화 행동은 보류 |

화풍·데포르메·해상도·레이어·눈꺼풀 모양을 기본 등록 과정의 필수 질문으로 만들지 않는다. 제품의 화풍 규칙은 별도로 정하고 버전으로 관리한다. 현재 B2와 C2는 비교 정본이고 최종 단일 제품 화풍과 최종 해상도는 미정이다. 식별 특징 최대 3개도 내부 검수 우선순위로 쓰며 별도의 필수 설문으로 늘리지 않는다. 사용자가 수정·강조한 특징을 우선 반영하고, 자동 후보는 후보 상태로 유지한다.

현재 사진에 가까운 털 표현을 선택 가능한 후보로 미리 보여줄 수 있으나 미선택을 사용자 선호로 저장하지 않는다. 미지원 털 옵션은 준비된 것처럼 표시하지 않는다. 부위별 털 조절은 필요한 경우의 수정 흐름으로 둔다.

추가 질문은 닮음에 중요한데 가려졌거나 근거가 충돌한 부분에 한해 해당 화면 안에서 짧게 제시한다. 추가 사진·설명·모름·나중에를 허용한다. 필수 정보가 없는 방향·자세는 미지원으로 남기고 지원되는 범위의 시안을 제공한다. 검수된 자산이 없으면 정적 미리보기 또는 준비 상태를 표시하며 동작 실행 완료로 보이지 않게 한다.

행동 카드는 “평소 한쪽 앞발을 들고 있나요?”처럼 실제 행동을 묻는다. 보고 싶은 연출을 고르는 기능이 생기면 실제 습관과 별도 저장한다. “이 모습으로 계속”은 보여준 외형 표현에 대한 수락이며 가려진 해부학적 특징이나 관찰하지 않은 습관을 확인한 것으로 처리하지 않는다.

## 2. 개체 프로필을 필수 기준으로 사용한다

이름·품종·사진 파일명이 아닌 변경되지 않는 dog_id를 사용한다. 같은 개체의 외형과 행동은 항상 이 ID에 연결한다. 다른 개체로 전환하면 자료·프로필·자산·생성 작업도 해당 ID로 함께 전환한다. 비슷한 사진이나 같은 이름만으로 프로필을 합치지 않는다. 사진 추가는 기존 개체 화면에서 하고, 여러 마리 또는 대상이 불분명하면 대상 확인을 요청한다.

| 구성 | 책임과 주요 필드 |
| --- | --- |
| 개체 | dog_id, 표시 이름, 소유·접근 범위, draft_revision, active_release_id, 삭제 상태 |
| 근거 목록 | evidence_id, dog_id, 사진·영상·보호자 응답, 시점·방향·반전 여부·가시성, 원본 접근·삭제 상태 |
| 외형 | 체형·비율, 얼굴·주둥이·귀·꼬리, 눈과 눈꺼풀, 색·부위별 무늬·좌우 차이, 관찰된 털, 식별 특징 후보 |
| 행동 | concept_id, 자세 변형, 상황, 한다/하지 않는다/모름 등의 상태, 빈도·지속·순서·선호, 근거와 보호자 확인 |
| 표현 설정 | render_preferences_id와 버전, 표현할 털 길이, 부위별 조정, 제작용 비율·색 단순화, 선택 범위·수정 이력 |
| 제품 화풍 | style_policy_id와 버전, 픽셀·윤곽·색·명암 표현 규칙. 개체의 실제 외형과 별도 관리 |
| 기준 자산 | reference_asset_id, 정확한 버전·파일 해시, dog_id, 생성에 사용한 프로필 버전, 표현 설정·화풍, 검수·선택 범위 |
| 수정 이력 | 이전/새 값, 변경 사유·근거·주체, 대상 속성, 적용 범위, 이전 버전 |

외형 속성은 기존 value, side, evidence_kind/ref/status, visibility, owner_review, value_role 등을 유지한다. 행동도 실제 관찰·보호자 보고·공통 제작값을 구분한다. 빈도 미확인은 0이나 추정된 일상 빈도로 채우지 않는다. 문헌의 행동 코드가 존재한다고 해당 개체의 행동 프로필에 실제 습관으로 넣지 않는다.

프로필은 개체의 참조 기록이지 생물학적 사실을 자동 확정하는 장치가 아니다. 새 미용 사진·성장·새 보호자 설명은 시점과 함께 기록한다. 생성 그림 자체를 외형 관찰의 새 근거로 역입력하지 않는다. 표현할 털을 바꿔도 사진에서 관찰한 털 기록, 눈매·귀·무늬·행동은 유지한다.

초안은 단계마다 저장해 재접속·다른 작업에서도 이어간다. 대화 맥락이나 생성 모델의 기억에만 의존하지 않는다. 구체적인 서버·DB·동기화 기술은 미정이며 클라이언트 재시작 이후 복구와 개체 간 격리를 구현 완료 기준으로 둔다. 개인 원본과 실제 개체 프로필은 공개 Git에 저장하지 않는다.

## 3. 선택·수정은 범위를 명시한다

모든 선택에는 selection_id, dog_id, 후보 자산 ID/버전, selection_scope, 제외 범위, 사용자 지시, 이전 프로필 버전을 기록한다. 숫자 “2번”만 저장하지 않고 어떤 비교표의 어떤 부분인지 연결한다.

| 사용자 표현 | 저장·적용 범위 | 자동 변경하지 않을 것 |
| --- | --- | --- |
| “2번 눈꺼풀” | 눈꺼풀·털 겹침의 표현 참고 | 얼굴 전체, 눈 크기, 귀, 주둥이, 체형, B/C 화풍 |
| “털은 짧게” | 표현 설정의 털 길이와 필요한 가림 | 관찰된 털 기록, 눈매, 무늬 위치, 행동 |
| “귀가 너무 길어요” | 귀 길이 수정 후보와 보호자 보고, 변경 전후 결과 | 다른 부위와 행동. 실제 사진 측정값으로 자동 승격하지 않음 |
| “이 모습으로 계속” | 현재 보여준 외형 자산·표현 버전 수락 | 개체의 미확인 사실과 미제시 방향·동작·행동 빈도 |
| “이 행동은 안 해요” | 해당 행동·상황의 보호자 보고와 제외 규칙 | 외형, 다른 상황의 행동, 임상·감정 판단 |

수정 지시는 우선 해당 개체 초안에 저장하고 다음 제작의 입력으로 사용한다. 생성 실패 때문에 수정 지시를 잃지 않는다. 단순 제작 오류라면 프로필을 그림에 맞춰 바꾸지 않고 프로필을 유지한 채 해당 자산을 수정한다. 실제 특징 정정과 일회성 연출 요청이 구분되지 않을 때만 짧게 범위를 확인한다.

승인된 필드·자산을 새 사진이나 모델 후보가 자동으로 덮어쓰지 않는다. 차이는 변경 후보로 두고 같은 결과 화면에서 수정 전후를 확인한다. “2번” 선택을 전체 얼굴 승인으로 확대한 최근 전신·동작 시안은 기준 자산으로 등록하지 않는다.

## 4. 생성 입력을 고정한다

개체 자산의 모든 생성·재생성·동작 확장 작업에는 아래 묶음을 필수로 연결한다. 개체와 무관한 화풍 연구는 style_study로 구분하고 개체 결과로 자동 등록하지 않는다.

| 입력 | 규칙 |
| --- | --- |
| job_id, dog_id, profile_revision | 동일 작업은 변경되지 않는 프로필 스냅샷을 참조. “최신 값”을 작업 중 다시 읽어 섞지 않음 |
| appearance_revision, behavior_revision | 한 profile_revision이 참조하는 외형·행동 하위 버전 |
| render_preferences_id/version, style_policy_id/version | 개체 표현 선택과 제품 화풍을 명시 |
| evidence_refs, reference_asset_refs | 해당 개체의 접근 가능한 근거와 검수 범위에 맞는 기준 자산. 삭제 원본은 재전송 금지 |
| action_request | 정적 자세 또는 행동 코드·변형·방향·상황·시작/끝 자세 |
| invariants, allowed_changes | 유지할 개체 속성과 이번에 바꿀 표현·동작 범위 |
| unresolved_fields, design_defaults | 미확인 속성과 임시 제작값을 분리하고 사용 범위 명시 |
| generation_recipe | 도구·모델/설정·요청문 버전, 입력 자산 해시, 재시도 관계. 수집 가능한 정보만 기록 |

정적 첫 시안에는 기준 자산이 아직 없을 수 있다. 이때도 dog_id와 초안 프로필 스냅샷은 필요하다. 첫 전신 후보를 보여주고 외형 표현을 수락받은 뒤 그 버전을 후속 동작의 기준으로 삼는다. 원본 사진만 다시 던지거나 프롬프트에 “같은 강아지”라고 적는 것으로 프로필 전달을 대체하지 않는다.

포즈별 허용 변화는 머리·몸의 회전, 관절·발 접촉, 눈 감기, 턱·혀 등 요청한 동작이다. 눈매·얼굴과 몸의 기본 비율, 귀 부착 형태, 큰 무늬와 좌우 정보는 유지한다. 투영과 가림으로 달라 보이는 경우는 실제 속성 변경과 구분한다. 눈꺼풀과 앞쪽 털은 별도로 제어하며 가려진 눈의 경계를 임의로 확정하지 않는다.

## 5. 초안과 사용 중인 결과를 분리한다

1. 사진·응답·수정 → draft 프로필의 새 revision 저장. 같은 base_revision에서 충돌한 수정은 재비교하며 마지막 저장으로 덮어쓰지 않는다.
2. 해당 revision 고정 → 생성 후보와 자동·제작 검수 기록 생성. 실패·미시험 자산은 실행 묶음에 들어가지 않는다.
3. 보호자의 화면 내 확인 → 선택 범위에 한해 review 저장. 외형 표현 수락과 개체 사실 확인은 다른 기록이다.
4. 사용 가능한 외형·동작·전환과 행동 설정 → release 후보 구성.
5. 개체 ID, 기준 버전, 검수·지원 범위가 맞으면 active_release_id를 한 번에 전환한다. 새 얼굴만 먼저 바뀌고 예전 몸·동작이 섞이지 않는다.

release에는 dog_id, profile_revision, 표현·화풍 버전, 자산/클립/전환의 정확한 버전, 검수 결과, 활성 행동과 미지원 목록을 묶는다. 이전 자산을 재사용하려면 새 프로필과 동일하게 유효한 범위임을 검사하고 release에 재사용 판정을 남긴다. 생성 당시의 원래 버전 이력은 바꾸지 않는다.

새 revision 작업 중 더 최신 수정이 들어오면 오래된 결과는 stale 후보로 보관하며 자동 활성화하지 않는다. 현재 초안과 차이를 재검사하거나 새 작업을 만든다. 활성화 직전 expected active/draft revision을 확인해 경합을 막는다. 생성·저장 재시도는 동일 job/request ID로 중복 적용을 방지한다.

실패하면 초안·수정 요청은 유지하고 마지막으로 사용 가능했던 release를 유지한다. 최초 생성이면 준비/재시도 화면을 제공한다. 되돌리기는 과거의 검수된 release를 사용 대상으로 다시 선택하는 작업이며 수정 이력을 삭제하지 않는다. 삭제된 개체·원본 접근권한을 되살리는 수단으로 사용할 수 없다.

미확인 사실이 남아도 범위가 명확한 제작 기본값으로 수락된 표현은 제공할 수 있다. 그 값은 개체의 확인 사실이 되지 않는다. 개인화 행동은 보호자 확인과 근거 규칙을 충족한 것만 활성화한다. 공통 걷기·쉬기·잠든 자세는 제작 기본 동작으로 구분하고, 검수된 호환 자산이 있을 때만 제공한다. 사용자가 특정 상황에서 하지 않는다고 한 행동을 공통 기본값으로 다시 켜지 않는다.

## 6. 수정의 영향을 후속 자산에 전달한다

| 변경 | 보존 | 재생성·재검수 범위 |
| --- | --- | --- |
| 눈매·눈꺼풀·귀 수정 | 다른 확인된 외형, 털 선택, 행동 근거 | 얼굴이 보이는 기준 이미지·포즈·깜박임·고개 회전과 해당 전환 |
| 표현할 털 길이 | 실제 관찰값, 체형·무늬, 행동 프로필 | 털 실루엣·눈 가림·부위 겹침·영향받는 동작 |
| 체형·다리 비율 | 확인된 얼굴·색·행동 근거 | 전신·걷기·앉기·눕기·접지·부착·전환 |
| 한쪽 무늬 | 반대쪽 근거, 행동 | 해당 면이 보이는 자산과 회전·가림. 자동 좌우 반전 금지 |
| 행동 빈도·상황만 수정 | 외형과 호환 검수된 그림·클립 | 선택·발생 규칙 검수. 동일 그림의 재생성을 강제하지 않음 |
| 새 자세 변형 | 외형 프로필·기존 지원 동작 | 새 클립·진입/복귀 전환과 기존 부품 호환 |
| 제품 화풍 변경 | 개체 사실·행동 근거 | 영향받는 전체 외형·동작을 새 표현 버전으로 검수. 자동 일괄 교체 금지 |

자산별 depends_on_fields와 검수된 입력 버전을 기록한다. 영향 범위를 확신할 수 없으면 해당 자산 묶음 전체를 재검수 대상으로 둔다. 프로필을 고쳤다는 이유만으로 기존 이미지도 수정 완료로 표시하지 않는다.

## 7. 검수와 상태 표시

기계적으로 확인할 것은 ID·버전·파일·크기·메타데이터·자산 지원 목록이다. 닮음, 무늬 위치, 귀 형태, 눈과 털 겹침, 접지와 동작 자연스러움은 제작 검수와 보호자 평가가 필요하다. 이미지 모델 점수 하나로 닮음 통과를 확정하지 않는다. 판정 기준·도구·오차 범위가 미정인 항목은 미시험으로 둔다.

정적 후보 → 외형 표현 수락 → 포즈 검수 → 실제 표시 크기·8fps 연속 재생 검수는 별개다. 정적 한 장을 수락했다고 모든 방향·동작을 승인 처리하지 않는다. 사용자에게 매 프레임 승인을 요구하지 않고 내부 검사 후 대표 동작 미리보기로 결과를 확인하게 한다. UI에는 “사용 중”, “수정 중”, “아직 준비되지 않은 동작”처럼 결과 중심 상태를 보여주며 버전·해시·레이어 표를 기본 화면에 노출하지 않는다.

## 8. 자료 삭제와 프로필 지속성

프로필은 개체에 지속적으로 연결되지만 사용자 삭제 요청보다 우선하지 않는다. 원본만 삭제하면 해당 근거는 접근 불가로 표시하고 보유가 허용된 프로필·결과물만 유지한다. 개체 삭제 시 초안·사용 묶음·전용 자산·진행 중 생성과 캐시를 삭제 범위에 연결한다. 늦게 도착한 생성 응답은 활성화·재등록하지 않는다. 공유 공통 클립과 다른 개체 자산은 구분한다. 외부 처리·백업을 포함한 실제 삭제 완료 확인과 보관기간은 기존 삭제 설계를 따르며 현재 미구현이다.

## 10. 구현 순서와 범위

G0의 임시 캐릭터 표시·입력·종료 검증은 그대로 진행한다. 이 설계는 G1 개인화의 저장·생성 계약이다.

1. dog_id, 근거·외형·행동·표현 설정과 스냅샷 저장, 선택 범위·수정 이력부터 구현.
2. 3단계 화면과 재접속 복구, 미확인·충돌 처리 연결.
3. 프로필을 반드시 받는 정적 생성 요청과 기준 자산 검수 구현.
4. 동작 생성·자산 의존 관계·영향 분석 및 release 단위 전환 구현.
5. 위 시나리오와 첫 개체 닮음·실제 크기·8fps를 검증한 뒤 체형·개체 확장.

공급자·모델·DB·서버·리깅 엔진, 보관기간, 구체 검수 오차는 아직 선택하지 않았다. 이번 산출물은 설계 문서와 설정의 대응 기록이며 위 기능의 구현 완료가 아니다.
