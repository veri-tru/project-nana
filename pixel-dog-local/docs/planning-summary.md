# 반려견 모바일 펫 기획 종합 정리

기준일: 2026-10-18. 현재 기획은 **실제 반려견을 닮은 외형과 익숙한 행동을 작은 2D 픽셀 캐릭터에 반영하는 모바일 펫 앱**이다. 행동 개인화를 핵심 차별점으로 두고, 미리 만든 외형·동작을 사진과 짧은 보호자 응답에 맞추는 방식을 검토한다. 첫 입력에서 영상 제출 부담을 줄이는 것이 우선이다.

공통 값과 결정 상태는 [현재 사양](current-spec.md)에 모았다. 10월 18일 검토 의견을 반영한 [개체 개인화 설계](personalization-spec.md)는 속성별 확인 상태, 부품·동작 호환, 특징 최대 3개의 닮음 검수와 출처·삭제 흐름을 다룬다. 세부 규칙은 설계 초안이며 실제 제작·평가 결과와 구분한다.

[세부 로드맵](roadmap.md)은 사진·응답으로 시작해 닮은 외형과 익숙한 행동을 확인하고, 일상 사용·수정·구매 검토로 이어지는 목표 경험을 작업에 연결했다. 개발·자산 제작 병행을 가정한 12주 계획이며, 실제 제작 시간과 인력에 따라 다시 산정한다. 6주차 A/B, 7일 파일럿과 원가·구매 조건 검토를 배치했으며 공개 출시일은 미정이다.

기획·문헌조사·행동 DB 정리와 외형 자료 활용 검토를 마쳤다. 실제 앱, 개체용 동작 자산, 자동 fitting, 고객 인터뷰와 A/B 테스트는 아직 실행하지 않았다. 서비스명은 미정이다.

## 고객과 사용자 니즈

첫 대상은 현재 반려견을 기르는 보호자다. **20대 여성은 첫 고객 후보, 30대 여성은 유료 개인화 구매 후보로 검증**한다. 국내 모바일 펫 게임의 결제 주력층으로 확정된 집단이라는 뜻은 아니다. 두 집단 모두 이용과 구매를 확인하고 남성 보호자는 비교군으로 검토한다.

공개 리뷰 조사에서 다음 요구를 확인하거나 검증 항목으로 도출했다. 실제 우선순위와 집단별 차이는 인터뷰가 필요하다.

- 얼굴·귀·무늬·체형과 움직임에서 자신의 강아지를 알아보고 싶다.
- 잠깐 보거나 반응을 주고받는 것만으로 만족하고 싶다.
- 입력과 수정이 간단하고 마음에 들지 않는 부분을 고칠 수 있기를 원한다.
- 돌봄 의무, 반복 광고, 복잡한 결제 조건과 화면 방해의 부담을 줄이고 싶다.
- 결과물을 간직하거나 공유하는 가치도 검토할 만하다.

미리보기·수정 범위·저장·공유·광고 정책은 아직 출시 기능으로 확정하지 않았다. 기존 조사에는 추모 이용 사례도 포함되어 있으므로 현재 양육자의 요구와 구분한다. [고객 가설과 니즈 조사](customer-needs-2026-10-17.md)

## 사용자 경험과 입력 방식

현재 우선 검토 흐름은 다음과 같다.

1. 임시 캐릭터를 보고 간단히 만져 보며 앱의 경험을 이해한다.
2. 기존 사진으로 외형 후보를 만들고, 품종을 알면 참고값을 사용한다. 믹스견이나 품종을 모르는 개도 특징을 직접 선택할 수 있도록 검토한다.
3. 보호자가 사진과 다른 외형 부분을 수정한다. 털에 가린 부분이나 반대쪽 무늬는 미확인으로 남긴다.
4. 동작 예시를 보면서 평소 쉬는 자세, 부를 때 반응, 요구 방식, 따라오는 경향 등을 선택한다. 해당 없음·잘 모르겠음도 허용한다.
5. 동작·속도·반복·순서의 미리보기를 보고 수정한 뒤 프로필을 적용한다.
6. 일상에서는 앱 안이나 지원되는 표시 방식으로 캐릭터를 보고 상호작용한다. 필요할 때 사진·응답·짧은 영상을 추가한다.

| 입력 | 반영할 내용 | 한계 |
| --- | --- | --- |
| 사진 | 외형, 직접 보이는 자세와 부위 배치 | 빈도·반응 지연·헥헥거리는 리듬은 확인할 수 없음 |
| 보호자 응답 | 자주 보이는 행동, 발생 상황, 대표 자세·순서 | 직접 관찰과 구분해 보호자 보고로 저장 |
| 선택적 영상 | 실제 움직임과 전환, 확인 가능한 시간 정보 | 잘 나온 영상만으로 일상 발생확률을 산출하지 않음 |
| 제작 기본값 | 재생 속도·대기시간·프레임 유지시간의 초기 설정 | 실제 측정된 습관처럼 표시하지 않음 |

초기 상세 설계의 방향별 사진·반복 촬영·영상 제출 계획은 고도화 단계의 참고로 남긴다. 첫 경험에는 영상 제출을 필수로 두지 않는 최근 방향을 우선한다.

## 행동 개인화

개인화는 행동 이름을 고르는 데서 끝나지 않는다. **상황 → 반응 여부 → 자세·동작 → 지속·반복 → 후속 행동**을 연결한다. 예를 들어 보호자가 선택한 경우에만 부름 뒤 고개를 돌리고 잠깐 기다렸다가 다가오는 순서를 사용한다. 이는 제작 규칙이며 모든 개의 보편적 행동 순서가 아니다.

| 요소 | 맞출 내용 | 현재 상태 |
| --- | --- | --- |
| 앉기·눕기·휴식 | 몸통 방향, 앞발·뒷다리 배치, 머리 지지, 대표·보조 자세 | 개인화 검토 방향 |
| 고개·접근·머무르기 | 바라보는 대상, 접근 여부, 대기와 전환 순서 | 우선 검토 후보 |
| 앞발 사용 | 허공 들기, 유지, 짧은 접촉, 얹기와 좌우 차이 | 구분하여 검토 |
| 꼬리 | 형태에 맞는 흔듦, 발생 상황·폭·리듬 | 검토 후보 |
| 몸 털기 | 발생 상황, 반복과 후속 행동 | 별도 동작 포함 확정 |
| 기지개 | 자세·유지·발생 상황과 앞뒤 전환 | 별도 동작 포함 확정 |
| 입·두 발 서기 | 입 벌림과 헥헥거림, 두 발로 서기와 지지물 사용 | 추가 검토 방향 |
| 탐색·놀이·물체 조작 | 냄새 맡으며 이동, 놀이와 물체를 다루는 특징 | 자료 확보, 제작 우선순위는 미정 |

초기 G1의 기본 동작 8종은 기본 자세·걷기·고개 돌리기·앉기·눕기·일어나기·꼬리 흔들기·앞발 들기다. 이는 자산 구성 초안이다. 문헌조사에서 제시한 우선 개인화 요소 8개와 구분하며, 사용자 지정인 몸 털기·기지개를 별도로 포함한다. 첫 개체의 대표 행동 최대 3개도 기존 설계 제안이며 최종 확정 수량이 아니다.

긍정·부정·중립적 일상 행동, 사람에 대한 신뢰 관련 행동, 커뮤니티의 습관 보고와 추가 후보를 폭넓게 조사했다. 조사 DB에 포함됐다는 이유만으로 모든 행동을 제품에 넣거나 해당 개체의 감정·건강 상태를 판단하지 않는다.

## 행동 DB의 현재 상태

버전 2.0.0은 행동 영역 → 동작군 → 구체 행동 → 세부 변형의 기존 위계를 유지하면서 대표 행동·속성·상황·연쇄를 분리했다.

| 항목 | 현재 규모 | 해석 |
| --- | ---: | --- |
| 출처별 기록 | 307건 | 행동 발생 횟수나 개체 수가 아님 |
| 대표 행동 | 121개 | 연구·설계를 위한 분류이며 완성된 애니메이션 수가 아님 |
| 출처 | 91개 | 문헌 66, 커뮤니티 19, 설계 4, 사용자 요구 2 |
| 자세·동작 속성 | 70행 | 형태와 세부 차이를 분리 |
| 관계 | 43개 | 기존 ID 83개를 통한 양방향 조회 유지 |
| 설계 연쇄 | 8개·27단계 | 반복 단계 보존, 관찰된 고정 순서와 구분 |

8개 행동 영역은 이동과 위치, 자세와 휴식, 머리와 방향, 접촉과 앞발, 입과 발성, 꼬리와 몸통, 물체 다루기, 활동과 반응이다. 원기록과 수정 이력을 보존했고 DB·Excel 대조 검증을 통과했다. 산책 상황, 머리 지지, 앞발·입 합산 범주, 옆눕기 근거 연결 등을 정정했다.

## 외형 자료 활용안

첨부된 품종 322종 자료는 9개 몸통 계열, 14차원 외형 태그, 45개 논리 파트 유형을 제시한다. 품종별 외형의 참고 사전으로 사용할 수 있으며 ID·태그·집계의 일치 여부를 확인했다. 현재는 활용 검토까지 완료했으며 실제 외형 DB 편입이나 자산 제작은 하지 않았다.

외형 참고값, 개체별 외형 프로필, 행동 프로필, 실제 자산의 호환 정보를 나누어 연결하는 안이다. 품종 기본값보다 개체 사진과 보호자 확인을 우선하며, 몸통 코드로 행동·성격을 결정하지 않는다.

63개 품종에는 미확인 태그가 남아 있고, 복수 옵션의 조합 조건 중 일부는 설명문으로만 존재한다. ZIP에 실제 캐릭터 자산이나 원사진은 없다. 45개 유형을 최종 그림 수나 제작 공수로 해석하지 않는다. 10월 17일의 체형 4종·동작 4종 시험은 확장 검토안으로 남긴다. 10월 18일 보완안에서는 균형형 한 마리의 외형과 호환·닮음을 먼저 확인하고, 짧고 긴 체형과 넓은 체형으로 순차 확장한다. 모든 몸통의 실제 지원 상태는 미시험이다.

## 표현과 개발 구조

- 기본 8fps를 사용하되 동작마다 프레임 수와 유지시간은 다르게 둘 수 있다. 입력·화면 이동·상태 체류시간은 프레임 재생과 분리한다.
- 픽셀 크기와 화풍은 실제 표시 크기에서 외형과 동작이 구분되는지 보고 정한다. 96×96 기존 시안은 참고물이다.
- 미리 제작한 동작 자산과 확인된 프로필을 기기에서 재생한다. 평소 움직임마다 AI를 호출하지 않는다.
- AI는 등록·추가·재분석 때 후보 추출과 응답 구조화에 사용하는 안이다. 공급자·실제 모델 연결·비용·처리 성능은 미검증이다.
- Android G0은 Kotlin 네이티브 표시 검증을 기본안으로 둔다. 공통 UI 프레임워크와 iOS·위젯의 구체 동작은 별도 검토한다.
- 프레임 사이 무늬·기준점·접지선을 유지하고 좌우 비대칭을 보존한다. 실제 파일과 검수 결과가 있는 자산만 사용 가능으로 등록한다.

## 중간점검과 고객 검증

중간점검 A/B 테스트는 같은 외형으로 기본 행동 A와 보호자 응답에 맞춘 행동 B를 비교한다. 10월 18일 보완안은 공통 클립 목록과 같은 작화·전환 자산 버전을 사용하고, 첫 비교에서는 행동 선택·빈도·발생 타이밍만 바꾼다. 클립 내부 속도, 표시 크기와 총 제시 시간은 고정한다. 빈도 차이를 시험하므로 실제 재생 횟수는 기록하되 같게 강제하지 않는다. 제시 순서를 교차하고 개인화 여부를 먼저 알려 선호를 유도하지 않는다. 세부 통제안은 [개체 개인화 설계](personalization-spec.md)에 있다.

핵심 질문은 어느 쪽의 행동이 더 자기 강아지다운지와 그 이유다. 차이 없음·둘 다 닮지 않음·판단 어려움을 허용한다. 외형 닮음·귀여움·우리 강아지다운 행동을 각각 평가하고 자연스러움·계속 사용 의향, 응답 시간·수정 횟수·입력 부담을 별도로 기록한다. 외형의 닮음은 보호자가 고른 특징 최대 3개를 중심으로 행동 비교 전에 확인한다.

20대·30대 여성에게 동일 과제를 적용한다. 구매 의향, 실제 자료 제출, 제작 완료, 실제 결제는 서로 다른 결과로 기록한다. 행동 개인화의 차별화 방향을 유지하면서 어떤 행동 요소와 입력 방식이 효과적인지 개선한다.

인터뷰 20대 여성 6명·30대 여성 6명·남성 비교군 4명, 시제품 7일 사용, G2의 5~10마리·30~50장면은 기존 제안 규모다. 표본·일정·정량 통과 기준은 확정하지 않았으며 모집·인터뷰·결제 실험도 미실시다.

## 사업 가설과 미결정 사항

수익은 일회성 개인화 결과물과 선택형 확장 구매를 우선 가설로 둔다. 보호자가 체감하는 추가 가치, 제작·수정에 드는 시간과 비용을 확인한 뒤 가격과 판매 범위를 정한다. 기존 문서의 가격 예시는 실험 후보이며 확정 가격이 아니다. 구독·광고·공유·꾸미기 기능의 범위도 미정이다.

서비스명, 최종 해상도·팔레트·화풍, 초기 지원 체형과 행동 수, 입력 문항과 수정 범위, 제작 도구, 실제 AI 연결, 최소 지원 OS·테스트 기기, 데이터 보관·삭제의 구체 조건, 가격과 출시 범위를 결정해야 한다. 이 항목 전체를 확정해야 G0을 시작할 수 있는 것은 아니다.

## 개발 순서와 다음 작업

| 단계 | 목표 | 현재 상태 |
| --- | --- | --- |
| M0 고객 검증 | 고객·가치·입력 부담·구매 조건 확인 | 공개자료 조사 완료, 인터뷰·결제 검증 전 |
| G0 Android 표시 | 걷기·쉬기·잠든 자세, 탭·드래그, 켜기·끄기·권한·종료 | 구현 착수 전 |
| G1 한 마리 개인화 | 외형과 행동 프로필, 자산 연결, 미리보기·수정 | 설계와 자료 준비 |
| 중간점검 | 동일 외형의 기본 행동과 개인화 행동 비교 | 계획 확정, 비교 시제품 전 |
| G2 탐색 파일럿 | 여러 개체에서 제작·수정·입력 부담과 재사용성 확인 | 제안 단계 |
| G3 플랫폼 확장 | iOS와 양 플랫폼 위젯 등 검토 | 후속 |

다음 작업은 두 흐름으로 나누어 진행할 수 있다. 개발은 기존 G0 범위의 표시·입력·종료 검증부터 시작한다. 개인화 준비는 첫 개체 또는 시험 체형, 우선 동작, 사진·선택 질문과 미리보기 규칙을 구체화한다. 외형·동작 비교물이 준비되면 중간점검 A/B를 실행한다. 자료 전체를 곧바로 구현 목록으로 바꾸지 않는다.
