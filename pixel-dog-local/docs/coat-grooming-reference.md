# 엔진의 털·미용 표현 기준과 참조 자료

기록일: 2026-11-07. 사용자 요청 “인터넷서치부터해봐” → “엔진에 정리해놔”에 따라 조사 결과와 후속 설계안을 보존한다.

상태: **실제 참조 사진 4건 선별·관찰 완료 / 기존 v03 길이 초안 및 등록 말티푸 3D 외피→직접 native64 진단 연결 구현 / v2 3D 정수리·가슴 및 native64 가슴 풍성함 연결 / 공통 결·미용 변형과 B2 native64 화풍은 후속**. `coat` 명령의 실제 입력 규격과 지원 범위는 [엔진 실행 안내](../tools/dog_engine/README.md)를 따른다. 아래 전체 설계 항목이 모두 실행된다고 해석하지 않는다.

후속 구현: [참조 카탈로그](../tools/dog_engine/coat-references.json), [사진별 관찰과 한계](coat-reference-observations.md), [3D·native64 연결 기록](coat-head-integration.md). 실제 사진을 새 캐릭터 프리셋으로 채택한 것은 아니다. v03는 5부위 길이 JSON 초안이며, 3D 경로는 별도 검토 모델의 정수리·볼·양쪽 귀·앞가슴 길이를 새 외피에 적용한다. 원본 모델·관찰 DB는 보존한다.

## 1. 조사에서 확인한 내용

| 근거 | 확인 내용 | 엔진 설계에 주는 시사점 |
|---|---|---|
| S1 AKC 털 길이·유형 | 털 길이, 곱슬 여부, 얼굴의 수염·눈썹 털(furnishings)을 구분한다. | 얼굴 장식털과 몸통 길이를 별도로 기록한다. |
| S2 AKC 이중모 | 이중모에도 짧은 유형부터 긴 유형까지 있다. | 털 길이로 모량·풍성함·속털 유무를 자동 결정하지 않는다. |
| S3 I Pet Grooming | 사진 설명에 슈나우저 몸통 6mm, 푸들 3mm, 캐부들 13mm/3mm와 긴 귀 스타일을 명시한다. | 몸통 길이와 귀털 모양을 독립적으로 설명하는 참조 사례다. 서로 다른 개체 사진을 통제된 길이 비교로 사용하지 않는다. |
| S4 Andis 교육 | 테디베어 머리를 별도 미용 주제로 다루며 곱슬 털에 특히 적합하다고 설명한다. | 미용 형태와 털의 결 사이의 적합성을 확인한다. |
| S5 Groomer to Groomer | 실제 미용 사례에서 몸통은 5/8인치 가드콤을 사용하고 다리·목·둥근 머리를 부위별로 다듬는다. | 전신을 한 길이·한 볼륨으로 처리하지 않고 부위별 조합으로 기술한다. |

위 자료는 유형과 사례에 관한 근거다. 엔진에 필요한 예시 개수, 픽셀 변환식, 모든 품종에 공통으로 적용할 수치 범위를 검증한 자료는 아니다. 앞선 대화의 ‘6개’는 근거가 확인된 기준이 아니므로 채택하지 않는다.

## 2. 엔진에서 구분할 표현 요소 — 설계안

| 요소 | 기록·묘사할 내용 | 구분할 사항 |
|---|---|---|
| 털의 결 | 직모·물결·곱슬, 거친 결 등 | 결은 길이 또는 미용 이름으로 추정하지 않는다. |
| 털 길이 | 짧음·중간·김, 근거가 있으면 부위별 길이 | 사진에서 추측한 mm와 미용 기록의 mm를 구분한다. |
| 보이는 풍성함 | 몸에 붙음·보통·부풀어 보임, 부위별 외곽 부피 | 실제 모량/밀도의 측정값이 아니다. 길이와도 별개다. |
| 피모 층 | 단일모·이중모·미확인 | 사진의 풍성함만으로 확정하지 않는다. |
| 미용 형태 | 고르게 정리, 둥근 얼굴, 귀털 유지, 다리털 유지 등 | 이름만 저장하지 않고 부위별 길이·외곽 형태를 함께 기록한다. |
| 얼굴 장식털 | 눈썹·수염·볼·주둥이 주변 털과 눈 가림 | 눈·주둥이의 실제 형태와 털이 만든 외곽을 구분한다. |

‘털의 양’이라는 요청은 먼저 보이는 풍성함으로 해석하되, 사용자가 실제 숱이나 길이를 뜻하는 경우 해당 항목으로 구분한다. 낮음/보통/높음 같은 단계와 경계는 비교 예시를 검토한 뒤 확정한다. 서로 불가능하거나 부자연스러운 조합을 자동으로 모두 제공하지 않는다.

부위는 정수리·볼/주둥이·좌우 귀·목/가슴·몸통·다리/발·꼬리로 구분하는 안을 사용한다. 이는 내부 기술을 위한 분류이며 제품 등록 화면에 필수 설문을 추가하는 결정이 아니다. 기존 [개체 프로필 설계](profile-generation-spec.md)의 사진 등록 → 털 선택·모습 보기 → 행동 설정 흐름을 따른다.

## 3. 관찰과 표현 선택

- 사진별 관찰: 개체 ID, 사진 ID, 촬영 시점(알려진 경우), 보이는 부위·시점, 관찰된 털, 미용 기록, 미확인·충돌 상태를 연결한다.
- 표현 선택: 사용자가 원하는 털 길이·풍성함·미용 형태와 적용 부위를 별도로 기록한다. 선택으로 원본 관찰을 덮어쓰지 않는다.
- 미확인: 가려진 부위와 실제 모량은 근거 없이 채우지 않는다. 사진의 품종·미용 이름만으로 실제 개체 특징을 확정하지 않는다.
- 묘사 예시: “몸통은 짧게, 볼은 둥글고 풍성하게, 귀 끝 털은 길게, 주둥이 주변은 짧게 정리.” 이는 전체 설계를 설명하는 가상 문장이며 현재 명령으로 전부 적용할 수 없다. 미지원 속성이 섞인 요청은 부분 적용하지 않는다.

## 4. 참조 예시 수집과 비교

먼저 아래 특징을 포괄하는 실제 사진을 수집하고, 추가 예시가 필요한 차이를 확인한다. 이 목록은 서로 배타적인 품종 분류가 아니다.

| 참조군 | 비교할 차이 |
|---|---|
| 몸에 붙는 짧은 털 | 피부·체형 윤곽과 털 외곽의 차이 |
| 아래로 흐르는 긴 털 | 늘어지는 방향, 귀·가슴·꼬리 장식털 |
| 부풀어 보이는 곱슬/물결 털 | 길이, 둥근 얼굴, 볼·귀의 볼륨 |
| 속털이 풍성한 이중모 | 길이와 별개인 부피, 목·가슴의 외곽 |
| 거친 털과 얼굴 장식털 | 수염·눈썹·주둥이 주변 실루엣 |

가능하면 같은 개체의 미용 전후 사진을 사용한다. 같은 개체여도 자세·촬영 각도·배율·조명·성장·빗질/건조 상태가 다르면 그 차이를 기록한다. 서로 다른 개체의 사진은 유형 참고로만 사용하고 ‘털만 바꾼 비교’로 표시하지 않는다. 현재 선택된 두 개체 C도 서로 다른 개체이므로 미용 전후 쌍으로 취급하지 않는다.

참조 기록에는 다음 정보를 남긴다.

- 자료 ID·원문 URL·제공자·확인일, 사진 설명에 적힌 길이와 적용 부위.
- 개체 동일성 확인 여부, 정면/사선/측면 등 시점과 보이는 부위.
- 털의 결·길이·보이는 풍성함·미용 형태, 직접 관찰/출처 설명/제작 추정의 구분.
- 적용 목적(유형 참고/길이 비교/부위별 미용 참고), 사용 범위와 한계.
- 파일을 실제 도입할 경우 원본 경로·해시·이용 조건. 후속으로 공개 사진 4장을 로컬 `private-data/coat-references-20261107`에 원본 그대로 보관하고 관찰했다. Git에는 사진을 포함하지 않으며 배포용 자산으로 채택하지 않았다.

초기 조사는 원문 텍스트와 캡션 확인이었으며, 후속 관찰 담당자가 미용실 사진 4장을 각각 직접 열어 관찰 기록을 추가했다. 같은 개체의 통제된 비교는 아직 확보하지 않았다. 자료가 설명하는 미용 길이를 모든 피모의 동일한 실루엣이나 엔진 단위로 환산하지 않는다.

## 5. 후속 구현·검수 기준

1. 참조 사진과 부위별 설명을 선별하고 예시 수·단계 경계를 정한다. 현재 개수는 미정이다.
2. 검토된 같은 개체 구조에서 한 번에 비교할 털 요소를 정한다. 눈·코 위치, 귀뿌리, 머리–목–어깨 연결, 무늬와 화풍을 유지한다. 털이 덮어 보이는 정도의 변화와 실제 구조 변경을 구분한다.
3. 길이·풍성함·미용 형태를 실제 실행 파라미터와 연결하고 지원 범위를 검증한다. 현재의 3D 머리/2D 전신 분리와 미지원 부위를 명시한다.
4. [전체 구조 검토 규칙](anatomy-regression-policy.md)과 [독립 외형·기술 리뷰](visual-review-policy.md)를 적용한다. 생성 결과의 다른 형상이 달라졌다면 단일변수 비교라고 표시하지 않는다.
5. 고해상도 작화에서 구분되어도 native64에서 구분된다고 가정하지 않는다. 실제 64×64 원본에서 눈·귀·주둥이·목 경계와 털 단계의 식별성을 별도로 검수한다.

현재 두 개체 C의 선택 범위는 [선택 기록](../config/individual-pair-canonical.json)을 따른다. 새로운 털 유형·다른 개체·native64 전체로 승계하지 않는다.
