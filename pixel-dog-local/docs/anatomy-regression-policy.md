# 귀·뒤통수·목 구조 오류 재발 방지

2026-11-07 사용자의 귀–뒤통수 융합, 사람 흉상처럼 보이는 목 지적과 “재발방지해”에 따른 현재 규칙이다. 기존 화풍·선택 이력은 보존하되 해당 부위가 검증됐다는 범위를 넓히지 않는다.

## 실제 실패와 원인 구분

| 실패 | 확인한 제작·검토 문제 | 차단 기준 |
|---|---|---|
| 귀와 뒤통수가 한 덩어리 | 이전 그림 윤곽을 유지하며 털 묘사만 줄였다. 귀뿌리·자유 가장자리·독립 후두부 구조 입력이 없었다. | 귀를 숨긴 온전한 머리와 같은 색 재질의 실제 귀 부착을 확인한다. |
| 사람 흉상처럼 끝나는 목 | 머리와 짧은 목만 그렸고 어깨·상흉부 연결을 검토하지 않았다. 귀 부문 수정 후 목 문제까지 해결됐다고 확장할 수 없다. | 어깨까지 연결된 동일 메시 5시점과 같은 카메라의 짧은/넓은 crop 비교가 필요하다. |
| 세 안이 단일 변수 비교처럼 설명됨 | image_gen은 귀털 외 정수리·주둥이·시점도 바꿨다. | 실제 차이를 확인하기 전 0/4/8% 등 정밀한 통제 비교라고 표시하지 않는다. |
| 수치·부분 검토가 전체 품질로 전달됨 | 기술 무관통과 귀 부문 PASS를 개체·목·화풍 승인처럼 사용할 위험이 있었다. | 두 리뷰어가 같은 최종 파일의 전체 필수 항목을 명시적으로 판정한다. |

엔진의 기존 목 중심은 실제로 후하방으로 기울어 있다. 따라서 “엔진 목이 수직이며 얼굴 중앙에 꽂혔다”라고 단정하지 않는다. 문제는 짧은 절단면, 몸통 기준 부재와 최종 그림의 받침대 같은 외형을 구분해 진단해야 한다. 정면에서 좌우 중심에 목이 있는 것 자체는 결함이 아니다.

사용자가 지적한 그림은 image_gen 출력이다. 기존 엔진의 귀는 단일 skin 표면에 합쳐져 있지만, 그 코드가 해당 그림에 직접 적용된 것은 아니다. 생성 입력·구도와 엔진의 구조적 한계를 별도로 기록한다. 모델 내부 생성 원인은 확정하지 않는다.

## 작업 순서와 게이트

1. 사진의 관찰과 제작 추정을 분리한다. 기존 실패 그림을 그대로 구조 기준으로 이어받지 않는다.
2. 실제 메시로 머리·목·상흉부를 검토한다. 일반 해부 자료의 연결 관계를 개체 실측값으로 바꾸지 않는다.
3. 정면·사선·측면·후면·윗면, 귀를 숨긴 측면/후면, 동일 카메라·배율의 full/crop 파일을 저장한다.
4. 독립 외형·기술 리뷰가 같은 입력 해시와 전체 구조 범위를 통과한다.
5. `structure-gate`로 작화 입력 계획을 만들고 호출 직전에 실제 참조 파일 목록을 다시 검사한다.
6. 실제 built-in image_gen 호출에는 검사한 동일 payload를 사용하고, 기술 리뷰에서 호출 기록과 generation.json을 대조한다. JSON 검사만으로 실제 외부 호출까지 검증됐다고 표시하지 않는다.
7. 작화 후 두 리뷰어가 귀와 목을 다시 검토한다. 구조 PASS를 화풍·개체 닮음·최종 작화 PASS로 승계하지 않는다.

```powershell
python -m tools.dog_engine structure-gate --status <구조상태> --contract <구조계약> --output-plan <새입력계획>
python -m tools.dog_engine structure-gate --plan <입력계획> --generation <실제호출인수JSON>
python -m tools.dog_engine structure-gate --plan <입력계획> --generation <실제호출인수JSON> --art-status <최종작화상태>
```

게이트는 기존 `tools/review/check_delivery.py`의 검사를 먼저 적용하고 구조 범위 검사를 더한다. 보존 도구의 바이트는 바꾸지 않는다. 누락·FAIL·범위 불일치·해시 변경은 차단하며, 생성·검토 대기를 승인으로 바꾸지 않는다.

## 구조 계약과 보고서

`structure-contract.json`은 검토 상태의 inputs에 해시로 포함한다. schema_version=1, scope=`head_neck_shoulders`, geometry_kind=`actual_mesh`, models(파일→해시), appearance_reference_artifacts(교정된 참조 이미지 목록), view_sets를 기록한다. 이전 실패안을 포함한 전후 비교판을 무조건 작화 참조로 전달하지 않는다.

각 view_set에는 모델 파일/해시, 다섯 시점, frame=`head_neck_upper_thorax`, 귀 숨김·crop 비교 여부와 실제 자료를 기록한다. boolean만으로 통과하지 않는다.

- `renders`: 다섯 개별 이미지의 view, artifact, model_sha256, camera `[az,el]`, scale, center, canvas와 projection_id. ID는 모델·카메라·배율·중심·캔버스의 정규 JSON SHA256이다.
- `ears_hidden_renders`: 같은 측면/후면 카메라·배율의 별도 이미지. 귀가 있는 파일과 동일하면 차단한다.
- `crop_comparison`: 같은 측면 원본의 source_artifact, artifact, source_rect `[left,top,right,bottom]`, model_sha256, projection_id. 저장된 crop의 픽셀이 원본 영역과 정확히 일치해야 한다. crop 때문에 형상이 바뀐 비교는 차단한다.

두 보고서의 기존 review-verdict에 `structure_review`를 추가한다. scope, contract_sha256과 다음 checks 모두 PASS가 필요하다. 최종 작화는 `appearance_review`에 scope, plan_sha256, 같은 checks를 기록한다.

| 체크 키 | 실제 외형 판단 |
|---|---|
| ear_root_and_free_edge | 귀뿌리는 충분한 두께로 붙고, 귀 아래·뒤 가장자리는 독립되어 있는가 |
| independent_occiput | 귀와 구별되는 뒤통수 부피가 있는가 |
| jaw_to_throat | 아래턱 뒤에서 목 앞면으로 이어지는가 |
| dorsal_neck_to_withers | 후두부–목 뒤–등의 연결이 자연스러운가 |
| throat_to_chest | 목 앞면이 가슴으로 이어지는가 |
| canine_attachment_not_pedestal | 받침대·긴 끈·판·큰 삼각막처럼 보이지 않는가 |

형상·닮음·해부학은 자동 판정하지 않는다. 게이트는 파일과 검토 범위의 연결을 검사한다. 작성된 카메라 기록이 실제 렌더 호출과 일치하는지, 모델의 표면과 근거 사진이 타당한지는 독립 기술·외형 리뷰가 확인한다.

귀 숨김은 PNG 메타데이터만 다른 동일 그림으로 대신할 수 없다. 디코딩한 RGBA 픽셀도 대조한다. 최종 작화 검토 inputs에는 구조 자료뿐 아니라 실제 generation.referenced_image_paths의 모든 사진·화풍 입력을 포함하고, 현재 해시를 다시 검사한다.

## 거절 이력과 회귀

`config/anatomy-rejections.json`에 비공개 이미지의 **내용 해시만** 기록한다. 사용자 거절과 독립 검토 FAIL을 구분한다. 파일 이름 변경, 부분 선택, 다른 파일 추가로 같은 실패 이미지를 통과시키지 않는다. 기존 사용자 거절 이력도 이미지 해시 단위로 확인한다. 새로운 사용자 결정으로 해제를 요구받은 경우에만 명시적 이유와 새 검토를 남겨 변경한다.

회귀 테스트는 귀 부문 PASS 승계, 누락 시점, crop/숨김 근거 누락, 다른 모델/카메라 crop, 변경된 입력, 빈 참조 목록, 거절 이미지 재명명·추가·새 상태표를 차단한다. 새 귀 부품을 기존 native64 경로에서 눈처럼 처리하는 경우도 오류로 차단한다.

두 개체의 revision02와 earfix-art03는 전달 차단이다. 귀 구조04의 과거 PASS는 귀 검토 이력이며 전체 목 승인으로 사용할 수 없다. 초기 목·상흉부 실험 neck-structure01도 미승인이다. 후속 neck-reference02는 전체 구조 검토 및 입력 게이트를 통과했고, 이를 실제 입력으로 사용한 pair-b2-retry04의 B/C는 최종 작화 게이트 READY다. A는 독립 외형 FAIL로 차단한다. 후속 사용자 지시로 C를 두 개체 정본으로 선택했다. B는 미선택이며 실제 native64 검수는 남아 있다.

## 검증 기록

2026-11-07 기존 회귀 89개와 게이트 초기 15개가 전체 verify에서 통과했다. 이후 독립 기술 검토에서 사진 입력 누락, PNG 메타데이터만 바꾼 숨김 증거, 잘못된 좌표 타입을 추가 발견해 수정했다. 최종 게이트 18개는 구현자와 별도 기술 리뷰어가 각각 실행해 통과했다. 변경 없는 기존 테스트를 다시 실행한 것으로 부풀리지 않는다. 독립 기술 최종 판정은 기록·입력 검증 범위 PASS이며 실제 형상 승인은 아니다. 실제 미승인 목 실험을 새 CLI에 넣어 비정상 종료와 BLOCKED를 확인했다.
