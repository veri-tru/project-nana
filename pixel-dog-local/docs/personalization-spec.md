# 개체 외형과 행동을 자산에 연결하는 설계

## 현재 화풍 연결: B2·C2 비교 정본

[B2·C2 정본 규격](b2-c2-style-spec.md)을 표현 설정에 연결한다. 두 화풍 모두 비교 기준으로 승인됐고 최종 단일 제품 화풍은 미선택이다. 화풍 전환은 style_policy_id/version과 표현·자산 버전에만 반영하며 관찰된 개체 외형·행동을 바꾸지 않는다. 아래 ‘2번 눈꺼풀’ 선택의 제한 범위는 그대로 유지한다. B2/C2 정본 선택은 이번 별도 지시에서 발생한 결정이다.

## 2026-11-02 사용자 3단계와 프로필 필수 참조

사용자는 **사진 등록 → 털 선택·모습 보기 → 행동 설정·결과 확인**을 수행한다. 아래 외형 추출·부품 호환·특징 검수는 내부 과정이며 각각을 별도 필수 입력 화면으로 만들지 않는다. 추가 질문과 수정은 해당 단계 안에서 필요한 경우에만 제공한다.

개체 외형과 행동은 지속적인 dog_id 아래 프로필로 저장한다. 모든 개체 이미지·동작 생성은 고정된 프로필 버전, 표현 설정, 제품 화풍과 기준 자산을 참조해야 한다. 사진이나 대화 맥락만으로 매번 개체를 재해석하지 않는다. 수정은 대상 범위와 근거를 기록해 후속 자산에 전달하고, 생성 결과가 프로필을 지켰는지 검수한다.

사용 흐름·데이터 책임·부분 선택·생성 입력·사용 묶음 전환·수정 전파·검증 조건의 상세 정본은 [개체 프로필 기반 생성 설계](profile-generation-spec.md)다. 현재 문서와 설정은 설계이며 저장·생성 기능은 미구현이다.

## 2026-11-02 눈·눈꺼풀·눈 주변 털의 개체별 적용

사용자가 눈꺼풀의 개체 차이를 지적하고 아래 원칙의 기록을 요청했다. 특정 시안의 눈꺼풀 모양을 모든 개에게 복제하지 않는다. 시안 ‘2번’ 선택은 눈꺼풀·털 겹침 표현의 참고 범위이며 얼굴 전체와 공통 화풍 승인이 아니다. 선택 이력은 [결정 기록](decisions.md)을 따른다.

| 구분 | 개체별 반영 | 제작 시 구분 |
| --- | --- | --- |
| 눈 | 사진에서 보이는 크기·간격·기울기·노출 형태, 확인 가능한 색 | 실제 특징과 픽셀 표현을 위한 제작 조정값 분리 |
| 눈꺼풀 | 개체의 눈매와 관찰 가능한 경계 | 눈 열림·깜박임을 제어하되 모든 개에게 같은 눈매를 강제하지 않음 |
| 눈 주변 털 | 부위별 길이·방향·가림 범위 | 눈꺼풀과 별도로 관리하고 선택한 털 길이에 맞춰 겹침 조절 |
| 공통 화풍 | 픽셀·선·색·명암 단순화 방식 | 화풍을 통일해도 눈매·얼굴형·귀·주둥이·체형은 개체 근거 보존 |

사진에서 가려진 눈꺼풀은 추정해 확정하지 않고 미확인으로 둔다. 털의 사선·음영을 눈썹 또는 감정으로 확정하지 않는다. 자료가 부족하면 해당 항목에 필요한 추가 사진 또는 보호자 설명을 받고, 관찰 사실과 보호자 보고·제작용 임시값을 구분한다.

제작 순서는 개체 사진에서 보이는 눈매 확인 → 눈·눈꺼풀의 기준 형태 설정 → 표현할 털 길이에 따른 가림 적용 → 보호자 닮음 검토다. 얼굴 바탕·무늬, 눈, 눈꺼풀, 앞쪽 털을 논리적으로 구분하고 포즈별 가림 순서를 확인한다. 이 구분은 구현 기준이며 실제 편집 레이어나 동작 자산이 이미 분리됐다는 뜻이 아니다.

갈색 홍채와 옅은 반짝임 등 이번 시안의 표현 선택을 모든 개의 실제 눈 특성으로 저장하지 않는다. 눈꺼풀 시안 선택만으로 얼굴 전체·B/C 화풍·체형·동작·해상도를 승인 처리하지 않는다. 걷기·고개 돌림·깜박임에서는 해당 개체의 눈매와 털 겹침을 유지하는지 별도 검수한다.

기준일: 2026-10-18. 사용자 검토 의견을 구체화한 설계 초안이다. 우선순위는 개체 외형 설정 구조, 부품·동작 호환표, 한 마리의 닮음 검증 순서다. 실제 자산의 지원 여부나 최종 출시 사양을 확정한 문서는 아니다. 공통 값과 결정 상태는 [현재 사양](current-spec.md)에서 확인한다.

## 개체 외형 설정 구조

품종별 외형 참고값에서 개체 외형 프로필을 만들고, 여기에 개체 행동 프로필과 실제 자산 대응표를 연결한다. 품종 ID는 선택 사항이며 개체 ID를 대체하지 않는다. 품종 변경으로 보호자가 확인한 개체 특징을 덮어쓰지 않는다.

| 구분 | 저장할 내용 | 적용 규칙 |
| --- | --- | --- |
| 개체 | 개체 ID, 프로필 버전, 수정 이력 | 실제 개 한 마리를 식별. 공개 품종 목록과 별도 |
| 품종 참고 | 알려진 품종·믹스견·모름, 자료 묶음·버전·3자리 품종 ID | 초기 후보를 제시할 때 사용. 믹스견도 동일한 수정 화면 사용 |
| 몸통 | 기본 몸통 후보, 길이감·사지·흉곽·등선의 선택값 | 정성 선택값과 실제 측정값을 별도 저장 |
| 부위 | 머리·주둥이·귀·꼬리, 현재 피모·미용 | 고정 형태와 순간적인 포즈를 구분 |
| 무늬 | 바탕색, 영역별 무늬, 좌우 차이 | 품종 표준과 달라도 사진·보호자 확인에 따라 수정 |
| 우선 특징 | 보호자가 고른 식별 특징 최대 3개와 관련 속성 | 확인된 특징만 선택. 세 개를 채우려고 추정하지 않음 |

각 속성에는 다음 정보를 붙인다. 한 프로필 전체에 하나의 확인 상태를 붙이는 방식으로 대체하지 않는다.

| 필드 | 의미 |
| --- | --- |
| attribute_key, value | 귀의 좌우 형태, 눈 주변 무늬 등 속성과 선택값. 미확인은 null |
| side | 개체 자신의 왼쪽·오른쪽·양쪽·해당 없음·미확인. 화면의 좌우와 구분 |
| evidence_kind | 사진 관찰, 영상 관찰, 보호자 응답, 품종 참고값, 제작 기본값 |
| evidence_ref, captured_at | 근거 사진·응답·영상 구간 또는 참고 자료의 식별자와 시점 |
| evidence_status | 확인 가능, 가림·범위 밖·판단 불가, 미질문, 근거 충돌 |
| owner_review | 확인 전·수락·수정·제외. 소유자의 수락이 사진 관찰 근거를 새로 만들지는 않음 |
| visibility | 해당 부위가 사진·방향·포즈에서 보이는 범위 |
| value_role | 직접 보이는 특징, 보호자 보고, 참고 후보, 제작용 조정 |
| revised_from, change_reason | 원래 값, 수정자와 이유, 버전 |

사진과 보호자 설명이 다르면 두 근거를 함께 남기고 현재 미용·촬영일·보이는 방향을 확인한다. 단순한 출처 우선순위나 최신 파일 하나로 충돌을 해소하지 않는다. 셀카 반전 여부가 불명확하면 좌우를 확정하지 않는다. 사진에 보이지 않는 반대쪽 무늬를 자동 복제하지 않는다.

몸통 분류를 실측비로 변환하지 않는다. 첨부 검토에서 체장 절대값이 미확인인 313종은 그대로 미확인으로 둔다. 화면에서 고른 길이·폭 조정값은 제작용 값이며 반려견의 실제 신체 측정값이 아니다. [외형 자료 검토](../reviews/appearance-assets-2026-10-17/report.md)

## 미확인 외형의 추가 정보 수집

2026-11-01 사용자 방향: 최초 사진에서 확인되지 않은 외형은 추가 이미지 또는 보호자 설명으로 보완한다. 14개 항목을 모두 다시 입력하게 하지 않고, 미확인·근거 충돌 항목과 그 이유를 보여 준 뒤 해당 부위에 필요한 정보만 받는다.

1. 추가 사진 제공, 짧은 설명·선택 응답, 모름·나중에 중 사용자가 가능한 방식을 고른다. 사진과 설명을 모두 요구하지 않는다.
2. 기존 사진으로 보완할 수 있으면 새 촬영을 요구하지 않는다. 같은 사진이 여러 항목을 보여 주면 여러 항목의 근거로 연결한다.
3. 사진을 요청할 때는 부위·방향·가리지 않을 범위를 안내한다. 예를 들어 꼬리는 뿌리부터 끝까지 보이는 평소 사진, 주둥이는 옆얼굴 사진을 안내한다. 설명에는 전문 분류 용어 대신 평소 모습과 비교할 기준을 쓴다.
4. 입력이 들어오면 추가 근거를 연결하고 후보를 재검토한다. 자료 제출 자체를 확인 완료로 처리하지 않는다. 설명은 보호자 보고로, 직접 보이는 모습은 사진 관찰로 남긴다.
5. 충분한 근거로 후보가 정리되면 보호자가 결과를 확인한다. 여전히 가려지거나 설명만으로 판단하기 어려우면 null을 유지한다. 기존 근거와 다르면 현재 미용·시점·자세·방향을 함께 확인하고 충돌 이력을 보존한다.

추가 요청에는 request_id, attribute_keys, 미확인 사유, 요청 문구·허용 입력 방식, 요청 상태, 응답 근거 ID, 재검토 결과, owner_review를 연결하는 설계안이다. 요청 상태는 수집 대기·자료 수신·재검토 완료·보류로 구분하며, 재검토 완료도 외형 확정을 뜻하지 않는다. 현재 앱·수집 기능은 미구현이다.

먼저 우선 식별 특징이나 현재 제작 방향의 실루엣에 영향을 주는 항목을 보완한다. 미확인 항목이 남아도 확인된 특징으로 검토용 시안을 이어갈 수 있지만, 불명확한 부위를 그릴 경우 제작용 임시값과 교체 대상을 표시하고 개체의 실제 특징으로 저장하지 않는다. 최초 개체의 구체적인 [추가 정보 안내](../reviews/individual-dog-appearance-20261101/follow-up.md)를 참고한다.

## 외형 선택 항목 축소와 털 길이 선택

2026-11-01 사용자 방향: 나중에 14개 외형 축을 축소하고, 사진마다 털 길이가 달라지는 점을 전제로 사용자가 표현할 털 길이를 선택하게 한다. 축소할 최종 항목 수와 통합 기준은 후속 설계에서 정한다. 현재 14개 관찰 기록은 비교 근거로 보존하며 즉시 삭제·통합하지 않는다.

기본 등록 화면에서는 표현할 털 길이를 선택한다. 체형, 얼굴·귀, 색·무늬, 꼬리 등은 사진에서 후보를 만들고, 닮지 않은 부분을 수정할 때만 이해하기 쉬운 묶음으로 보여준다. 각 부위를 필수 설문으로 만들지 않는다. 내부 관찰 세부값과 좌우 차이·근거·미확인·수정 이력, 개체의 식별단서는 보존한다.

털은 다음 두 층으로 분리한다.

| 구분 | 내용 | 적용 |
|---|---|---|
| 사진별 관찰 | 사진 ID별 부위의 털 길이·결·보이는 범위, 시점과 미용 여부는 알려진 경우만 기록 | 서로 다른 사진의 길이를 억지로 하나의 현재 상태로 합치지 않음 |
| 표현 선택 | 사용자가 캐릭터에서 원하는 짧게·중간·길게, 필요 시 얼굴·몸통·꼬리별 조정 | 사진 관찰을 수정하거나 실제 개의 고정 특성으로 저장하지 않음 |

같은 개체·같은 자세·같은 무늬·동일한 표시 크기의 예시에서 털 길이만 바꿔 비교하게 하는 안이다. 길이 선택은 제작용 단계이며 cm나 자연 피모 유형으로 환산하지 않는다. 결·색·무늬·체형은 길이 선택 때문에 자동 변경하지 않는다. 실제 제작된 예시와 부품·동작의 지원 여부를 확인한 뒤 선택 가능으로 표시한다.

기본 화면에서는 전체 털 길이를 고르고, 필요한 경우 얼굴·몸통·꼬리를 따로 조절하는 안을 검토한다. 긴 꼬리털이나 수염이 우선 식별 특징에 포함되어 있는데 짧은 표현을 고르면 예상 변화를 보여 주고 선택을 확인한다. 형태를 바꾼 결과는 보호자가 닮음을 다시 검토한다. 선택하지 않은 값은 null로 두며 사진 업로드만으로 선호 길이를 결정하지 않는다. 현재 실제 선택 예시·UI·길이별 자산·개체 선택값은 없다.

## 부품과 동작 호환

몸통 계열이 같다는 사실은 호환 판정의 출발점이다. 최종 호환은 몸통 변형 자산과 부품·클립의 정확한 버전, 방향, 원본 해상도, 포즈 또는 프레임에 대해 판정한다. 시험하지 않은 조합을 지원으로 표시하지 않는다.

| 호환표의 항목 | 기록할 내용 |
| --- | --- |
| 조합 식별 | 몸통 자산·버전, 부품 자산·버전, 클립·버전 |
| 표시 조건 | 원본 크기, 방향, 프로필의 변형값, 검사한 포즈·프레임 |
| 부착점 | 머리·귀·꼬리 등의 부모 부위, 연결점 좌표, 적용 포즈 또는 프레임 |
| 좌표 기준 | 캔버스 원점과 축, 부위 좌표를 캔버스로 옮기는 변환, 기준점 |
| 발과 바닥 | ground_y, 접촉 발과 접지 프레임, 이동량과 미끄러짐 여부 |
| 가림 | 포즈별 앞뒤 순서, 클리핑 마스크, 털·귀·꼬리의 중첩 |
| 비대칭 | 좌우 부품·무늬와 반전 허용 여부, 방향별 검수 |
| 지원 판정 | 미제작·미시험·조건부 통과·통과·실패, 이유와 재검수 조건 |
| 검수 근거 | 실제 파일·버전·해시, 캡처 또는 재생 결과, 검수자·날짜 |

좌표는 해당 원본 캔버스의 픽셀 단위로 기록하는 초안이다. 원점은 좌상단, x는 오른쪽, y는 아래쪽으로 둔다. 다른 규격으로 변환할 때는 변환 정보를 저장하고 다시 검수한다. 실제 자산이 없는 현재는 연결점이나 바닥 좌표를 임의의 숫자로 채우지 않는다.

| 몸통 | 시험 순서 제안 | 주로 확인할 차이 | 실제 지원 상태 |
| --- | --- | --- | --- |

조건부 통과에는 허용 방향·변형 범위·포즈를 명시한다. 몸통·부품·클립 또는 해상도가 바뀌면 영향을 받는 조합을 다시 확인한다. 미지원 선택은 보류하거나 지원되는 대안을 설명하고 보호자가 고르게 한다. 비슷한 다른 행동으로 자동 교체하지 않는다. 검수된 기본 휴식 자산도 없는 경우에는 재생 가능으로 표시하지 않는다.

## 행동 DB와 클립 연결

한 행동에 여러 클립이 대응할 수 있고, 하나의 검수된 클립을 서로 다른 상황 규칙에서 사용할 수도 있다. 121개 대표 행동을 121개 파일이나 모든 몸통의 지원 동작으로 취급하지 않는다.

연결 행에는 concept_id, 세부 속성, 근거 record_id와 주장 유형, clip_id·버전, 시작·끝 자세, 지원 몸통 자산·버전, 방향·해상도, 전환 클립, 자산 검수 상태를 둔다. 개체가 실제로 하는지에 대한 근거는 문헌 근거와 별도로 연결한다.

아래는 연결 방식의 초기 예다. 클립과 지원 몸통은 모두 미할당이며, 시작·끝 자세는 첫 제작을 위한 제안이다. 실제 개의 운동 순서를 단정하는 표가 아니다.

| 대표 행동 코드 | DB의 참고 기록 | 제작할 표현 | 시작 → 끝 자세 제안 | 클립·지원 몸통 |
| --- | --- | --- | --- | --- |
| SIT | E014 문헌 정의 | 앉은 자세 유지와 선택한 앞발 배치 | 앉음 → 앉음 | 미할당 |
| SIT_DOWN | E195 문헌 관찰 | 앉는 자세로 내려가는 전환 | 서기 → 앉음 | 미할당 |
| LIE | E015 문헌 정의 | 엎드림·옆눕기 등의 휴식 자세별 표현 | 선택한 눕기 자세 → 같은 자세 | 미할당 |
| LIE_DOWN | U017 사용자 요구 | 누운 자세로 이동하는 전환 | 서기 또는 앉음 → 선택한 눕기 자세, 각각 별도 검수 | 미할당 |
| SHAKE | E023 문헌 정의 | 몸 털기 | 서기 → 서기부터 시험 | 미할당 |
| STRETCH | E024 문헌 정의 | 선택한 형태의 기지개 | 중립 자세 → 중립 자세, 중간 자세 포함 | 미할당 |
| PAW_HOVER | E002 문헌 정의 | 앞발 하나를 들어 유지 | 앉음 → 같은 앉음부터 시험 | 미할당 |
| MOUTH_OPEN | U005 사용자 요구 | 입을 벌리는 표현 | 몸통 자세 유지, 입 상태 변화 | 미할당 |
| PANT | U006 사용자 요구 | 반복되는 헥헥거림 표현 | 몸통 자세 유지, 별도 반복 클립 | 미할당 |

문헌 정의가 개체의 습관을 증명하지 않는다. E019의 옆눕기 본문 언급을 직접 정의 근거로 재승격하지 않는다. U017·U005·U006은 사용자 요구이며 관찰 근거가 추가된 것으로 표시하지 않는다. 입 벌림과 헥헥거림, 앉은 상태와 앉는 전환을 서로 대체하지 않는다.

2026-11-01 [얼굴·시선 움직임 정책 반영안](facial-motion-policy.md)을 추가했다. MOUTH_OPEN을 입술·턱 세부 동작으로 기술하고, TONGUE_OUT·LICK는 노출 범위·접촉 대상·경로를 확인한다. LOOK·HEAD_TURN·HEAD_TILT·GAZE_ALTERNATE는 눈 방향·머리 방향·대상 전환의 관찰 방식을 구별한다. 바라봄 대상과 이동 목적지를 별도 관리하며 기존 DB 코드·원기록을 재분류하거나 새 개체 습관으로 등록하지 않았다. 근거와 SNS 확인 한계는 [시선 조사](gaze-motion-research-20261101.md)에 있다. 모든 새 조합의 자산·개체 검수는 남아 있다.

### 개체 행동의 확인 상태

시선·얼굴 동작의 발생 상황은 [상황별 연결 정책](contextual-motion-policy.md)에 따라 사건·대상·현재 활동·진행 단계와 함께 설정한다. 같은 행동을 모든 상황에 동일하게 적용하지 않는다. 개체 근거가 없는 공통 연출은 제작 기본값으로 분리하고, 상황별 하지 않는다는 보고와 근거 충돌을 반응 선택 전에 검사한다. 동작 묶음의 필수 자산·시간·종료·복귀 조건이 검수되기 전에는 실행 준비 상태로 표시하지 않는다.

| 상태 | 의미 | 재생 규칙에 반영하는 방법 |
| --- | --- | --- |
| 관찰됨 | 지정한 영상·구간에서 확인 | 해당 상황과 관찰 범위만 연결 |
| 한다고 보고 | 보호자가 한다고 응답 | 보호자 보고로 표시하고 선택 규칙에 연결 |
| 하지 않는다고 보고 | 보호자가 해당 상황에서 하지 않는다고 응답 | 그 상황의 선택에서 제외하는 안. 보편적 부재로 확대하지 않음 |
| 관찰 구간에서 미발생 | 정해 둔 관찰 구간에서 발생하지 않음 | 구간의 결과로 저장. 일상 빈도 0으로 변환하지 않음 |
| 판단 불가·자료 부족 | 가림, 장면 부족, 빈도 모름 등 | null 또는 미확인으로 유지 |
| 미질문·근거 충돌 | 아직 묻지 않았거나 근거가 다름 | 후보 적용 보류, 추가 확인 |

빈도·지속·지연에 대해서도 별도의 근거와 결측을 보존한다. 품종 성격 설명으로 빈 항목을 채우지 않는다.

## 우리 강아지로 알아보는 특징 검수

보호자가 강조하거나 수정한 외형 특징을 최대 3개까지 내부 검수의 우선 항목으로 둔다. 자동 추출 항목은 후보로 표시하며, 특징 선택을 별도의 필수 사용자 단계로 만들지 않는다. 한쪽 접힌 귀, 눈 주변 무늬, 꼬리 형태 등은 선택지의 예이며 실제 개체에 존재한다고 가정하지 않는다. 특징마다 해당 부위·좌우·근거·표시 상태를 기록한다.

64×64와 96×96 후보를 같은 화면 크기에서 비교하고, 중립 자세와 선택한 앉기·눕기·몸 털기·기지개에서 특징이 유지되는지 확인한다. 가려져 원래 보이지 않는 포즈와 잘못 그려 사라진 경우를 구분한다. 작은 화면에서 구분되지 않는 특징은 과장·생략 여부를 보호자와 확인하고 제작용 변경으로 기록한다.

한 마리의 수정 완료 기준은 선택한 특징이 의도한 방향·포즈에서 보이고, 좌우 오류와 무늬 이동이 없으며, 보호자가 수정 결과를 확인하는 것이다. 이는 첫 개체의 제작 기준이며 사용자 집단의 제품 효과나 통계적 성공 기준은 아니다. 실제 기록은 [한 마리 검수 양식](../templates/pet-likeness-review.md)에 남긴다.

## A/B 조건의 품질 통제

같은 개체 외형 프로필과 자산 버전을 고정한다. 양 조건에 동일한 클립 목록과 전환표를 제공한다. 실제로 선택된 행동의 구성과 빈도는 개인화 조건에 따라 달라질 수 있지만 B에만 더 좋은 새 클립을 넣지 않는다.

| 구분 | 첫 비교의 통제안 |
| --- | --- |
| 고정 | 외형, 선택 특징, 클립·작화·전환 자산과 버전, 배경·기기·해상도·표시 크기, 총 제시 시간 |
| 고정 | 클립 내부의 프레임·재생 속도·포즈 품질, 시작·끝 자세의 연결 규칙 |
| 변경 허용 | 행동 선택, 빈도, 시작 시점·대기 간격 등 발생 타이밍 |
| 후속 분리 비교 | 새 자세 변형, 클립 내부 속도, 새로운 순서·동작 자산을 추가하는 효과 |
| 기록 | 실제 재생한 클립·전환·횟수·시각, 표시 오류, 조건 순서, 프로필·자산 버전 |

A는 공통 프로필, B는 확인된 보호자 응답에 따른 프로필이다. 품질이 다른 클립이나 한쪽만 지원되는 조합은 맞춘 뒤 비교한다. 빈도를 바꾸는 시험에서 실제 재생 횟수까지 같게 강제하지 않는다. 대신 총 제시 시간과 사용 가능한 자산을 고정하고 실제 노출 차이를 기록한다. 결과는 선택·빈도·타이밍을 함께 바꾼 효과이며 각 변수의 독립 효과로 해석하지 않는다.

외형 닮음, 귀여움, 우리 강아지다운 행동을 각각 질문하고 이유를 받는다. 자연스러움·입력 부담·수정량도 별도 기록한다. 개인화 여부를 미리 알리지 않고 제시 순서를 교차하며, 차이 없음·둘 다 닮지 않음·판단 어려움을 허용한다. 표본 수와 정량 통과 기준은 실행 전에 정한다.

## 참고 사진과 제품 자산의 이력

| 구분 | 별도로 관리할 정보 |
| --- | --- |
| 외부 참고 자료 | 자료 ID·원문 URL·저작자·표시된 라이선스·확인 범위·사용 목적·파일 해시 |
| 제품 자산 | 자산 ID·버전·제작자·수정자·제작 도구·참조 자료 ID·허용 사용 범위·검수 결과 |
| 보호자 자료 | 자료 ID·개체 연결·제공자·동의한 처리 범위·저장 위치·파생 프로필/자산과의 연결·삭제 상태 |

참고 사진에 붙은 조건을 새 스프라이트 전체의 조건으로 자동 복사하지 않는다. 새로 그렸다는 이유만으로 이용 조건이 해결됐다고 표시하지도 않는다. 실제 제작 방식과 참조·수정 관계를 남겨 해당 자산의 사용 범위를 확인한다. 출처 미확인은 사용 승인으로 처리하지 않는다. [외부 자료 기록 기준](../THIRD_PARTY.md)

### 사용자 자료의 처리와 삭제 흐름 초안

개인화 제작·보관, 외부 분석 전송, 공유·홍보·모델 학습 등 목적을 구별한다. 개인화 요청을 다른 목적의 동의로 확대하지 않는다. 외부 전송이 필요하면 전송 대상과 범위를 설명하고 선택을 받는 안이며, 공급자·보관기간·법적 문안은 아직 정하지 않았다.

원본 자료만 삭제할지, 해당 개체의 프로필·개체 전용 결과물까지 삭제할지 결과를 설명하고 범위를 선택하게 한다. 원본만 삭제하고 확인된 프로필을 유지할 경우 무엇이 남는지 표시한다. 삭제한 원본의 참조 ID가 남더라도 원본을 열 수 있는 것으로 표시하지 않는다.

삭제 요청, 처리 중, 완료, 일부 실패를 구분하고 재시도 상태를 제공한다. 썸네일·캐시·전송 사본·외부 처리와 백업의 처리 상태도 추적한다. 외부 처리나 백업 만료를 확인하지 못했으면 전체 삭제 완료라고 표시하지 않는다. 보관기간과 삭제 완료 기한은 실제 저장·처리 구조를 선택한 후 정한다. 이 초안은 삭제 기능이 구현됐다는 뜻이 아니다.
