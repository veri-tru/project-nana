이 파일은 이전 조사·설계의 보존본입니다. 현재 개발 기준은 [결정 기록](../decisions.md)과 [프로젝트 개요](../project-brief.md)를 우선 확인하세요. 내부 프로젝트 링크는 같은 폴더의 문서로 연결했습니다.

실제 반려견의 외형과 습관을 반영한 2D 모바일 앱을 개발한다. 현재 프로젝트의 대상은 개이며, 고양이는 별도의 후속 프로젝트로 진행한다. Android와 iOS를 모두 지원하되, Android의 플로팅 캐릭터를 먼저 검증하고 공통 앱과 홈 화면 위젯으로 확장한다. 사용자에게는 휴대폰을 사용하는 동안 자신의 반려견과 함께하는 경험을 제공한다.

# 확정한 방향

- 표현 방식은 2D 일러스트로 시작한다.

- 실제 개체의 외형과 관찰된 행동 특성을 반영한다.

- Android와 iOS를 모두 지원한다.

- 두 플랫폼의 공통 기능은 앱 내 상호작용과 홈 화면 위젯으로 구성한다.

- Android에는 다른 앱 위에 캐릭터를 표시하는 플로팅 모드를 추가한다.

- 첫 검증 대상은 Android 플로팅 모드다.

현재 작업용 프로젝트명은 ‘반려견 디지털 트윈 앱 개발’로 정한다. 개를 대상으로 문헌검토, 자료 수집, 행동 설계, 시제품과 보호자 평가를 진행한다. 고양이의 문헌과 행동 항목은 후속 프로젝트 자료로 구분해 보존한다. 서비스명, 구체적인 일러스트 화풍과 최종 개발 도구는 아직 결정하지 않았다.

# 목표 사용자와 시장 검증

현재 우선 과제는 목표 사용자 정의, 시장조사, 경쟁사 분석이다. 국내 출시를 우선 가정하고, 현재 반려견의 사진·영상을 기록하며 고유한 행동을 화면에서도 보고 싶어 하는 보호자를 초기 고객 가설로 둔다. 연령·성별과 유료 구매의향은 검증 전 확정하지 않는다.

사진 기반 캐릭터와 위젯·플로팅은 기존 서비스와 겹친다. 미감과 움직임의 완성도를 첫 선택·결제의 핵심 가치로 두고, 실제 행동의 순서·타이밍을 반영하는 추가 가치와 자료 제공 부담을 검증한다. 개인화 결과물의 일회성 구매와 선택형 확장 구매를 수익모델의 우선 가설로 둔다. 공개 자료, 개발자의 제품 방향, 고객 검증 결과를 구분한다.

[반려견 개인화 앱 목표 사용자와 시장 및 경쟁사 분석](./06_market_competitors.md)에 국내 수요 기반, 직접·인접 경쟁사, 공개 가격, 리뷰 사례와 고객 인터뷰 계획을 정리했다.

[반려견 앱 경쟁사의 매출 구조와 사업 현황](./07_competitor_revenue.md)에 과금 상품, 공개 실적과 추정치의 구분, 미감을 강점으로 삼는 수익모델 가설을 정리했다.

Pixel Pals를 화면 배치와 짧은 상호작용의 우선 벤치마크로 삼는다. 작은 크기의 미감·동작 연결·표시 설정·유료 확장을 비교하고, 우리 앱의 실제 반려견 외형과 습관 개인화에 적용한다. [Pixel Pals 벤치마킹과 반려견 앱 적용안](./08_pixel_pals_benchmark.md)에 시제품 범위와 실기기 확인 과제를 정리했다.

# 현재 설계 가정

2026-10-17 기준으로 Claude Haiku 5.5를 기본 분석 모델로 가정한다. 사진과 영상 프레임에서 행동 후보를 추출하고, 보호자가 확인한 기록을 프로필로 만들어 기기 내 행동 엔진이 재생한다. 첫 개인화는 반려견 한 마리, 기본 동작 8종과 필요한 전환, 대표 행동 최대 3개로 검증한다. 수량과 촬영 조건은 파일럿의 시작 설정이며 검증된 최소 자료량은 아니다.

캐릭터 애니메이션은 8fps를 시제품 기본값으로 채택한다. 기본 프레임 간격은 125ms이며, 동작당 그림 수는 동작 길이와 반복·정지 구간에 맞춰 정한다. 휴식 자세는 같은 그림을 길게 유지하고, 탭·드래그의 입력 처리는 애니메이션 갱신과 분리한다. 앱 내 재생과 Android 플로팅에 적용하며, 홈 화면 위젯은 별도의 OS 표시 범위를 따른다. 픽셀 원본 해상도는 64×64px를 후보로 검토 중이며, 작은 화면의 외형 식별과 동작 전환 품질을 시안에서 확인한다.

M0에서 목표 사용자와 경쟁 대안, 행동 개인화의 추가 가치·수집 부담·결제 방식을 먼저 검증한다. 기술·제품 개발 단계는 G0 Android 표시 검증, G1 한 마리 개인화, G2 탐색 파일럿, G3 Android·iOS 앱과 위젯 제공으로 유지하되 M0 결과에 따라 범위를 조정한다. 아래 첫 Android 시제품의 3가지 상태는 G0 범위이며, 실제 자료와 AI를 연결하는 G1에서 동작을 확장한다. 데이터 수집 문서의 P0·P1·P2 우선순위는 별도로 유지한다.

[Claude Haiku 5.5 기반 반려견 앱 상세 기획과 설계](./05_detailed_design.md)에 사용자 흐름, 데이터 위계, AI 출력 계약, 2D 제작 공정, 플랫폼별 표시 범위, 비용 통제와 검증 기준을 정리했다.

[픽셀 반려견 외형과 움직임 구현을 위한 GitHub 조사](./09_github_research.md)에 외형 편집, 강아지 동작 자산, 행동 전환, 8fps 재생과 생성 자동화 후보를 정리했다. Pixelorama·Aseprite·vscode-pets·Flame을 우선 검토하며, 도구 채택은 첫 개체 시안과 G0 결과로 결정한다.

# ChatGPT 프로젝트 지침

이 프로젝트에서 기획과 개발 파트너로서 실제 반려견 데이터를 반영한 2D 모바일 앱 개발을 지원한다. 현재 수집 양식, 행동 분류, 애니메이션과 평가 설계는 개를 기준으로 작성하며, 고양이 연구 결과를 개의 근거로 적용하지 않는다. 고양이의 구현과 검증은 후속 프로젝트에서 별도로 진행한다.

1. Android와 iOS를 모두 지원하되, Android 플로팅 모드의 기술 검증을 먼저 수행한다. 공통 앱과 홈 위젯은 이후 단계에서 확장한다.

2. 사진과 영상에서 외형 특징을 확인하고, 영상 및 보호자 기록에서 습관과 상황별 반응을 정리한다. 영상에서 관찰한 사실, 보호자 보고, 시스템의 추정을 구분한다.

3. 외형 자료, 애니메이션, 행동 선택 규칙, 사용자 입력, 플랫폼별 표시 기능을 분리해 설계한다. 같은 개체의 정보가 앱과 위젯에서 일관되게 사용되도록 한다.

4. 행동 개인화에는 상황, 반응이 나타나는 빈도, 반응까지 걸리는 시간, 지속시간, 선호와 회피를 검토한다. 자료가 없는 행동이나 감정을 실제 개체의 특성으로 단정하지 않는다.

5. 초기에는 한 개체와 소수의 행동으로 작동하는 시제품을 만든다. 실제 개체 자료를 받기 전에는 임시 캐릭터와 예시 행동값을 사용하고 이를 명확히 표시한다.

6. Android 플로팅 모드는 사용자가 직접 켜고 끌 수 있게 한다. 캐릭터 밖의 화면 조작을 방해하지 않고, 권한 거부·철회와 서비스 종료에 대응한다. 모든 화면에서 영구적으로 유지된다고 약속하지 않는다.

7. iOS는 앱 내 상호작용과 홈 화면 위젯을 중심으로 설계한다. Android의 자유로운 오버레이와 동일한 동작을 전제로 삼지 않는다. 위젯의 애니메이션과 갱신은 운영체제가 허용하는 범위에서 구현한다.

8. Claude Haiku 5.5 직접 API를 사진·영상 프레임의 행동 후보 추출과 보호자 설명의 구조화에 사용하는 것으로 가정한다. 관찰 자료·보호자 보고·파생값·제작 기본값을 구분하고, 확인된 프로필을 기기 내 규칙으로 재생한다. 외형 일러스트와 동작 자산은 별도 제작 공정으로 관리하며, 개체별 AI 모델 학습을 초기 필수 요건으로 두지 않는다.

9. 사진·영상·음성의 저장 위치, 이용 범위와 삭제 방법을 설계한다. G0 표시 시제품은 계정·서버 없이 검증한다. G1 외부 AI 분석부터는 API 키 보호와 사용자별 자료 접근을 위한 인증 서버를 두고, 원본은 기기에 유지하며 사용자가 확인한 분석용 프레임을 전송하는 흐름을 기본안으로 한다.

10. 기술 지원 여부, 정책, 라이브러리, 비용에 관한 설명은 최신 공식 자료로 확인하고 근거를 제시한다. 가정과 확정 사항을 구분한다.

11. 코드 작성, 빌드 성공, 설치 성공, 실기기 검증을 구분해 보고한다. 웹 미리보기만으로 모바일 오버레이가 검증되었다고 판단하지 않는다.

12. 각 단계에서 작동하는 결과물과 남은 문제를 정리한다. 최종 개발 도구와 배포 방식은 요구사항 및 기술 검증 결과에 따라 결정한다.

# 첫 Android 시제품

첫 시제품의 목적은 ‘다른 앱을 사용하는 동안 작은 반려동물이 자연스럽게 보이고, 필요할 때 반응하며, 휴대폰 조작을 방해하지 않는가’를 확인하는 것이다. 아래 항목은 이를 위한 초기 구현 범위다.

- 한 마리의 임시 2D 개 캐릭터를 배경 없이 표시한다.

- 걷기, 쉬기, 잠들기의 기본 동작을 구현한다.

- 탭하면 짧은 반응을 보이고, 드래그하면 위치를 옮긴다.

- 화면 가장자리를 벗어나지 않도록 위치를 조정한다.

- 앱에서 시작·중지하고, 실행 중에도 쉽게 종료할 수 있게 한다.

- 화면이 꺼지면 애니메이션을 중지하는 방향으로 설계한다.

- 행동 선택 규칙과 캐릭터 그림을 교체할 수 있게 구성한다.

영상에서 외형과 습관을 자동 추출하는 기능, 음성 호출, 결제, 커뮤니티와 다중 동물은 후속 단계로 둔다.

# 시제품 완료 기준

- 사용자가 권한을 허용한 경우에만 플로팅 모드가 시작된다.

- 홈 화면과 오버레이를 허용하는 일반 앱에서 캐릭터가 표시된다.

- 세 가지 기본 동작이 전환되고 탭과 드래그가 구분된다.

- 캐릭터가 차지하지 않는 영역에서는 다른 앱을 정상적으로 조작할 수 있다.

- 화면 회전과 표시 영역 변경 후에도 캐릭터를 조작하고 종료할 수 있다.

- 사용자가 종료하거나 권한을 철회하면 캐릭터와 관련 실행 작업이 정리된다.

- 화면 꺼짐과 복귀 상황에서 중복 표시나 불필요한 애니메이션 실행이 발생하지 않는다.

- 실제 Android 기기에서 발열, 배터리 사용, 반응 속도를 확인하고 기종과 OS 버전을 기록한다.

OS나 다른 앱이 오버레이를 제한하는 상황은 정상적인 제약으로 처리한다. Android 문서는 시스템이 오버레이의 위치·크기·표시 여부를 변경할 수 있다고 명시하며, 앱 창이 비시스템 오버레이를 차단하는 API도 제공한다. [Android 오버레이 창](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#TYPE_APPLICATION_OVERLAY), [오버레이 차단 API](https://developer.android.com/reference/android/view/Window#setHideOverlayWindows(boolean))

# 실제 반려견 데이터 적용

플로팅 기능을 검증한 뒤 반려견 한 마리의 사진, 일상 동영상과 보호자 설명을 적용한다. 자료 수량과 촬영 조건은 첫 결과물을 확인하면서 정하며, 정해진 수량만으로 충분한 재현이 가능하다고 가정하지 않는다.

각 행동 기록에는 행동명, 발생 상황, 반응, 빈도, 지속시간, 근거 자료와 보호자 확인 여부를 연결한다. 예를 들어 ‘장난감을 보여 주면 고개를 기울인다’는 기록은 관찰된 상황과 동작을 함께 보존한다. 반복 관찰 자료가 부족하면 정확한 확률을 부여하지 않고 보호자가 수정할 수 있는 임시값으로 관리한다.

외형 유사성, 대표 습관의 재현, 입력에 대한 반응, 반복 움직임의 자연스러움을 따로 검토한다. 보호자 평가와 영상 대조를 함께 사용한다.

# 플랫폼별 확장

1. Android 플로팅 검증: 권한, 표시, 기본 동작, 입력, 종료를 확인한다.

2. 반려견 한 마리 개인화: 실제 자료를 바탕으로 외형과 대표 습관을 적용한다.

3. 공통 앱: 등록, 자료 관리, 행동 수정, 앱 내 상호작용을 Android와 iOS에 제공한다.

4. 홈 화면 위젯: 각 플랫폼이 허용하는 갱신과 상호작용 범위에서 개체의 모습과 상태를 표시한다.

Android 오버레이는 별도의 표시 권한을 요구한다. 장시간 실행에 포그라운드 서비스를 사용하는 경우 관련 알림과 실행 제한을 반영해야 한다. [Android 오버레이 권한](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#TYPE_APPLICATION_OVERLAY), [포그라운드 서비스](https://developer.android.com/develop/background-work/services/fgs)

Apple의 위젯은 버튼과 토글을 통한 상호작용을 지원하지만, 위젯과 Live Activities의 데이터 변경 애니메이션은 최대 2초로 제한된다. iOS 홈 위젯은 지속적인 게임 애니메이션 대신 상태 표시와 짧은 반응에 맞춰 설계한다. [위젯 상호작용](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities), [위젯 애니메이션](https://developer.apple.com/documentation/widgetkit/animating-data-updates-in-widgets-and-live-activities)
