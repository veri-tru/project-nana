# 반려견 개인화 앱 세부 로드맵

기준일: 2026-10-19. 목표는 보호자가 사진과 짧은 응답으로 자신의 강아지를 만들고, 익숙한 행동을 발견한 뒤 일상에서 다시 만나고 싶어지는 경험이다. 첫 12주의 도착점은 Android 한정 탐색 파일럿과 다음 투자 범위의 판단이다. 공개 출시일을 약속하는 일정은 아니다.

이 일정의 기간·표본·평가 수치는 실행을 위한 제안이다. 현재 앱·개체용 자산·고객 실험은 미실시다. [현재 사양](current-spec.md)과 [개체 개인화 설계](personalization-spec.md)를 구현 기준으로 사용하고, 실제 담당자·첫 개체·기기·제작 속도를 확인한 뒤 주차를 다시 산정한다.

## 단계별 구분

작업은 아래 8단계로 구분한다. 1~7단계가 첫 12주 계획의 범위이고, 8단계는 결과에 따라 범위와 기간을 정하는 후속 단계다. 주차는 배치안이며 단계 완료는 산출물과 검증 결과로 판단한다. 기존 작업 코드 R0~R7은 추적을 위해 유지한다.

| 단계 | 목표 | 주요 작업 | 완료 기준 | 기존 작업과 예상 시기 |
| --- | --- | --- | --- | --- |
| 1. 착수 준비 | 무엇을 누구의 강아지로 시험할지 정함 | 첫 개체·자료·특징·담당 역할·기기·평가 기준 준비 | 실제 자료와 작업 환경을 확보하고 첫 과제를 설명할 수 있음 | R0, 1주차 |
| 2. 기본 앱 구현 | 화면에서 편하게 보고 조작할 수 있음 | 걷기·쉬기·잠든 자세, 탭·드래그·표시·숨기기·권한·종료 | 시험 기기에서 표시·조작·종료를 검수하고 사용을 막는 문제를 처리 | R1, 1~2주차 |
| 3. 외형 개인화 | 보호자가 우리 강아지로 알아봄 | 속성별 근거, 특징 최대 3개, 64/96 비교, 부품·좌우·무늬 수정 | 실제 표시 크기에서 보호자가 특징을 확인하고 시험 범위의 외형 오류를 수정 | R2, 2~3주차 |
| 4. 행동 개인화 | 익숙한 버릇을 재현함 | 몸 털기·기지개·대표 습관, 전환·호환, 응답 기반 규칙, 미리보기·수정·저장 | 확인된 습관이 지원 자산으로 재생되고 수정·되돌리기가 작동 | R3, 3~5주차 |
| 5. 중간 검증 | 개인화 행동의 추가 가치를 확인함 | 같은 외형·클립 품질의 A/B, 닮음·귀여움·행동 평가 분리 | 비교 조건을 검수하고 선호 이유와 개선 대상을 설명할 수 있음 | R4, 6주차 |
| 6. 여러 개체와 일상 사용 검증 | 다른 체형에서도 만들고 다시 사용할 수 있음 | 체형 확장 후 5~10개체의 각 7일 사용, 중단·수정·제작 시간 기록 | 실제 지원 조합과 재사용 한계, 사용 지속·중단 이유와 제작 부담 확인 | R5·R6, 7~9주차 |
| 7. 상품화 판단 | 제공 가능한 상품과 구매 조건을 정함 | 제작·수정 원가, 상품·가격 후보, 구매 의향·거절 이유, 보완 시험 | 지원 범위·납기·수정 조건·원가를 근거로 다음 판매 시험의 범위를 정함 | R7와 보완, 10~12주차 |
| 8. 판매와 확장 | 검증된 범위를 운영하며 확대함 | 제한 판매, 필요한 제작 자동화, 체형·행동 확대, iOS·위젯 검증, 공개 출시 준비 | 선택한 확장 작업별 실제 제공·운영·기기 검증 완료 | 파일럿 이후, 기간 미정 |

2단계 개발과 3단계의 자료·정적 외형 준비는 병행할 수 있다. 5단계에는 참여자마다 자기 개체의 외형과 공통 품질의 비교 자산이 필요하다. 6단계는 체형 호환 검수 후 일상 사용을 진행한다. 8단계 안의 작업 순서는 관측한 병목과 수요에 따라 선택한다. 고객 인터뷰는 2~5단계와 병행한다.

## 목표 경험과 이번 범위

발견 → 사진 선택 → 외형 특징 확인 → 익숙한 버릇 선택 → 첫 재현 → 짧은 일상 사용 → 한 가지씩 수정 → 추가 개인화의 구매 검토로 이어진다.

첫 가치 도달은 캐릭터 생성 완료와 구분한다. 보호자가 외형을 알아보고, 재현된 행동 중 자신의 강아지와 연결되는 구체적인 특징을 설명할 때를 첫 가치 도달로 기록한다. 귀여움만으로 행동 개인화 효과를 인정하지 않는다.

| 이번 12주에 확인할 것 | 이후 확장할 것 |
| --- | --- |
| Android G0의 표시·입력·종료와 기기 내 재생 | iOS의 적합한 표시 경험과 양 플랫폼 위젯 |
| 균형형 한 마리의 외형·대표 습관, 이후 짧고 긴 체형과 넓은 체형의 재사용성 | 9개 몸통 전체와 322종 전반의 자산 지원 |
| 사진·짧은 응답·보호자 수정에 따른 개인화 | 영상 기반 정밀 분석과 자동 fitting의 확대 |
| 동일 외형·동일 자산 품질의 행동 개인화 A/B | 자세 변형·클립 내부 속도·새 동작 자산 각각의 효과 |
| 5~10개체의 7일 사용과 제작·수정 원가 | 대규모 유지율·유료 전환율 검증과 공개 판매 |
| 결제 전 결과 확인·상품 범위·가격 후보 | 실제 결제·환불·복구를 포함한 판매 운영 |

공유는 파일럿에서 수요를 묻고, 개발 여유가 있으면 사용자가 요청한 장면을 저장하는 정도로 검토한다. 커뮤니티·친구 초대·공동 돌봄은 이번 완료 조건에 포함하지 않는다. 322종과 121개 대표 행동은 참고 사전이며 이번 제작 수량이 아니다.

## 일정과 역할의 가정

- 1주차는 실제 착수일부터 계산한다. 달력상의 시작일·출시일은 미정이다.
- 개발 1명과 픽셀 자산 제작 1명이 각각 주 5일 작업할 수 있는 경우의 배치안이다. 제품 기획·리서치·보호자 검수는 별도 역할로 두되 겸임할 수 있다. 실제 인원과 투입 시간은 확인 전이다.
- 개발과 자산 제작은 작업물의 입력 조건이 갖춰진 부분부터 병행한다. 한 사람이 겸임하면 같은 주차에 모두 끝내는 것으로 계산하지 않는다.
- 1~10주차는 기본 작업, 11~12주차는 재제작·모집 지연·기기 문제·재시험을 흡수하는 기간이다. 필수 검증이 남으면 완료 시점을 뒤로 옮긴다.
- 첫 개체 자료와 보호자 피드백, Android 시험 기기, 자산 제작 역량이 필요하다. 실제 자료가 없을 때 합성 예시로 형식을 준비할 수는 있지만 개체 닮음 검증으로 대체하지 않는다.
- 처음에는 사람이 외형 후보를 골라 검수하는 방식도 허용한다. 수작업 준비 시간과 비용을 기록하고, 이를 자동 생성 성능으로 표현하지 않는다. AI 공급자 선택은 이 첫 비교의 선행 조건이 아니다.

## 주차별 일정

| 시기 | 작업 묶음 | 주 산출물 | 다음 단계 조건 |
| --- | --- | --- | --- |
| 1주 | R0 범위·첫 개체·측정 준비, R1 G0 착수 | 입력 과제, 자료 처리안, 환경·기기 목록, 임시 재생 | 첫 개체 자료 확보 경로와 담당 역할 확인 |
| 2주 | R1 G0 마감, R2 개체 구조·외형 후보 | 기기 검수 기록, 외형 프로필과 64/96 비교본 | 표시·종료가 작동하고 특징을 근거와 연결 |
| 3주 | R2 닮음 검수, R3 동작·프로필 연결 착수 | 특징 최대 3개 검수, 자산 메타데이터·호환표 | 첫 개체의 외형과 시험 해상도 확인 |
| 4주 | R3 우선 동작·전환·행동 규칙 | 몸 털기·기지개를 포함한 실제 클립과 규칙 | 지원 조합의 접지·무늬·전환 검수 |
| 5주 | R3 첫 사용·수정 흐름, A/B 준비 | 입력→미리보기→수정→저장 시제품, 비교 자산 묶음 | 각 참여자의 자기 개체와 동일 품질 A/B 준비 |
| 6주 | R4 중간점검 A/B | 6명 탐색 비교, 문제·수정 우선순위 | 차이의 이유와 입력 부담을 확인하거나 수정 과제 특정 |
| 7주 | R5 수정과 체형 확장 | 짧고 긴 체형·넓은 체형 시험, 호환표 갱신 | 실제 검수된 범위와 지원 불가 범위 명시 |
| 8~9주 | R6 여러 개체의 7일 사용 | 5~10개체 사용 기록, 수정·제작 시간, 사용 중단 이유 | 마지막 참여자의 7일 관찰과 종료·삭제 검수 완료 |
| 10주 | R7 원가·구매 조건·다음 범위 판단 | 상품 후보, 제작 원가 범위, 구매 의향과 거절 이유 | 유지·개인화·제작 가능성을 함께 설명 가능 |
| 11~12주 | 보완·재시험·결과 확정 | G2 결과, 남은 문제, 후속 실행안 | 필수 미해결 항목과 실제 지원 범위를 확인 |

제품·니즈 인터뷰 M0는 2~6주차에 병행하는 안이다. G0 완료 전에 개인화 데이터 형식과 정적 외형을 준비할 수 있으나, 실제 통합 시제품 통과를 선언하지 않는다. G0에서 표시 문제가 남으면 앱 안 A/B로 개인화 연구를 진행할 수 있다. 이 경우 플로팅 검증은 미완료로 남으며 실제 일상 표시의 성과를 주장하지 않는다.

## 1단계 착수 준비

| 작업 | 담당 역할 | 산출물과 완료 조건 |
| --- | --- | --- |
| R0-1 첫 개체 선택 | 제품·보호자 | B01 또는 B02 후보에 맞는 개체 1마리, 기존 사진·특징·확인 가능한 행동. 품종명만으로 몸통을 확정하지 않음 |
| R0-2 사용 과제 정의 | 제품·개발 | 사진 선택, 특징 확인, 행동 선택, 미리보기, 수정, 저장, 종료의 화면 순서와 각 상태 |
| R0-3 실제 자료 처리 준비 | 제품·개발 | 수집 목적·접근자·저장 위치·삭제 범위, 사진 없이 시험 가능한 가상 데이터. 자료 수집 전에 적용 |
| R0-4 평가 방식 고정 | 리서치 | 외형 닮음·귀여움·행동 닮음의 분리 질문, 도움 제공·중단·미확인 기록 방식 |
| R0-5 작업 추적 준비 | 제품 | 역할별 작업 시간·대기 시간·재작업 시간, 빌드·프로필·자산 버전의 기록 양식 |

첫 사진 한 장으로 시작하되 확인되지 않는 부위를 억지로 채우지 않는다. 추가 자료 요청은 결과의 구체적 문제와 연결한다. 외부 분석·공유·학습은 최초 개인화 자료 제출과 별도 범위로 다룬다.

## 2단계 기본 앱 구현

선행 조건은 시험 기기와 실제 개발 환경의 확인이다. Kotlin 네이티브를 개발 기본안으로 사용하며 도입 시점의 공식 지원 조합·권한·서비스 요건을 확인한다.

| 작업 | 담당 역할 | 산출물과 완료 조건 |
| --- | --- | --- |
| R1-1 환경과 빌드 | 개발 | 실제 기기에서 실행한 빌드, OS·SDK·도구 버전 기록 |
| R1-2 기기 내 재생 | 개발·자산 | 임시 걷기·쉬기·잠든 자세. 기본 8fps·125ms, 입력·이동 시간과 그림 교체 분리 |
| R1-3 표시와 조작 | 개발 | 켜기·끄기, 탭·드래그, 위치·경계 처리. 캐릭터 바깥 터치가 앱 사용을 방해하는지 확인 |
| R1-4 수명주기 검수 | 개발 | 권한 거절·철회, 화면 꺼짐·복귀, 프로세스 종료·재실행, 중복 표시와 제거 확인 |
| R1-5 자원 사용 | 개발 | 같은 기기·밝기·시나리오에서 표시 켬/끔의 소비·발열·프레임 상태 기록 |

통과 조건은 지원한다고 명시할 기기에서 핵심 시나리오가 재현되고, 끄기 실패·유령 표시·조작 방해 등 사용을 막는 문제가 남지 않는 것이다. 최소 2개의 Android 기기·OS 조합을 목표로 하되, 1개만 시험했다면 지원 근거도 그 조합으로 제한한다. 배터리 절대 목표는 기초 측정 후 정한다. 기록은 [기기 검수 양식](../templates/device-check.md)을 사용한다.

## 3단계 외형 개인화

| 작업 | 담당 역할 | 산출물과 완료 조건 |
| --- | --- | --- |
| R2-1 개체 프로필 | 개발·제품 | 개체 ID, 선택적 품종 참고, 몸통·부위·무늬, 속성별 근거·좌우·미확인·충돌·보호자 확인 |
| R2-2 식별 특징 선택 | 보호자·자산 | 특징 최대 3개. 사진 관찰과 보호자 보고를 구분하고 보이지 않는 면은 미확인 유지 |
| R2-3 정적 후보 제작 | 자산 | 같은 개체·표시 너비의 64×64·96×96 후보. 중립·앉음·눕기에서 식별·가림 확인 |
| R2-4 호환표 최초 작성 | 자산·개발 | 실제 몸통·부품 버전, 방향, 연결점, 접지선, 겹침, 반전 허용 여부 |
| R2-5 외형 수정과 확인 | 보호자·자산 | 틀린 특징·좌우·무늬 수정, 선택한 특징의 표시 확인, 수정 시간과 이력 |

통과 조건은 보호자가 선택한 특징을 실제 표시 크기에서 확인하고, 시험한 방향·포즈에 남은 중대한 외형 오류가 없는 것이다. 단순한 가림과 그림 오류를 구별한다. 여기서 고른 해상도는 첫 G1 제작 기준이며 전체 체형의 검증 완료를 뜻하지 않는다. [한 마리 검수 양식](../templates/pet-likeness-review.md)에 기록한다.

## 4단계 행동 개인화와 첫 사용 시제품

행동은 클립 제작, 개체별 적용 규칙, 보호자 확인을 나누어 진행한다. 같은 클립을 쓰더라도 선택·빈도·발생 시점에 따라 다른 개체 경험을 만들 수 있어야 한다.

| 우선순위 | 제작·연결 범위 | 적용 원칙 |
| --- | --- | --- |
| G0 유지 | 걷기·쉬기·잠든 자세 | 검수된 기본 재생과 이동·표시 기반을 재사용 |
| 첫 개인화 | 앉기·눕기와 필요한 전환, 몸 털기, 기지개 | 몸 털기·기지개는 각각 포함. 해당 개체의 발생 상황과 빈도는 별도 확인 |
| 개체별 대표 습관 | 첫 개체에서 확인된 행동 1개부터 | 위 동작을 사용할 수도 있음. 지원·근거가 있으면 고개·꼬리·앞발 행동으로 보완 |
| 후속 변형 | 입 벌림·헥헥거림·두 발 서기·세부 자세·물체 행동 | 실제 필요와 호환 검수 후 확대. 조사 목록을 한꺼번에 제작하지 않음 |

기존 기본 동작 8종과 대표 행동 최대 3개는 G1 구성 제안으로 유지한다. 첫 비교에 필요한 동작부터 만든다. 행동 이름 수와 실제 파일 수는 다르며 시작·끝 자세의 전환 자산도 공수에 포함한다.

| 작업 | 담당 역할 | 산출물과 완료 조건 |
| --- | --- | --- |
| R3-1 클립과 전환 | 자산·개발 | 행동 코드→클립 버전→시작/끝 자세→지원 몸통 대응, 접지·가림·무늬 검수 |
| R3-2 선택 질문 | 제품·리서치 | 짧은 동작 예시와 상황 질문, 한다·하지 않는다·모른다·건너뛴다를 구별 |
| R3-3 행동 프로필 | 개발 | 상황별 선택·빈도·발생 타이밍, 근거와 확인 상태. 미확인을 빈도 0으로 변환하지 않음 |
| R3-4 재생 규칙 | 개발 | 클립 지원 확인, 시작/끝 자세 연결, 중단·재시작, 잘못된 프로필의 적용 보류 |
| R3-5 첫 사용 흐름 | 개발·제품 | 사진→외형 확인→짧은 행동 응답→미리보기→수정→저장. 중간 이탈 후 복귀와 실패 재시도 |
| R3-6 수정과 자료 삭제 | 개발 | 수정 전후 미리보기·되돌리기, 사진과 프로필의 삭제 범위 설명·처리 상태 확인 |
| R3-7 비교 준비 | 개발·리서치 | A/B 프로필, 동일 자산 목록·전환 버전, 실제 재생·오류 기록, 참여자별 외형 확인 |

첫 경험에는 대표 습관 하나를 보여주고 추가 질문은 수정·확장 시점으로 넘긴다. 첫 입력과 확인의 사용자 조작 시간은 3~5분을 목표로 시험한다. 사진 제출부터 개인화 결과가 준비될 때까지의 총 경과 시간, 제작자의 작업 시간, 사용자의 조작 시간을 각각 기록한다. 미리 만들어 둔 개체 자산으로 수행한 입력 실험은 즉시 생성 성능의 증거가 아니다.

사용자에게 준비 중인 상태와 실제 제공 가능한 대기 범위를 알린다. 아직 지원하지 못하는 체형·행동은 지원되지 않는 것으로 안내하고 다른 개체나 일반 행동으로 몰래 대체하지 않는다. 샘플 구경은 가능하지만 자기 개체의 개인화 결과와 구별한다.

사진 자동 분석이 필요한 병목으로 확인되면 G1 안에서 별도 작업으로 추가한다. 그때 공식 모델 기능·비용, 동의 범위, 후보 정확도·수정 시간·실패 복구를 검증한다. 공급자 선택이나 자동 분석 성공을 현재 일정의 확정 전제로 놓지 않는다.

## 5단계 중간 검증

목적은 같은 외형과 같은 자산 품질에서 응답에 따른 행동 선택·빈도·발생 타이밍이 자기 강아지다움을 더하는지 확인하는 것이다. 새로운 자세나 더 정교한 작화를 B에만 제공하지 않는다.

| 항목 | 실행안 |
| --- | --- |
| 표본 | 20대 여성 3명·30대 여성 3명, 총 6명부터 시작. 현재 보호자이며 검수된 범위에서 자기 개체 자산이 준비된 사람 |
| 선행 조건 | 6명 각각의 실제 개체 외형을 확인. 한 마리의 결과물을 여러 보호자에게 보여주고 자기 개체 비교로 집계하지 않음 |
| 조건 | A 공통 행동 프로필, B 응답 기반 프로필. 외형·클립 목록·버전·전환·내부 속도·기기·표시 크기 고정 |
| 노출 | 사전 점검으로 길이를 정하고 A/B에 동일 적용. 동일한 앱 내 상황 자극을 제시하며 실제 동작·횟수·시각을 기록 |
| 순서 | A 먼저 3명, B 먼저 3명. 화면에 개인화 여부를 알리지 않음 |
| 주요 결과 | 자기 강아지다운 행동의 선택과 구체적인 이유. A·B·차이 없음·둘 다 닮지 않음·판단 어려움 |
| 별도 평가 | 외형 닮음·귀여움·자연스러움·입력 부담·수정 요청. 첫 선호 질문 후 수집 |
| 타당성 점검 | 두 조건의 규칙과 실제 노출에 의도한 차이가 있었는지, 한쪽만 깨지거나 지연되지 않았는지 확인 |

6명 중 4명 이상이 B를 선택하고 자신의 강아지에게서 아는 구체적 행동을 이유로 설명하는 것을 다음 파일럿으로 진행할 탐색 신호로 제안한다. 이는 실무상 수정 우선순위를 정하는 기준이며 통계적 우월성이나 시장 성공 기준이 아니다. 기준은 첫 세션 전에 고정한다.

해석 가능한 비교가 6명 미만이면 결과를 억지로 채우지 않는다. 중단·오류·제외 사유와 전체 시도 인원을 함께 보고하고 보완한다. 차이가 느껴지지 않으면 질문이 습관을 잘 구분하는지, 장면이 해당 습관을 보여주는지, 개인화 규칙이 실제 적용됐는지 순서대로 확인한다. 행동 개인화의 방향을 유지하며 요소·상황·입력을 수정한다.

이전 결정의 속도·순서 개인화는 장기 후보로 유지한다. 첫 A/B는 [10월 18일 상세 통제안](personalization-spec.md)에 따라 내부 속도와 전환 자산을 고정한다. 선택·빈도·발생 타이밍을 함께 바꾼 결과를 각 변수의 독립 효과로 설명하지 않는다.

## 6단계 여러 개체와 일상 사용 검증

### R5 수정과 체형 확장

A/B에서 나온 주요 문제를 먼저 고친 후 B06/B07 중 짧고 긴 체형 하나, B08/B09 중 넓은 체형 하나를 실제 개체에 맞춰 시험한다. 몸통 코드만 추가해 지원 범위가 늘었다고 표시하지 않는다.

각 체형에서 실제 부품·클립 조합, 연결점·접지·가림·비대칭, 대표 특징의 식별, 수정 시간과 재사용 가능 항목을 기록한다. 모든 행동의 지원을 복제하지 않고 검수한 조합만 공개한다. 기존 균형형의 시험 해상도가 적합하지 않으면 크기·자산 규격을 재검토하고 관련 비교물을 다시 맞춘다.

통과 조건은 처음 시험한 균형형과 확장한 두 체형 각각에 검수 기록이 있고, 다음 참여자에게 제공할 수 있는 범위를 목록으로 설명할 수 있는 것이다. 호환성이 부족하면 그 체형의 등록을 보류하고 파일럿 대상을 실제 지원 범위로 제한한다.

### R6 여러 개체의 7일 파일럿

| 항목 | 실행안과 완료 조건 |
| --- | --- |
| 규모 | 5~10개체, 각 1명의 보호자를 기본 단위로 사용. 같은 가구·복수 개체는 관계를 기록 |
| 지원 조건 | 실제 검수된 체형·동작·Android 조합. 지원 밖 체형은 제외 사유를 남기고 별도 수요로 집계 |
| 새 사용자 | A/B 참여자와 겹칠 수 있으나 처음 사용하는 보호자도 최소 2명 포함하는 안. 기존 경험 여부를 분리 |
| 기간 | 개인화 결과를 실제 사용할 수 있게 된 시점부터 각 7일. 마지막 참여자의 관찰이 끝나야 종료 |
| 일상 경험 | 보기·탭·드래그·숨기기·다시 표시, 자발적 수정. 미접속을 벌주는 상태 하락을 두지 않는 안 |
| 확인 | 다시 본 이유, 끈 이유, 방해 상황, 대표 습관의 재인식, 원하는 수정과 자료 제출 부담 |
| 운영 | 문의·오류 대응, 프로필 되돌리기, 삭제 범위·완료 상태, 기기별 표시·종료 문제 확인 |
| 제작 | 개체당 최초 제작·부품 수정·클립 수정·검수·보호자 대기 시간을 나누어 기록 |

가능하면 첫날·중간·7일째에 짧게 확인하되, 조사자의 알림으로 돌아온 경우와 자발적으로 다시 본 경우를 구분한다. 자동 실행이나 계속 떠 있는 표시를 방문으로 세지 않는다. 지원 체형과 Android 사용 조건 때문에 생긴 표본 제한을 결과에 남긴다.

파일럿 완료 조건은 정해진 관찰과 제작 기록이 모이고, 표시 중지·자료 손실·삭제 실패처럼 사용을 막는 문제의 처리 상태가 확인되는 것이다. 다음 확장 판단에는 행동을 다시 알아본 사례, 자발적 재방문과 중단 이유, 개체당 제작·수정 부담을 함께 사용한다. 작은 표본의 유지율 하나로 출시를 결정하지 않는다.

## 7단계 상품화 판단

무료 범위와 유료 범위는 아직 가설이다. 기본 외형과 대표 습관을 체험하고, 추가 습관·자세 변형·세밀한 제작을 구매하는 안을 비교한다. 미리보기·수정 횟수·납기·지원 범위·보관·재사용 조건을 같은 수준으로 설명한다.

| 작업 | 산출물 |
| --- | --- |
| 제작 원가 정리 | 최초 공통 자산 제작비와 개체별 추가 비용 분리. 역할별 작업시간×실제 적용 단가, 수정·문의·외부 처리 비용 |
| 상품 비교안 | 포함 행동·지원 체형·수정·제공 시점이 명확한 상품 2~3안. 가격은 관측한 비용과 인터뷰를 바탕으로 제안 |
| 구매 과제 | 구매하지 않음 포함 선택, 가격·결과·입력 부담·대기 때문에 거절한 이유 |
| 사업 판단 | 사용은 좋아하지만 구매하지 않는 경우, 작품 저장은 원하지만 상주는 싫은 경우 등 차이 분리 |

버튼 클릭·가격 선택·구매 의향은 실제 결제로 기록하지 않는다. 이번 12주 기본 범위는 판매 준비 판단까지다. 실제 결제를 시험하기로 정하면 제공 가능한 결과물과 판매·수정·취소 조건, 결제·복구 구현을 갖춘 별도 작업으로 추가한다. 현재 자료의 가격 예시를 확정 판매가로 사용하지 않는다.

| R4 A/B | 위 고객군 중 자기 개체 자산이 준비된 여성 6명부터 | 연령별 3명으로 집단 우열을 검증하지 않음. 전체 탐색 비교 |
| R6 파일럿 | 실제 지원 범위의 Android 보호자 5~10명 | A/B와 일부 중복 가능. 새 사용자 최소 2명 제안, 사용 경험 여부 기록 |

위 인원은 서로 중복될 수 있으므로 합계를 고유 참여자 수로 발표하지 않는다. 참여자 ID·개체 ID·조사 참여 이력으로 구분한다. iPhone 보호자는 니즈 인터뷰와 같은 시험 기기의 A/B에 참여할 수 있으나 Android 파일럿 기록으로 대체하지 않는다. 양 연령군에 이용과 구매를 모두 묻고 남성 비교군도 같은 과제를 사용한다.

모집·자료 확보가 늦으면 비교 실행일을 조정한다. 준비된 사람만의 빠른 결과와 전체 신청자의 이탈·대기·지원 불가를 함께 기록한다. 참가자 모집이나 외부 연락은 이 문서 작성에 포함되지 않는다.

## 측정할 결과와 기록 방식

| 항목 | 정의 | 사용할 판단 |
| --- | --- | --- |
| 첫 사용 완료 | 시작한 사람 중 미리보기 확인·저장까지 도달한 사람 수, 도움 유무 | 어느 화면에서 중단하는지 확인. 6명 중 5명이 진행자 도움 없이 완료하는 것을 초기 개선 목표로 제안 |
| 사용자 조작 시간 | 사진 선택 시작부터 확인·저장까지 실제 조작한 시간 | 3~5분 목표. 미완료 인원을 함께 보고하고 중앙값만으로 숨기지 않음 |
| 결과 준비 경과 시간 | 자료 접수부터 사용할 수 있는 결과 준비까지 | 수작업·자동 처리·대기 시간을 포함한 실제 납기 |
| 첫 가치 도달 | 자신의 외형 특징과 재현 행동을 구체적으로 연결한 시점 | 생성 완료·귀여움·행동 닮음을 분리 |
| 외형 수정 | 특징별 수정 횟수와 원인, 제작·보호자 시간 | 외형 입력과 자산 재사용성 개선 |
| 행동 개인화 | A/B의 선택·이유·실제 노출·오류 | 품질 차이와 개인화 효과 구분 |
| 7일 사용 | 사용 가능 시점 기준 날짜별 자발적 재방문·숨김·중단과 이유 | 자동 표시와 능동 사용 분리, 관찰 가능 인원·중도 중단 표시 |
| 개체당 비용 | 제작·수정·검수·문의 시간과 처리 비용 | 가격 후보와 감당 가능한 지원 범위 |
| 구매 | 의향·상품 선택·실제 결제를 별도 필드로 기록 | 유료 수요의 증거 강도 구분 |

최소 기록은 익명 참여자 ID, 개체 ID, 단계, 시각, 도움·중단 여부, 프로필·자산·앱 버전이다. A/B에는 제시 순서와 실제 클립·횟수·시각을 추가한다. 원본 사진이나 자유 서술을 불필요하게 이벤트 기록에 복사하지 않는다. 데이터 전송·외부 분석 도구 도입은 저장 구조와 처리 범위를 먼저 정한 뒤 진행한다.

## 중간점검 때 남길 판단

2주차에는 G0의 실제 지원 기기와 종료 가능성, 3주차에는 한 마리의 외형·해상도·제작 시간, 6주차에는 행동 개인화의 탐색 결과, 9주차에는 일상 사용과 재사용성, 10~12주차에는 제작 원가와 후속 범위를 판단한다. 각 점검에 완료 증거, 남은 문제, 수정 대상, 다음 일정과 담당 역할을 남긴다.

## 8단계 판매와 확장

후속 기간은 파일럿의 실제 제작·수정 시간과 지원 범위를 확인한 뒤 추정한다. Android에서 확인한 효과와 표시 기능을 iOS에 그대로 적용하지 않는다.

| 후속 작업 | 시작 조건 | 산출물과 완료 기준 |
| --- | --- | --- |
| 제한된 Android 판매 시험 | 행동 개인화의 구체적 가치, 제공 가능한 범위·납기·원가가 확인됨 | 상품·결제·취소·복구·수정 지원을 연결하고 실제 전달·환불·재작업 비용 기록. 구매 의향과 별도 결과 |
| 제작 자동화 | 사람이 반복하는 선택·보정 작업이 주요 비용으로 측정됨 | 수작업 결과와 같은 기준으로 후보 정확도·수정 시간·비용 비교. 보호자 확인과 실패 복구 유지 |
| 체형·행동 확대 | 현재 범위에서 처리 가능한 수요와 지원 밖 요청이 확인됨 | 수요·제작 부담 순으로 조합 추가, 몸통·부품·방향·동작별 호환표 갱신 |
| iOS와 위젯 검증 | 핵심 사용 경험이 확인되고 별도 플랫폼 투입 범위를 정함 | 공식 지원 범위와 실제 기기에서 표시·상호작용·종료·자원 사용 검증. 플랫폼에 맞는 사용자 흐름 |
| 공개 출시 준비 | 판매·운영·지원 기기·자료 처리의 실제 검증 완료 | 지원 범위와 제공 조건을 공개 문구에 일치시키고 배포·문의·장애 대응·복구 확인 |

먼저 확인된 병목에 따라 제한 판매와 자동화의 순서는 조정할 수 있다. 추가 기능을 구매자가 원한다는 이유만으로 해당 자산이 제작·검수됐다고 처리하지 않는다. 공개 출시 후에는 실제 유입 경로별 첫 가치 도달·자발적 사용·결제·환불을 관찰하고 다음 체형과 동작의 우선순위를 갱신한다.

현재는 로드맵 작성만 완료했다. 개별 작업의 실행 상태는 [작업 목록](backlog.md)에 기록하고, 이번 계획의 주차·표본을 사용자 확정 결정으로 옮기지 않는다. 실제 선택이 생기면 근거와 영향 범위를 함께 결정 기록에 반영한다.
