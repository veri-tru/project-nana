# 프로필 기반 제작기와 제품 로드맵

현재 개체 등록 범위는 기존 실개체 3마리와 가이드 9개 몸통 계열의 대표 사진 27장이다. 제공 사진의 자세를 개체별로 등록해 30개체의 정지 출력을 재현했다. 신규 사진에서 관절 윤곽을 읽는 작업은 수동이며, 미관찰 자세의 변형과 동작 프레임 제작은 후속 단계다.

휘핏·닥스훈트는 코·입 수정 기준본을 기본 경로에서 재현했다. 직전 공통 몸통 실험은 철회했다. 다음에는 한 부위씩 공통화하고 바로 전 기준본과 대조한다. 같은 자세·같은 치수에서는 전신 픽셀 차이가 0이어야 한다. 치수를 바꾸는 비교에서는 대상 부위와 허용된 겹침 범위 밖의 차이가 0인지 확인한 뒤 새 개체로 확대한다.

목표는 **개체 공통 픽셀 캐릭터 제작 엔진**이다. 나나에서 찾은 문제는 먼저 개체 입력, 자세 입력, 공통 부품·규칙 중 어디에 속하는지 구분한다. 지원 범위 안의 서로 다른 강아지에게 같은 자세와 엔진 버전을 적용해 프로필만 바꾸었을 때 관찰된 차이가 나타나는지 시험한다. 나나는 첫 사례이고, 단계 3에서는 추가 2개체의 결과·개별 보정량·미지원 특징을 기록한다.

## 2026-11-04 다음 제작 실험 — 사진 1의 서기 전신

사진 1 서기 전신에서 보호자는 A의 머리 비율, 수정한 두 눈의 균형, 기존 A의 얼굴 음영을 선택했다. 이 조합을 사진 1 서기 기준본으로 기록했다. [시안 및 검수 기록](handoff.md)

1. **사진 1의 자세와 검사 기준을 고정한다.** 머리 방향부터 발까지 사진 1 한 장에 맞춘다. 크롭·좌우·정렬점, 개체 입력과 자세 입력을 기록한다. 관찰·형태 검토자는 작화 전에 제작에 쓰지 않을 가시 항목을 따로 기록한다. 예를 들어 발 위치를 직접 찍었다면 그 발은 재현 확인에만 쓴다. 귀끝을 트레이싱했다면 그 점도 독립 검증에서 제외한다. 전체 외곽을 따라 그렸다면 사진을 보며 독립 판독한 것과 미사용 검사를 구분한다. 사진 2·3은 해당 자세에서 공통으로 보이는 특징을 교차 확인할 때만 쓴다. 사진 1에서 잘린 꼬리끝은 미확인이다.
2. **한 기준안에서 누적 단계 세 장을 저장한다.** S1은 단색 전신 외곽, S2는 같은 외곽 안의 부위 경계와 고유 무늬, S3는 같은 부위 배치에 음영까지 넣은 결과다. 모두 64×64 원본으로 저장한다. 세 단계는 한 그림이 만들어지는 과정을 보여 준다. 개선안을 비교하는 별도 라운드에서만 한 변수를 바꾼 A·B·C 세 후보를 병렬 제작한다.
3. **새 검토자 둘이 같은 파일을 독립적으로 확인한다.** 두 검토자 모두 현재 세션과 같은 모델을 쓰며 서로의 판정을 보기 전에 기록한다. 관찰·형태 담당은 사진의 좌우, 보이는 겹침, 검사용으로 남긴 위치나 비율을 비교한다. 렌더링·규격 담당은 저장된 각 원본과 비교판을 열어 1배 식별, 정수 확대, 단계 간 외곽 알파 보존, S2→S3 부위와 무늬 마스크 보존을 확인한다. 각자 파일·단계·부위·근거를 적고 통과, 수정 필요, 판정 불가를 구분한다.
4. **최초로 깨진 단계만 고친다.** 사진 혼용이나 좌우 오류면 입력으로, 외곽 불일치면 S1으로, 겹침·무늬 문제면 S2로, 음영이 부위를 덮으면 S3로 돌아간다. S2에서 원인이 불분명하면 겹침만 켠 보기와 고유 무늬만 켠 보기를 대조한다. 주 작업자가 타당성을 판단해 재현된 지적을 자동 수정하고 영향받은 파일과 비교판을 새 검토자에게 다시 보낸다. 수정에 사용한 검사항목은 이후 회귀 확인으로 표시한다.
5. **보호자에게 세 단계의 1배 전신을 보여 준다.** 나나와 처음 달라 보인 단계와 부위를 확인한다. 방법론 검토가 통과해도 보호자가 다른 동물처럼 느끼면 단계 2는 열린 상태다. 나나에서 확인된 뒤 두 번째 개체의 프로필만 바꿔 같은 부품·같은 절차로 재현되는지 시험한다. 이후 다른 자세와 동작으로 넓힌다.

방법론 자문에는 Astra/xhigh를 사용한다. 두 검토자의 의견이 충돌하면 먼저 쟁점이 된 원본·마스크·관찰 근거를 재확인한다. 같은 실패가 반복되거나 현 실험으로 원인을 분리할 수 없을 때 Astra/xhigh에 실험 설계를 다시 의뢰한다. 닮음과 후보 선택은 보호자가 판단한다. [방법론 자문 기록](handoff.md)

## 1. 사용자 경험과 내부 제작

사용자는 기존 3단계를 유지한다.

1. 사진 등록.
2. 지원되는 털 표현 선택과 모습 확인·필요한 수정.
3. 행동 설정과 결과 확인. 모름·나중에를 허용한다.

내부 흐름은 사진의 관찰 후보 추출 → 근거·미확인·제작값을 구분한 프로필 저장 → 지원 범위 검사 → 부품·색면·가림·동작 구성 → 검수 → 버전이 고정된 사용 묶음이다. 별도의 눈꺼풀·레이어·화풍 설문을 필수로 추가하지 않는다.

| 동작 패키지 | 지원하는 포즈·프레임·변형·접지·가림·전환 | 프레임마다 독립 생성한 그림 |
| 사용 묶음 | 위 버전과 검수된 PNG/메타데이터의 정확한 조합 | 검수 없이 바뀌는 실행 결과 |

제작기는 **버전이 고정된 부품·마스크·색 역할을 프로필에 맞게 조립하고 정수 픽셀 좌표로 출력하는 방식**부터 검증한다. 부품 제작에는 초기 픽셀 작화 작업이 필요하다. 단순 도형 조립만으로 B2/C2 미감과 모든 개체의 닮음이 보장된다고 가정하지 않는다.

사진 분석 AI는 외형 후보를 만들고, 행동은 보호자 응답·관찰 근거로 연결한다. 사진 한 장에서 습관이나 가려진 해부학을 확정하지 않는다. 이미지 생성 도구는 필요할 때 부품 개발·연구에 사용할 수 있으나 제품 출력의 매 프레임 필수 경로로 두지 않는다. 특정 모델 학습·LoRA·새 공급자 도입은 이번 일정의 전제가 아니다.

## 2. 일정 가정

- 개발 1명과 픽셀 자산 제작 1명이 주 5일 투입하고, 제품 설계·보호자 검수 역할을 확보하는 경우 **8–12주 내 제한된 Android 시제품·파일럿 진입을 목표로 하는 배치안**이다. 실제 인력·속도·기기 확보는 확인 전이다.
- 한 사람이 개발·작화를 겸임하면 병행 일정이 성립하지 않는다. 단계 2의 첫 제작 시간과 단계 3의 재사용 결과로 다시 산정한다.
- 주차는 실제 착수부터 계산한다. 현재 날짜를 착수일이나 출시일로 고정하지 않는다.
- 초반에는 사람이 사진을 보고 프로필을 입력해도 된다. 이는 제작기의 재현성 검증이며 자동 등록 성능과 구분한다.
- 사용자 추가 자료를 기다리는 시간, 공통 부품 제작 시간, 개체별 보정 시간과 자동 처리 시간을 각각 기록한다.
- Android G0는 1–2주차에 병행할 수 있다. 제작기 자체를 휴대폰 안에서 실행할지는 미정이며, 초기 통합은 검수된 PNG·메타데이터를 기기에서 재생하는 방식으로 분리한다.

사진 분석은 단계 1 이후 조사·추출 실험을 병행할 수 있다. 다만 그 자동 분석 성공을 정적 제작기 검증의 선행 조건으로 두지 않는다. 단계 5 통과 전에는 완전 자동 등록으로 소개하지 않는다.

## 4. 단계 0–2의 구체 산출물

### 프로필과 출력 계약

- 외형: 머리/몸 비율, 귀·주둥이 형태, 눈 위치·크기·노출·눈꺼풀, 앞털 가림, 부위별 털 길이·색·큰 무늬, 다리·꼬리 구조를 실제 지원 범위로 표현한다.
- 모든 속성에 관찰/보호자 보고/파생/제작 기본값, 근거, 미확인과 확인 범위를 연결한다. 실제 개체마다 필요한 구조와 지원 범위를 구분한다.
- 털 선택은 실제 털의 관찰값과 별도 표현 설정이다. 행동도 관찰된 습관과 사용자가 보고 싶은 연출을 구분한다.
- 렌더 요청은 profile_revision, 제작 구조 버전, 화풍·동작 패키지 해시, 렌더러 버전, 출력 격자·방향·동작·프레임을 고정한다.
- 결과는 PNG/시트와 메타데이터, 사용한 입력 버전, 지원 범위, 검수 상태를 함께 저장한다.

### 최소 정적 제작기

1. 얼굴·귀·몸·발·꼬리의 큰 색면과 실루엣을 구현한다.
2. 눈/홍채/동공, 눈꺼풀 마스크, 앞털 가림을 분리한다. 모든 개에 같은 눈꺼풀을 붙이지 않는다.
3. 기본색+음영 역할과 유색 외곽선을 규칙으로 제한한다. 실제 격자에서 팔레트·알파·경계를 검사한다.
4. 같은 개체 구조의 B2/C2에서 윤곽 표현만 달라지는지 확인한다. 눈 간격·귀 길이·무늬가 바뀌면 실패다.
5. 64×64 원본에서 표시성과 개체 식별을 검증한다. 기존 96×96 출력은 비교용이며, 자동 축소본만으로 정본을 승인하지 않는다.
6. 실제 표시 크기에서 보호자가 개체의 주요 특징을 확인하고, 제작자는 정본 대비 색면·밀도·윤곽을 검수한다.

지원 방향은 필요한 근거와 자산을 갖춘 것부터 연다. 정면 사진만 있는 개체의 측면·뒷모습을 확정하지 않는다. 걷기용 방향을 새로 제작할 때는 그 방향의 지원·검수 항목을 추가한다.

실행 출력에 정본 PNG가 필요하지 않다는 뜻이지, 픽셀 부품·마스크 같은 제작 자산까지 없앤다는 뜻은 아니다. 재사용 가능한 제작 패키지가 그 책임을 맡는다. 같은 결과를 복사해 재현성 검사를 통과시키지 않으며 입력 속성을 바꿨을 때 지정 범위의 출력이 달라지는지도 확인한다.

## 6. 동작·행동·앱의 연결

- 기본 제작 순서는 정적 한 개체 → 다른 개체 적용 → 걷기·쉬기·잠든 자세와 전환이다. 별도 프레임 시안을 순차 생성하는 방식으로 동작을 완성하지 않는다.
- 단순 회전/늘이기만으로 모든 자세를 처리하지 않는다. 필요한 방향·관절·눈꺼풀·가림은 포즈별 부품과 검수된 변형으로 보완하고 픽셀 격자를 유지한다.
- 개체별 행동 설정은 같은 동작 패키지의 선택·빈도·발생 조건을 바꾼다. 물리적인 움직임·전환이 미지원이면 해당 행동을 지원한다고 표시하지 않는다.
- 기본 8fps·125ms를 유지하며 입력·이동·상태 체류 시간은 독립시킨다. 동작당 프레임 수는 별도다.
- 몸 털기·기지개와 확인된 대표 습관은 G1 후속 필수 검토 항목으로 유지한다. 단계 4의 세 기본 상태만으로 행동 개인화 A/B가 준비됐다고 선언하지 않는다.
- Android G0는 임시 자산으로 표시·탭·드래그·켜기/끄기·권한·종료를 먼저 검증하고 단계 6에서 제작기 산출물과 연결한다. 기기 내 재생은 외부 모델 호출 없이 동작한다.
- 모바일에 제작기를 내장할지, 별도 제작 과정에서 자산을 내려줄지는 패키지 크기·제작 시간·업데이트 비용을 실측한 뒤 결정한다. 아직 서버나 새 프레임워크를 선정하지 않는다.

| 같은 입력도 모양이 달라짐 | 누락된 버전·난수·외부 상태·렌더 경로 확인 | 재현성 확보 전 동작/개체 확대 중단 |
| 모든 개가 같은 얼굴로 보임 | 눈·귀·주둥이·비율 표현 범위와 부품 구조 수정 | 색만 바뀌는 상태를 개인화 완료로 처리하지 않음 |
| 사진을 잘못 읽음 | 속성별 근거·불확실성·필요 시 짧은 수정 흐름 보완 | 자동 분석 오류를 제작기나 개체 사실로 덮어쓰지 않음 |
| 정본 미감이 구현되지 않음 | 픽셀 작화·팔레트·털 덩어리 규칙 재작업 | 단계 2의 기술/시각 검증 전 전체 자동화 약속 보류 |
| 새 개체마다 전체 재작화 필요 | 공통 부품과 개체 보정 경계 재설계, 지원 범위 축소 | 경제성·재사용성 확인 전 등록 대상 확대 보류 |
| 포즈가 바뀌면 얼굴·무늬가 깨짐 | 해당 방향의 연결점·마스크·포즈별 부품 보완 | 검수하지 않은 방향/동작 제공 보류 |
| 지원 기기/자료/보호자 미확보 | 형식·내부 검증을 진행하고 외부 검수는 대기 표시 | 합성 자료·내부 평가로 실제 파일럿 통과를 대체하지 않음 |

규칙 기반 조립으로 목표 미감과 개체 차이를 충분히 표현하지 못하면 표현 구조를 다시 평가한다. 필요 시 별도 생성/학습 방식의 비용·재현성·수정 가능성을 검토할 수 있으나, 현재 공급자가 그 기능을 지원하거나 이미 구현된 것으로 전제하지 않는다.

## 9. 기존 제품 계획과 연결

| 기존 작업 | 현재 위치 |
| --- | --- |
| R0 착수 | 단계 0, 자료·역할·측정 준비 |
| R1 / G0 | 1–2주차 병행, 단계 6 통합 전 실기기 검수 |
| R2 외형 개인화 | 단계 1–3의 프로필·제작기·재사용 검증 |
| R3 / G1 | 단계 4–5와 몸 털기·기지개·대표 습관 후속 작업 |
| R4 행동 A/B | 필요한 개체·동작이 검수된 후. 기존 6주차 자동 개시 없음 |
| R5 확장 | 단계 3에서 제한된 다른 개체 시험, 이후 수요·지원 근거에 따라 확대 |
| R6 / G2 | 단계 6 이후 실제 지원 범위의 파일럿 |
| R7 상품화 | 실제 최초 제작·개체별 보정·검수·운영 시간과 사용 가치로 판단 |
| G3 판매/iOS/위젯 | 파일럿 결과 이후 별도 범위·일정 |

단계 3의 3개체 내부 검증과 보호자 파일럿을 구분한다. 파일럿은 검수된 개체부터 최대 5–10개체, 각 7일을 기존 탐색 제안으로 유지하되 지원 범위와 확보 인원에 맞춰 조정한다. 한 마리 결과를 여러 보호자의 자기 개 비교로 집계하지 않는다.

행동 개인화 A/B는 같은 외형·동작 품질에서 선택·빈도·발생 타이밍만 비교한다. B2/C2 화풍 비교와 다른 실험이며 화풍·동작 품질을 함께 바꾸지 않는다. 실제 사용을 막는 문제가 남으면 파일럿을 늦춘다. 모집·연락·결제·배포는 이번 문서 작업에 포함되지 않는다.

## 10. 현재 완료와 바로 다음 작업

완료는 B2/C2 비교 정본·세부 규격, 프로필 생성 설계, 이번 로드맵 문서다. r3의 6개 생성 결과는 화풍 미충족 상태로 보존한다. 제작기·저장·새 개체 재사용·사진 자동 추출·동작·앱 통합의 완료 실적은 아직 없다.

최초 계획의 첫 작업은 단계 0–1의 프로필 저장·버전·수정·복구 구현이었다. 현재 단계 2의 다음 작업은 문서 상단의 사진 1 서기 전신 실험을 따른다.
