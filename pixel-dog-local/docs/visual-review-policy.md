# 이미지 전달 전 리뷰 규칙

2026-11-05 ‘리뷰강화’ 지시로 시행. 기술적으로 구현됐다는 이유만으로 해결되지 않은 외형을 사용자에게 다시 판단시키던 실패를 막는다. AGENTS.md의 이미지 제작 규칙에 우선 연결되며, 과거 보고서의 ‘방법론만 PASS’는 전달 허가가 아니다.

## 판정과 책임

| 판정 | 담당 | 확인하는 것 |
|---|---|---|
| VISUAL | 제작하지 않은 새 외형 리뷰어 | 실제 참고자료와 최종 이미지의 구조·비율·실루엣·볼륨·부착부·표정 |
| TECHNICAL | 제작자 및 외형 리뷰어와 다른 기술 리뷰어 | 입력 근거·변경 격리·실행 경로·관절/표면·규격·재현성 |
| DELIVERY | 구현 담당자 | 두 검토가 동일 최종 파일을 대상으로 PASS인지, 미해결 차단사항과 거절 이력이 있는지 |
| USER | 사용자 | 최종 닮음·취향·선택. 내부 검토자가 승인했다고 만들지 않는다. |

각 검토는 `PASS / FAIL / NOT_REVIEWED` 중 하나다. 기술 PASS와 외형 FAIL을 평균하거나 ‘조건부 전달 PASS’로 합치지 않는다. 증거가 부족하면 NOT_REVIEWED이며 전달은 BLOCKED다. PASS는 명백한 결함을 걸러낸 **후보 전달 가능** 상태이지 사용자 승인이나 실측 해부학 정확도 보증이 아니다.

## 검토 순서

1. 구현자는 저장된 최종 파일을 직접 열어 요구사항과 대조한다. 명백한 실패는 리뷰어에게 개선 완료로 설명하지 않는다.
2. 외형 리뷰어는 새 에이전트에서 시작한다. 가능하면 `fork_turns="none"`을 사용한다. 사용자 요구, 승인된 특징, 이전 거절 사유, 실제 참고 파일, 최종 결과 경로·해시와 변경 범위만 제공한다. 제작자의 성공 설명·기술 PASS·이전 미감 판정은 첫 시각 판정 뒤 제공한다. 문맥이 이미 공유된 경우 완전한 비공개 판정이었다고 주장하지 않는다.
3. 외형 리뷰어는 골격선 없는 결과를 먼저 보고 독립 판정을 기록한다. 그다음 골격/비교 오버레이와 코드를 대조한다. 기술 리뷰는 병렬로 진행할 수 있다.
4. 발견 사항을 사용자 요구와 실제 결과에 대조해 수정한다. 의견 충돌은 근거로 해결할 때까지 차단한다. 최초 실패·수정 내용·재검토를 보존한다.
5. 최종 파일별 해시, 두 보고서, 검토 범위, 미해결 문제와 전달 상태를 기록한 뒤 전달 검사를 실행한다. 파일이 바뀌면 해당 검토는 무효다. 변하지 않은 기술 입력에 대한 검사 결과는 근거를 명시해 재사용할 수 있지만, 수정된 이미지의 직접 시각 확인은 생략하지 않는다. 문서만 바뀌면 무의미한 재렌더는 하지 않는다.

## 실제 파일과 참고자료

- 모든 전달 파일을 직접 열고, 비교판의 **모든 개체와 모든 행**을 확인한다. 대표 한 마리·한 표정의 통과를 나머지에 적용하지 않는다. 보고서에 파일 × 개체 × 시점/상태의 확인 범위와 누락을 남긴다.
- 머리–턱–목 수정은 골격선 없는 측면·정면·사선이 필수다. 귀 뿌리/뒤통수는 후면, 코·주둥이 폭은 윗면을 추가한다. 각 시점은 동일 형상의 실제 렌더여야 한다. 필요한 시점이 없으면 PASS를 내리지 않는다.
- 표정 변경은 기본·중간·최대 변경 상태를 비교한다. 입 벌림은 닫힘/중간/열림, 혀는 바닥 지지·두께·코 접촉을 확인한다. 여섯 표정 전체를 적용했다고 주장하면 여섯 상태 모두 검토한다. 중간 프레임이 없으면 연속 동작 검증을 주장하지 않는다.
- 전체 실루엣과 문제 부위 확대를 함께 본다. 확대의 목적은 구조 확인이며 최종 노출 크기의 가독성도 확인한다. 오버레이·음영·귀·털로 가려진 부착부는 별도 진단 시점이나 표면 보기로 확인한다.
- 실제 개 사진/골격 자료는 연결 관계와 특징의 근거이고, 승인 화풍은 데포르메 기준이다. 둘을 함께 비교한다. JSON 좌표·골격선·생성기 설명을 실제 동물 참고자료 대신 쓰지 않는다. 참고자료가 부족하면 확보하거나 해당 판단을 미검토로 남긴다. 정밀 치수·생물학적 정확도를 추정값으로 단정하지 않는다.

## 차단 기준

`BLOCKER`: 사용자 핵심 요구 실패, 반복 거절한 형태의 재발, 뚜렷한 부착 단절/관통/자기교차, 표정에서 구조 붕괴, 결과와 완료 주장 불일치. 후보 전달을 차단한다.

`MAJOR`: 정상 시점에서 보이는 심한 비율·볼륨·실루엣·연결부 문제, 필요한 검토 시점/참고 근거 누락, 일부 개체·표정 미검토. 후보 전달을 차단한다.

`MINOR`: 구조와 요청 충족을 해치지 않는 작은 표현 차이. 근거와 남은 항목을 적고 전달할 수 있다. 사용자가 이미 거절한 문제를 MINOR로 낮추지 않는다.

특히 다음은 ‘취향’으로 미루지 않는다.

- 코/주둥이의 깔때기·부리형 수렴, 코만 얹히거나 떨어져 보이는 접합.
- 얇은 주둥이 품종의 턱밑이 그릇처럼 부풀거나 턱이 목 중간에 붙는 형태.
- 뒤통수에 목이 판/막대처럼 따로 붙는 형태, 턱밑–목 앞의 큰 삼각형 면이나 비정상적으로 급한 꺾임.
- 귀 뿌리 위치 이탈, 종잇장 같은 부착, 구겨진 단면. 귀/털로 가려져 보이지 않는 연결을 정상으로 추정하는 것.
- 개방한 입을 얼굴 면이 메우거나, 아래턱이 관절과 분리되거나, 혀가 공중에 떠 보이는 상태.

데포르메는 허용된다. 그러나 승인된 단순화에서도 유지해야 할 연결·지지·볼륨이 무너진 결과까지 허용한다는 뜻은 아니다. 사용자가 특정 과장을 명시적으로 선택한 경우 그 요구를 기준으로 평가하고, 임의로 사진처럼 되돌리지 않는다.

## 보고서와 전달 기록

보고서에는 유일한 `<!-- review-verdict: {...} -->` 정형 표식을 둔다. 검토자 ID, 판정, 결과 해시 집합, 검토 범위 완료 여부, 미해결 문제 ID/심각도를 실제 본문과 일치시킨다. 기술 표식은 생성 코드·입력 해시도 포함한다. 전달 검사는 이 표식과 상태표를 직접 대조한다. 상태표의 PASS나 빈 findings만으로 보고서의 FAIL·미해결 문제를 덮을 수 없다. 판정 변경은 실질 재검토를 전제로 보고서·기록을 함께 갱신한다.

발견 사항마다 `파일/개체/시점/부위 → 직접 관찰 → 사용자 요구 또는 참고 근거 → 심각도 → 수정 후 확인 조건`을 기록한다. ‘자연스럽지 않다’만 쓰거나 미검사 항목을 PASS로 채우지 않는다. 코드 검사로 확인한 사실과 이미지에서 판단한 사실을 구분한다.

각 산출물 폴더의 `review-status.json`을 전달 판정의 권위로 삼는다. 입력/출력 생성용 recipe의 `USER_REVIEW_PENDING`은 이를 대체하지 않는다. 생성기는 이 파일이나 사용자 거절 이력을 덮어쓰지 않는다. 기록에는 이미지 경로/해시, 별도 리뷰어 ID와 보고서, 동일 파일 집합에 대한 판정, 확인 범위, 미해결 문제, 사용자 상태와 `delivery`를 포함한다.

실행: `python tools/review/check_delivery.py outputs/<candidate>/review-status.json`. 누락·오래된 해시·FAIL·NOT_REVIEWED·미해결 BLOCKER/MAJOR·사용자 거절이면 비정상 종료한다. 실제 보고서와 시각 검토를 대신하는 자동 미감 판정기는 아니다.

사용자가 거절하면 해당 해시의 `user_decision=REJECTED`, `delivery=BLOCKED`를 즉시 기록한다. 새 수정본은 다른 해시로 새 검토를 받으며, 거절된 파일의 상태를 검토대기로 되돌리지 않는다. 알려진 결함을 임의로 ‘범위 밖’으로 정해 재통과시키지 않는다. 사용자가 범위를 명시적으로 변경했을 때만 그 변경과 이유를 남긴다.

예외: 사용자가 실패안 열람·원인 진단·전후 비교를 **명시적으로 요청**하면 BLOCKED 자료를 진단용이라고 밝히고 보여줄 수 있다. 이를 수정 완료 후보·새 추천안·승인 요청으로 포장하지 않는다. ‘시안’, ‘초안’, ‘다시 진행’이라는 말만으로 이 예외를 적용하지 않는다.

전달 기록에는 `implementer`와 서로 다른 두 리뷰어 ID도 남긴다. 기술 보고서는 출력 이미지뿐 아니라 실제 생성에 사용한 코드·입력 파일의 경로와 해시를 연결한다. `inputs`와 `reviews.technical.inputs`는 같은 집합이어야 하며 전달 검사에서 현재 파일과 대조한다. 코드/입력이 바뀌면 이미지가 우연히 같아도 이전 기술 PASS를 자동 승계하지 않는다. 간접 의존성 검토 범위도 보고서에 명시하고, 필요한 입력 근거가 빠졌다면 미검토로 남긴다.
