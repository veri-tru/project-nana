# 로컬 개발 인수인계

## 최신 인계: 2026-11-02 프로필 기반 제작기 로드맵

사용자가 시안 의존을 지적한 뒤 로드맵을 요청해 [현재 계획](roadmap.md)을 갱신했다. 첫 구현은 지원 범위·출력 계약과 프로필 저장/수정/복구, 이어 정적 제작기다. 추가 2개체 재사용이 확인된 후 기본 동작, 사진 추출·사용자 3단계, Android 통합으로 확장한다. G0는 임시 자산으로 병행하며 표시 검증을 제작기의 선행 조건으로 묶지 않는다.

제작기는 부품·마스크·팔레트·동작 패키지와 버전이 고정된 개체 구조를 사용하는 제안이다. 사진/정본 없는 실행과 동일 픽셀 재현만으로 충분하지 않고, 실제 닮음·정본 미감·추가 개체 재사용을 함께 통과해야 한다. 제작 패키지를 만드는 초기 작화 비용과 개체별 보정 시간을 분리해 기록한다. 구현은 아직 없다.

이미지 모델 실험은 실제 정본 참조 규칙을 유지한다. 제작기 경로에서 정본은 개발·회귀 검수에 사용하며, 기준 자산은 임시 PNG뿐 아니라 검수된 개체 구조/패키지를 포함하도록 구분했다. 현재 미구현 상태에서 참조 이미지를 생략하는 예외가 아니다.

개발 1명+픽셀 제작 1명 기준 8–12주 배치안과 첫 10영업일 과제를 작성했다. 인력·속도·보호자·기기 확보 후 재산정한다. 이전 6주차 A/B 등은 [옛 계획](roadmap-20261019.md)으로 보존했고, 현재 행동 A/B는 필요한 개체/동작 검수 이후에만 진행한다. 기존 r3 결과는 미충족으로 유지한다. 이번에는 문서·설정만 변경했다.

## 최신 인계: 2026-11-02 B2·C2 정본 비교 r3

사용자 요청 “아까 비교테스트다시해보자”에 따라 B2/C2 각각 정책+프로필 1안과 화풍+사진 일반 조건 2안, 총 6개 독립 fresh run을 Sol 6.1/high로 실행했다. 같은 정본 원본·사진 4장·구도·공통 작화 계약을 전달하고 정책안에만 개체 프로필을 추가했다. 일반안도 화풍 계약을 받았으므로 스타일 지침 유무의 비교가 아니다. 이미지 도구 내부 모델·seed는 고정하지 않았다.

각 첫 결과 1장(1254×1254)을 수정 없이 보존했다. 도구 호출 횟수, 원본/보존본 해시, 요청문 해시, 참조 순서와 일반안 1/2 요청문 동일성을 확인했다. 부모가 6장을 직접 검수했다. B2의 유색 윤곽과 C2의 짙은 윤곽 차이는 나타나지만 모든 안에서 귀·주둥이·몸의 털과 명암이 과밀해 정본 화풍은 미충족이다. 일부 머리·귀·몸 비율이 달라 개체 유지는 부분 충족이고, 배경의 옅은 질감 때문에 형식도 부분 충족이다. 정책안의 안정적 우위는 확인되지 않았으며 작은 표본으로 효과를 확정하지 않는다.

로컬 기록: /workspace/nana-comparison-20261102-r3/README.md, comparison.html, 각 작업의 요청문·결과·생성 기록·검수와 parent-review.json. 이 경로는 실행 환경 전용으로 저장소만 복제하면 접근할 수 없다. 실제 사진·개체 프로필·개체 결과는 공개 Git에 올리지 않았다. 정본·프로필·release 승인 상태는 변경하지 않았으며 다음 제작은 털/명암 과밀과 비율 차이를 해결해야 한다.

## 최신 인계: 2026-11-02 B2·C2 비교 정본 v1.0

사용자가 B2 정본화를 요청한 뒤 C2도 비교 정본으로 포함하도록 지시했다. [세부 규격](b2-c2-style-spec.md)을 현재 작화 기준으로 사용한다. 정본은 [보존 원본](../references/styles/b2-c2/v1/reference-sheet.png)의 왼쪽 B2·오른쪽 C2이며 파일·해시·범위는 [manifest](../references/styles/b2-c2/v1/manifest.json)에 있다. 원본은 수정하지 않았다. 두 안 모두 비교 정본이고 제품의 최종 단일 선택은 미정이다.

공통 규격은 큰 색면·제한된 음영·털 생략·개체별 눈/눈꺼풀·앞털 가림·프레임 일관성이다. B2의 부드러운 유색선과 C2의 짙은 유색선을 별도 관리한다. 수치 규격은 96 기준 제작 기본값이며 최종 해상도나 실측 결과가 아니다. 과거 P1 점눈/크레용 지침은 B2/C2에 적용하지 않는다.

다음 제작은 동일 개체·털 길이·포즈·눈 형태로 얼굴/전신 B2와 C2를 비교하고, 닮음·화풍 검수를 거쳐 동일 동작으로 확장한다. 격자·팔레트·실제 표시 크기·8fps 검수와 앱 구현은 남아 있다. 이번에는 규격과 정본 보존을 수행했으며 새 개체 시안이나 동작 자산을 생성하지 않았다. 아래 인계는 당시 이력이며 “화풍 미정/임시 B2” 상태는 이 항목으로 갱신한다.

## 최신 인계: 2026-11-02 화풍 참조 분리 정책

이전 독립 비교에서 개체 사진과 텍스트 화풍만 전달해 실제 B/C 이미지가 누락됐고 털·명암의 단순화가 부족했다. 사용자 요청으로 [화풍 참조 분리 정책](style-reference-policy.md)을 추가했다. 모든 화풍 재현 작업은 실제 화풍 이미지의 역할·적용 영역·파일/해시를 기록해 도구에 전달하고, 개체 유지와 화풍 일치를 별도로 검수한다.

재시도는 같은 사진 4장과 같은 B2 화풍 이미지(비교표 왼쪽만)를 받는 fresh run 3개로 구성한다. 이전 회색/흰색 개체의 외형은 이식하지 않는다. Sol 6.1/high는 작업 에이전트 설정이며 이미지 모델 선택과 구분한다. 재실험 3개가 완료됐고 모두 실제 화풍 참조를 전달한 1회 생성 결과로 보존했다. B/C 공통 프롬프트 동일성 및 부모의 독립 이미지 확인을 마쳤다. 이전보다 단순해졌으나 세 안 모두 B2보다 내부 털·명암이 많아 목표 화풍은 미충족이다. 일부 머리·눈·몸 비율도 달라 보호자 닮음 검수가 남는다. 로컬 기록은 /workspace/nana-comparison-20261102-r2/README.md이며 이미지·개체 프로필은 공개 Git에 올리지 않았다. 이 로컬 경로는 실행 환경 전용으로 저장소만 복제해 접근할 수 있는 산출물 링크가 아니다. 최종 화풍·해상도·앱 구현 상태는 변경하지 않는다.

## 최신 인계: 2026-11-02 사용자 3단계·지속 프로필 설계

사용자 요청에 따라 [개체 프로필 기반 생성 설계](profile-generation-spec.md)를 작성했다. 사용자 화면은 사진 등록 → 털 선택·모습 보기 → 행동 설정·결과 확인이다. 외형 추출·근거 정리·선택 범위·검수는 내부 처리이며 기본 등록에서 부위별 필수 설문을 늘리지 않는다.

dog_id에 외형·행동·근거·표현 설정을 지속 보관하고 모든 생성은 고정된 프로필 revision과 기준 자산·제품 화풍 버전을 받는다. 부분 선택은 지정 범위만 적용한다. 새 사진·생성 결과가 확인된 프로필을 자동 덮어쓰지 않는다. 수정이 영향을 주는 자산을 재검수하고, 같은 개체·프로필에 유효한 자산 묶음을 한 번에 사용 대상으로 전환하는 설계다.

초안 저장·재접속, 생성 실패·오래된 결과·동시 수정, 부분 수정 전파, 삭제 후 응답 차단까지 14개 구현 검증 시나리오를 명시했다. 시나리오는 설계이며 테스트 실행·앱·저장·생성 엔진 구현 완료가 아니다. config/project.json은 설계 계약만 대응시켰다.

다음 구현은 G1의 개체 ID·근거·프로필 스냅샷·선택 범위 저장부터 진행한다. 이어 3단계 UI, 정적 생성의 필수 프로필 참조, 동작 확장·일관성 검사·자산 묶음 전환을 연결한다. G0 표시·입력·종료 검증 범위와 최종 화풍·해상도 미정 상태는 유지한다.

## 최신 인계: 2026-11-02 눈꺼풀 선택 범위와 개체별 눈 표현 정정

사용자는 대화의 5안 비교표에서 윗줄 가운데 ‘2번’을 골랐으나, 이는 눈꺼풀·눈 주변 털 겹침만 참고한 선택이라고 정정했다. 얼굴 전체나 B 화풍 승인이 아니다. 이어 눈꺼풀이 개마다 다름을 지적하고 개체별 적용 원칙을 기록하도록 요청했다.

공통으로 적용할 것은 픽셀·선·색·명암의 표현 방식이다. 눈 크기·간격·기울기·노출 형태와 눈꺼풀은 개체별로, 눈 주변 털의 길이·방향·가림은 별도로 관리한다. 가려진 눈꺼풀은 미확인으로 두고 털 경계를 표정으로 자동 해석하지 않는다. [개인화 설계](personalization-spec.md)와 [결정 기록](decisions.md)에 반영했다.

B·C 화풍은 비교 후보다. 갈색 눈·옅은 반짝임은 이번 시안의 표현 후보이지 모든 개의 실제 눈 색 기준이 아니다. 선택을 얼굴 전체 승인으로 오해해 만든 후속 전신·동작 시안은 확정 기준에서 제외한다. 이번 기록은 이미지 파일 업로드·실제 레이어 분리·최종 자산 승인이나 8fps 검증 완료를 뜻하지 않는다.

다음 제작에서는 개체 사진에서 보이는 눈매를 먼저 확인하고, 선택한 털 길이에 따른 가림을 적용한 뒤 닮음을 검토한다. 실제 부위별 레이어·포즈·깜박임 호환 검수는 남아 있다. 아래 이전 인계는 당시 이력으로 보존한다.

사용자가 털 단순화 픽셀 A안을 후속 제작 기준으로 선택하고 부분적인 두들풍 데포르메 시안 3개를 요청했다. ## 최신 인계: 2026-11-02 픽셀 화풍 비교

사용자가 디자인 방향은 여전히 픽셀과 고민 중이라고 정정했다. 크레용풍의 점눈·약한 외곽선 A 선택은 해당 후보 안의 선택이며 전체 화풍 확정이 아니다. 새 픽셀 레퍼런스 2장과 기존 개체 사진으로 [화풍 3안](../outputs/pixel-style-references-20261102/README.md)을 제작하고, ‘털표현은 좀더 단순화할필요있음’ 피드백에 따라 A/B/C 모두 잔털·명암 조각을 줄였다. 최신 파일은 *-simple.png이며 이전안·프롬프트를 보존했다. 모두 사용자 검토 대기다. 앱·동작 자산에는 적용하지 않았고 최종 저해상도 격자·표시 크기·애니메이션은 미검증이다.

## 최신 인계: 2026-11-01 정책 v1.0 + 세 장면 후보

- 기획·자료 위계·문헌·시장·경쟁사·벤치마크·GitHub 조사 10개를 로컬 Markdown으로 옮겼습니다.
- 원본 문서의 블록·링크·시퀀스를 JSON으로 보존했습니다.

## 아직 없는 것

실행 가능한 Android/iOS 앱, Gradle/Xcode 프로젝트, 분석 서버, API 연결, 실제 개체용 스프라이트, 완성된 행동 엔진, 앱 배포와 실기기 테스트 결과는 없습니다. 기존 HTML은 비교 시안입니다.

## 다음 작업

[세부 로드맵](roadmap.md)의 R0에서 실제 역할·투입 시간, 첫 개체 자료와 기기를 확인합니다. 개발은 G0부터 진행하고 외형·질문 준비는 병행할 수 있습니다. 첫 개체 제작 시간을 측정해 3~6주차를 다시 산정합니다. 주차·표본은 확정 일정으로 취급하지 않습니다.

개인화 설계는 개체 외형 설정 → 부품·동작 호환표 작성 → 한 마리의 특징과 닮음 검수 순으로 구체화합니다. 우선 실제 개체에서 확인한 외형 특징을 최대 3개 고르고, 해당 자산의 방향·해상도·포즈를 검수합니다. 다음으로 짧고 긴 체형·넓은 체형의 재사용 범위를 확인합니다. 현재 공통 사양과 미결정 항목은 [현재 사양](current-spec.md)을 봅니다. G0의 표시·입력·종료 구현 순서는 유지합니다.

행동 개인화에는 몸 털기·기지개를 각각 포함하고, 앉기·눕기도 자세 자체의 변형을 검토합니다. 사진은 몸통·앞발·머리의 보이는 형태에, 보호자 응답은 자주 취하는 자세와 빈도·순서에 사용합니다. 구체 자세 자산과 연결 규칙은 아직 미제작입니다.

추가 사용자 제안은 입 벌림·헥헥거림·두 발로 서기와 특정 상황에서 한쪽 앞발 들고 있기입니다. 입 벌린 정적 사진만으로 헥헥거리는 리듬을 추정하지 않고, 앞발을 들고 유지하는 동작과 건드리는 동작을 구분합니다. 두 발로 스스로 서기와 앞발을 물체에 얹고 서기도 구분합니다.

중간점검에는 사용자 요청에 따라 행동 개인화 A/B 테스트를 진행합니다. 같은 외형에서 공통 기본 행동과 응답에 맞춘 행동을 비교할 수 있는 시제품이 준비되면 실행합니다. 현재는 계획만 기록했으며 날짜는 미정입니다. 영상 제출을 필수로 요구하지 않는 입력 방식을 우선 검토하고, [실행안](decisions.md#2026년-10월-17일-행동-개인화와-중간점검-ab-테스트)에 따라 자기 개다움과 입력 부담을 확인합니다. 기존 니즈 조사의 영상 제출 과제는 이 방향에 맞춰 조정합니다.

[시작 프롬프트](../prompts/start-local.md)를 사용해 아래 순서로 진행합니다.

1. 프로젝트 루트를 연 뒤 로컬 OS, Git, JDK, Android SDK, Android Studio와 테스트 기기 연결 상태를 확인합니다. 비밀 값은 출력하지 않습니다.
2. 설치된 도구에 맞는 공식 지원 조합으로 Android G0 프로젝트를 생성하고 버전을 기록합니다. 현재 패키지에는 최신 버전을 임의로 고정하지 않았습니다.
3. 앱 안에서 임시 자산의 8fps 재생과 상태 전환을 구현합니다. 원본 크기와 표시 크기를 설정값으로 분리합니다.
4. Android의 작은 오버레이, 권한 안내, 켜기·끄기, 탭·드래그를 연결합니다. 서비스 방식은 현재 공식 OS 요건을 확인합니다.
5. 실제 기기에서 종료·터치·표시 제약을 확인하고 [기기 기록 양식](../templates/device-check.md)에 남깁니다.

## 개발 위치

앱 구현은 필요할 때 `apps/android`에 생성합니다. 공통 자산·프로필 형식은 특정 엔진에 종속시키지 않습니다. iOS·서버 폴더는 해당 단계에서 만듭니다. 폴더 이름만으로 구현이 완료됐다고 표시하지 않습니다.

## Git 시작

압축에는 Git 이력이나 원격 저장소 연결이 없습니다. 새 저장소로 관리할 때는 루트의 `.gitignore`를 확인한 뒤 `git init`으로 시작할 수 있습니다. 이미 관리 중인 저장소로 옮기면 기존 이력을 유지합니다. 이 패키지는 원격 저장소를 만들거나 공개하지 않았습니다.

## 우선순위

G0에서 표시·입력·종료가 성립하는지 먼저 확인합니다. G1의 AI·수집·개인화와 M0의 고객 검증은 별도 작업으로 이어갑니다. 64/96px와 제작 도구 선택은 시안 비교 후 결정하되, 해상도를 교체할 수 있도록 구현합니다.

M0에서는 두 연령 집단에 동일한 외형·행동·가격 비교 과제를 적용합니다. 공개 리뷰의 추모 이용자 요구를 현재 양육자에게 그대로 일반화하지 않습니다. 니즈 조사에서 제안한 기능은 개발 승인이나 G0 범위 확장을 뜻하지 않습니다.
