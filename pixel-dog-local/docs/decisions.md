## 2026년 11월 3일 공통 제작 부품과 리뷰 범위

개체 사진에서 확인한 형태를 외형표 항목과 대조해 명세를 작성하고, 명세로 공통 부품을 구동한다. 나나 전용 그림에 좌표를 반복 수정하는 방식은 도구의 공통 계약으로 삼지 않는다. 첫 검증 항목은 주둥이 폭과 코끝 돌출의 분리다. 같은 기준안에서 작은 파라미터 차이 세 개를 병렬 생성한다. 모든 생성 이미지에 대한 동일 모델의 적대적 검토는 계속하되, 권한은 자료 출처·생성 조건·규칙 및 방법론 검증에 한정한다. 닮음·미감 및 후보 선택은 보호자 판단이다. 이전 기록의 미감 판정은 당시 평가 이력으로만 읽는다.

외곽선은 한 색을 쓰고 내부 전체를 최대 네 색으로 그린다. 움직임과 외형을 읽는 데 필요한 전신 구조는 음영 또는 윤곽으로 구분하며, 빛이 상대적으로 적게 닿는 면을 어둡게 표현한다. 나나의 눈동자는 홍채를 생략한 작은 원형으로 정했다. 첫 적용 대상은 76×76·96×96 서기 비교본이다.

## 2026년 11월 2일 거절 이후 얼굴 재작업과 검토 방식 보완

사용자 “다시 문제 보완해서 업무개시”에 따라 얼굴 P0를 재개했다. 이전 후보를 승인 자산으로 삼지 않고 실제 사진과 B2/C2 정본을 다시 대조했다. 짙은 눈과 좁은 홍채, 닫히지 않은 눈 주변 색면, 넓은 귀 시작점, 줄인 정수리·턱과 코, 좌우로 분리한 주둥이 접촉 음영을 새 네이티브 작화 데이터로 보존한다. 기존 관찰 프로필과 제작 revision을 덮어쓰지 않는다.

비교에서는 캔버스 크기가 같아도 머리 점유율이 다르면 개선 평가가 왜곡될 수 있다. 앞으로 머리 표시 영역을 같은 폭으로 맞춘 보기와 원본 격자 보기를 분리한다. 표시 영역은 수동 근사값이며 사진의 해부학적 실측이나 최종 제품 해상도 확정으로 사용하지 않는다. 재사용 가능한 읽기 전용 비교 생성기를 추가했다.

새 후보의 기술 검사는 통과했으나, 이마·볼과 귀 흐름의 도식성이 남아 P0 시각 통과는 선언하지 않았다. 사용자의 이전 거절은 유지하고 새 후보는 별도로 미검수 상태로 둔다. 고해상도 추가 생성 1회는 강한 눈 주변 색면과 밝은 홍채가 남아 채택하지 않았다. 생성 횟수나 상대적 개선을 근거로 P1·몸 연결에 자동 진입하지 않는다.

## 2026년 11월 2일 P0 작화 검수와 사용자 거절 반영

사용자가 Astra max에 화풍·개성화 검토를 요청하고 “권장순 연속진행”을 지시했다. 얼굴의 실제 면/가림 작화 검증부터 시작했으며, 새 native96 후보에 대한 Astra의 조건부 패키지 실험 권고 뒤 사용자가 “기괴해졌는데”라고 거절했다.

이번 후보는 탈락 처리한다. 이전보다 면이 분리되고 기술 검사가 통과했다는 사실로 자연스러움·개체 닮음 통과를 대신할 수 없다. P0가 해결되기 전 P1 패키지 변환과 몸 연결을 진행하지 않는다. 내부 AI 평가를 사용자 수락으로 승격하지 않으며 앞선 조건부 진입 의견은 원문을 보존한 채 사용자 거절로 대체한다.

원본의 짙은 눈·눈–코–귀 관계를 복구하고 눈 주변의 가면 모양, 주둥이/턱의 연결된 수염띠를 제거하는 방향으로 재작업한다. 후속 고해상도 수정 참고안은 네이티브 자산이 아니고 정본보다 세부 명암이 많아 채택하지 않았다. 공통 B2/C2 작화 기준, 실제 개체 프로필, 사용자 3단계와 해상도 미정 상태는 바뀌지 않는다.

- 검증: 사진/정본에 접근할 수 없는 출력 실행, 같은 입력의 픽셀 재현, 개체별 수정·가림·동작 일관성, 다른 개체 재사용과 시각적 닮음을 함께 확인한다.
- [현재 로드맵](roadmap.md)에 단계·완료 기준·첫 10영업일·실패 시 조정·기존 R0–R7 연결을 기록했다. [2026-10-19 계획](roadmap-20261019.md)은 이력으로 보존했다.
- 기존 B2/C2 비교 정본, 개체별 눈꺼풀·외형·행동, 사용자 3단계, G0·8fps는 유지한다. 최종 해상도·단일 화풍·공급자·배포 위치는 이번에 확정하지 않았다.
- 이번 완료 범위는 계획·정책 연결이다. 앱·제작기·사진 분석·동작 자산 구현이나 공개 배포는 수행하지 않았다.

## 2026년 11월 2일 B2·C2 비교 정본 지정과 세부 규격

- 사용자 지시: “b2를 정본으로 세부규격작성”, 이어 “c2도 함께 비교로 정본화하자.”
- 이전: B2는 재실험용 임시 화풍 참조였으며 B/C 전체 화풍은 미선정.
- 현재: 같은 비교 이미지의 왼쪽 B2와 오른쪽 C2를 각각 비교 정본으로 승인. 제품에 적용할 단일 화풍은 아직 미선택.
- [세부 규격 v1.0](b2-c2-style-spec.md): 공통 픽셀·색면·명암·털 생략·눈/털 가림·전신/동작 확장·검수 기준과 B2/C2의 윤곽 대비 차이를 분리했다.
- [원본·manifest](../references/styles/b2-c2/v1/manifest.json)에 수정 없는 생성 이미지, 적용 영역, SHA-256, style ID/version과 승인 범위를 보존했다. 실제 사용자 사진·프로필은 포함하지 않는다.
- 정본의 얼굴형·눈꺼풀·귀·회백색 무늬는 모든 개에게 공통 적용하지 않는다. 과거 ‘2번’ 눈꺼풀 선택 범위는 그대로다.
- 96 기준 선 두께·색 수·털 덩어리 등 수치는 제작 기본값이며 정본 실측값이 아니다. 최종 해상도·표시 크기·실행 자산·앱 구현은 미확정/미완료 상태를 유지한다.
- 이전 재시도 결과를 소급 승인하지 않는다. 두 정본의 신규 개체 적용 결과와 프레임은 각각 검수해야 한다.
- 아래 날짜별 기록의 “임시 B2/화풍 미선정/P1”은 당시 이력이다. 현재 화풍 승인 범위는 이 항목을 우선한다.

## 2026년 11월 2일 화풍 참조 전달 정책 정비와 재시도

- 사용자 지시: 이전 비교 시안이 화풍을 따르지 않은 원인 설명 후 “정책정비하고 재시도”.
- 확인된 절차 문제: 이전 세 작업은 개체 사진 4장과 텍스트 화풍 지시만 받았으며 실제 B/C 화풍 이미지는 전달하지 않았다. 세 결과 모두 털·명암이 목표보다 세밀했다. 이미지 모델 내부 원인을 확정한 것은 아니다.
- 개선: 실제 화풍 이미지와 개체 사진의 역할·순서·적용 영역을 구분해 도구에 전달한다. 스타일의 얼굴·귀·눈꺼풀·무늬를 개체 특징으로 가져오지 않는다. 구체적인 색면·음영·털 생략 규칙과 개체/화풍 별도 검수를 필수로 한다.
- [화풍 참조 분리 정책](style-reference-policy.md)을 작성하고 개발 지침·생성/자산 규격·설정에 연결했다.
- 재시도 조건: 이전의 요청을 이어 세 개의 fresh run을 Sol 6.1/high로 병렬 배정한다. 동일한 사진 4장과 B2/C2 비교표의 왼쪽 B2 화풍 이미지를 제공하고 정책 적용 1안·일반 독립 2안을 비교한다. B2는 실험용 화풍이며 최종 제품 선택이 아니다.
- 생성·결과 검수 기록은 로컬 실험 폴더에 보존하며 사진·개체 프로필을 공개 Git에 올리지 않는다. 정책 반영과 이미지의 완전 준수는 구분한다.

## 2026년 11월 2일 사용자 3단계와 개체 프로필 기반 생성 설계

- 사용자 지시: 사용자는 사진 제공·표현할 털 선택·행동 설정/결과 확인 정도만 수행하며, 외형과 동작은 프로필로 저장되어 항상 해당 개체를 따라다녀야 한다. 이어 설계 보완을 요청했다.
- 사용자 과정은 3단계로 줄인다. 외형 속성 추출·근거 정리·프로필 구성·동작 호환 검사는 내부 처리다. 추가 질문·수정은 필요한 경우 해당 화면에 포함하고 화풍·눈꺼풀·레이어 선택을 필수 입력으로 만들지 않는다.
- dog_id 아래 외형·행동·근거·표현 설정을 보관한다. 모든 개체 생성은 변경되지 않는 프로필 스냅샷과 정확한 기준 자산·화풍 버전을 참조한다. 생성 이미지가 개체 사실을 덮어쓰지 않는다.
- 부분 선택 범위를 저장한다. “2번 눈꺼풀”은 얼굴 전체·귀·체형·B/C 화풍 승인으로 확대하지 않는다. 외형 결과 수락과 가려진 실제 특징의 확인은 별도다.
- 구현 설계안: 초안과 사용 중인 자산 묶음을 분리하고, 수정 영향을 추적하여 검수된 묶음 단위로 전환한다. 동시 수정·오래된 생성 응답·실패·되돌리기·삭제를 처리한다.
- 산출물: [개체 프로필 기반 생성 설계](profile-generation-spec.md), 개인화·현재 사양·자산 규격, 설계 설정, 작업 목록·인계.
- 설계 반영이며 앱·프로필 저장·생성 파이프라인·검증 시나리오 실행은 미구현이다. B/C·최종 해상도·공급자·DB는 이번에 선정하지 않았다. G0 표시 검증과 조사 DB·원문 보존 범위는 유지한다.

## 2026년 11월 2일 눈꺼풀 선택 범위 정정과 개체별 눈 표현

- 사용자 정정: “애초에 해당선택지는 눈 커풀만본거였어”, “눈커풀은 그런데 강아지들마다 너무상이해서”. 이어 개체별 적용 원칙의 기록을 요청했다.
- 여기서 ‘2번’은 대화에서 사용자가 다시 첨부한 5안 비교표의 윗줄 가운데 후보다. 눈꺼풀·눈 주변 털의 겹침 표현만 참고한 선택이며 얼굴 전체·귀·주둥이·체형이나 B 화풍 전체의 승인이 아니다. 다른 비교표의 2번과 혼동하지 않는다.
- 특정 후보의 눈꺼풀 형태를 모든 개에게 공통 적용하지 않는다. 눈의 크기·간격·기울기·노출 형태와 눈꺼풀은 개체 근거로 정하고, 눈 주변 털의 길이·방향·가림은 별도 속성으로 관리한다.
- 공통화 대상은 픽셀 표현, 선·색·명암을 단순화하는 방식이다. 개체별 눈매·외형은 공통 템플릿으로 덮어쓰지 않는다.
- 사진에서 털에 가려진 눈꺼풀은 미확인으로 유지한다. 눈 주변 털 경계를 눈꺼풀·눈썹 또는 감정 표현으로 자동 해석하지 않는다.
- 이번 비교의 눈 표현 후보는 단순화한 갈색 홍채·어두운 동공·옅은 반짝임이며 B·C 화풍은 비교 상태다. 모든 개의 실제 눈 색이나 최종 화풍·해상도·자산을 확정한 것이 아니다.
- 선택을 얼굴 전체 승인으로 오해하여 만든 후속 전신·동작 시안은 확정 기준에서 제외한다. 이번 정정은 기록이며 실제 레이어 분리·애니메이션 검수 완료가 아니다.
- 적용 문서: personalization-spec.md, handoff.md, backlog.md. 기존 조사 원문·DB·출처 스냅샷은 유지한다.

## 2026년 10월 17일 행동 개인화와 중간점검 A/B 테스트

- 사용자 방향: 행동 개인화를 차별화 요소로 유지하고, 미리 준비한 행동 요소를 보호자 응답과 사진에 맞추는 방식을 검토합니다. 영상 제출 부담을 줄이는 것이 우선입니다.
- 사용자 결정: 중간점검 때 A/B 테스트를 진행합니다. 현재는 계획 기록이며 테스트는 미실시입니다.
- 실행 시점 제안: 동일 외형으로 기본 행동과 응답 기반 개인화 행동을 모두 재생할 수 있는 비교물이 준비된 중간점검입니다. 날짜는 미정이며 G0 구현 범위를 확대하지 않습니다.
- A안은 공통 기본 행동, B안은 보호자 응답에 따라 동작·속도·빈도·순서를 맞춘 행동입니다. 외형·화풍·표시 크기·재생 시간·동작 자산의 품질은 같게 유지합니다.
- 개인화 여부를 먼저 알리지 않고 제시 순서를 교차 배정합니다. 같은 보호자가 두 안을 보는 탐색 비교로 시작하며, 차이 없음·둘 다 닮지 않음도 선택할 수 있게 합니다.
- 핵심 평가는 어느 쪽이 더 자기 강아지다운지와 그렇게 느낀 구체적 이유입니다. 귀여움·자연스러움·계속 사용 의향은 별도로 기록하고, 응답 시간·수정 횟수도 확인합니다.
- 사진은 외형과 직접 보이는 자세에, 응답은 습관·반응에 사용합니다. 사진 한 장으로 성격이나 행동 빈도를 확정하지 않고, 보호자 보고와 직접 관찰 근거를 구분합니다. 첫 비교에 영상 제출은 필수로 요구하지 않는 안입니다.
- 20대·30대 여성에게 동일 과제를 적용합니다. 표본 수·정량 통과 기준은 실행 전에 정하고, 소수 탐색 결과를 통계적 우위나 실제 구매로 해석하지 않습니다.
- 결과는 행동 개인화를 없앨지 결정하는 근거보다, 어떤 행동 요소와 입력 방식이 개체의 특징을 잘 전달하는지 개선하는 데 우선 사용합니다.

## 혼동을 피할 사항

- 8fps는 프레임 표시 속도입니다. 모든 동작을 8장으로 만들라는 뜻은 아닙니다.
- 96×96 시안은 일반화한 강아지 그림으로 만든 비교 자료입니다. 실제 개체의 외형·습관이나 최종 화풍이 승인된 자산은 아닙니다.
- 이전 문서의 일반 2D 일러스트·레이어 설명은 제작 방식의 참고로 유지합니다. 픽셀화에 맞는 결과물 규격은 [자산 초안](asset-spec.md)에서 관리합니다.
- Jev 문서는 과거 대안 검토입니다. 현재 구현의 의존성 목록으로 해석하지 않습니다.
- 기존 문서의 공급자 가격·모델 스펙·OS 정책은 당시 조사 기록입니다. 이 패키지 제작 과정에서 재검증한 최신 API 계약이 아닙니다.

## 2026년 11월 6일 체급·품종·개체 계층과 골든 native64

사용자 지시 “소형 중형 대형별 차이”, “해당 구조도 엔진에 반영”, “골든은 픽셀 다시”에 따라 [머리 엔진](../tools/head_engine/README.md)에 계층 해석과 실제 렌더 소비 경로를 추가했다. 체급은 제작 상대배율, 품종은 검토된 골격/외피 프리셋, 개체는 근거를 기록한 같은 품종의 프리셋과 상대배율 보정으로 구분한다. 체급만으로 얼굴형을 정하거나 제작 배율을 실측값으로 표시하지 않는다. normalized는 비율 비교, relative는 같은 제작 단위의 크기 비교이며 캔버스 초과는 오류로 처리한다.

골든의 수정 B는 작업 기본값이며 사용자 선택을 대신하지 않는다. [새 픽셀 후보](../outputs/golden-pixel-refresh-20261106/README.md)는 실제 저장 메시를 64×64 깊이 버퍼에 투영하고 코/눈의 가독성을 격자 안에서 보정했다. P1/P2는 음영 차이, P3는 P2의 윤곽색 차이다. 지원 범위는 머리/짧은 목이고 전신 엔진, 학습, 행동, 실기기 완료로 확대하지 않는다. 기존 저장 모델과 검토 기록은 변경하지 않았다.

## 2026년 11월 6일 기존 B2 품종 시안의 화풍 정본화

사용자가 골든 재출력의 음영·픽셀이 다른 개체와 다르다고 지적한 뒤 “기존 시안으로 정본화하고 다시만들어”라고 지시했다. 직전 비교에 사용한 B2 / SOFT PIXEL 품종 보드를 현재 머리 화풍 정본으로 복사·해시 고정했다. style ID는 `breed-head-soft-B2-v1`이다. 기존 B2/C2 기록을 덮지 않고 새 manifest를 권위로 연결한다. C2는 비교 이력으로 남긴다.

골든의 수정 adult-B 형상은 작업 기준으로 유지하고, 픽셀 밀도·윤곽·눈·음영을 기존 품종 시안에 맞춘다. 화풍 선택을 골든 정본 속 과거 형상 승인으로 해석하지 않는다. 이전 native64 P1/P2/P3는 REJECTED/BLOCKED이며 당시 독립 PASS는 화풍 불일치를 해소하지 못한 과거 판정으로 보존한다. 계층형 엔진과 모델 코드는 변경하지 않는다.

이번 재작화는 실제 B2 이미지를 입력으로 쓰는 built-in image_gen 고해상도 시안이다. native64·정확한 메시 투영·5색 제한·정수 픽셀 확대 검증 결과로 주장하지 않는다. 실제 실행 자산의 화풍 일치 작업은 별도다. 새 그림의 사용자 선택과 정본 화풍 선택은 구분한다.
