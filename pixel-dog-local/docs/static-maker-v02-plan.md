# 한 개체 정적 제작기 0.2 보완 기획

기준일: 2026-11-02. 현재 상태: 0.2 기술 구현·검증 완료, 시각 검수 부분 충족/보호자 대기.
사용자 요청: “보완안 기획”.
대상: [정적 제작기 0.1](../tools/static_maker/README-v01.md), 구현 커밋 feb966c4f91c8f75a74bc4f87643edb2697f7fee.
최초 문서는 수정의 범위와 완료 기준을 정의한 계획이었다. 후속 사용자 “지금진행”에 따라 P0–P2 구현과 자동 검사 14개·실제 브라우저·재현 검증을 실행했다. [실행 안내](../tools/static_maker/README.md)와 [V01–V10 실제 판정](../tools/static_maker/VERIFY-v02.md)을 우선한다. 자연스러운 형상·정본 미감·닮음·실기기 표시의 미완료 조건을 기술 통과로 대체하지 않는다.

## 1. 이번 목표

**한 개체의 정면 얼굴·앉은 전신이 자연스럽게 연결되고, 해당 개체의 특징과 B2/C2 작화 기준을 유지하도록 제작 구조를 보완한다.**

프로필 저장·revision·되돌리기·동일 입력 재출력은 유지한다. 96×96 제작 후보에서 한 개체를 먼저 다듬으며 최종 제품 해상도를 확정하지 않는다. 동작·다른 방향·자동 사진 추출·새 개체 지원 확대는 이번 범위에 넣지 않는다. B2/C2는 모두 비교 정본이고 최종 단일 선택은 미정이다.

정본 이미지는 패키지를 제작·검수하는 기준으로 보존한다. 개체별 실행은 프로필과 버전이 고정된 제작 패키지만 받는다. 개선 결과를 매번 다음 생성의 이미지 입력으로 이어 붙이지 않는다.

## 2. 확인된 문제와 원인

현재 출력과 maker.py를 함께 검토했다. 미감에 대한 아래 평가는 제작자의 관찰이며 보호자 평가와 구분한다.

| 우선순위 | 현재 문제 | 확인한 구조 | 수정 방향 |
| --- | --- | --- | --- |
| P0 | 머리·목줄·가슴 사이에 끊김이 생기고 부품이 붙어 있는 인상 | 머리는 head_height에 반응하지만 목줄은 고정 y=44–49, 가슴은 다른 좌표식 | 턱·목·가슴 연결점을 공유하고 목줄을 목 영역에 종속 |
| P0 | 앞다리가 긴 사각 부품처럼 읽힘 | 각 다리에 닫힌 외곽선을 그리고 제한된 가슴 덮음으로 연결 | 가슴에서 발까지 흐르는 형상, 필요한 겹침 경계만 남김 |

| P1 | 털 선택이 정수리만 바꿈 | coat_length가 crown의 tuft 값만 변경 | 지원 부위별 털 실루엣과 가림을 함께 갱신 |

| P1 | 범위 안 입력도 조합에 따라 잘못된 그림 가능 | 개별 정수 범위 검증 중심, 부위 관계 검증 부족 | 연결·겹침·화면 경계·필수 특징 노출 검증 |
| P2 | 수정하려면 JSON 편집이 필요함 | 출력 HTML은 읽기 전용 | 내부 제작자용 조절·마스크 확인 화면 제공 |

현재 원형 눈이나 고정된 귀를 새로운 공통 스타일로 승인하지 않는다. “화풍이 단순하다”는 이유로 개체의 눈매·얼굴형까지 통일하지 않는다.

## 3. 제작 구조 개편

### A. 관찰 프로필과 제작 상태 구분

기존 프로필의 실제 관찰·보호자 보고·미확인을 보존한다. 픽셀 치수·좌표·마스크 선택은 그 근거를 참고한 **제작 상태**로 별도 버전 관리한다.

제작 상태에는 기준 profile_revision, shape_package_id/version/hash, style_package_id/version/hash, 관절/부위 연결점, 얼굴 제어값, 털 설정, 지원 방향·포즈·격자, 제작 기본값과 수정 이유를 기록한다. 형상을 고쳤다는 이유로 관찰된 개체 사실을 덮어쓰지 않는다.

v0.1의 화면 좌우와 향후 해부학적 좌우는 구분한다. 이번 정면 범위는 screen_left/screen_right로 명시하고 향후 방향 확장 때 매핑을 추가한다. 현재 값을 해부학적 좌우로 자동 재해석하지 않는다.

### B. 연결점을 공유하는 형상

- 좌표는 body_root, ground, neck_base, chin, ear_attach, eye_center, muzzle_center, foot_contact, tail_root 등 의미 있는 연결점에서 계산한다.
- 귀 길이는 귀 부착점에서, 눈은 얼굴 기준계에서, 목줄은 목의 형상·폭에서 계산한다.
- 얼굴 크기 변경 시 머리 아래·목줄·가슴의 연결이 같이 움직여야 한다. 목줄을 꺼도 실제 목/가슴 실루엣이 이어져야 한다.
- 얼굴 보기와 전신 보기는 같은 제작 상태를 사용한다. 얼굴 전용으로 다른 눈·코 배치를 저장하지 않는다. 최종 픽셀 스냅 때문에 생기는 차이는 기록한다.
- 정규화된 부위 좌표로 관계를 계산한 뒤, 출력 격자에 한 번 스냅한다. 64 지원은 별도 검수 전 제공하지 않는다.

### C. 개체별 얼굴 표현

| 항목 | 제어할 값 | 유지 조건 |
| --- | --- | --- |
| 얼굴·볼 | 폭/높이, 아래 얼굴 폭, 볼의 큰 굴곡 | 귀를 포함한 전체 얼굴 폭과 구분 |
| 귀 | 부착점, 길이, 폭, 끝의 둥글기, 전면 겹침 | 크림색 개체의 긴 귀 등 개체 근거 보존 |
| 눈 | 가로/세로 노출, 간격, 높이, 좌우 미세 차이 | 모든 개체를 같은 원형 눈으로 대체하지 않음 |
| 눈꺼풀 | 상하 노출 경계·가림 | 가려진 실제 경계는 미확인, 제작 기본값으로 구분 |
| 앞털 | 눈 위/옆의 큰 털 마스크 | 눈썹·표정선으로 오인되는 선을 추가하지 않음 |
| 코·주둥이 | 코 폭/높이/위치, 주둥이 폭/높이/중심 | 눈과 주둥이의 겹침을 제약하고 코를 고정된 검은 도형으로 통일하지 않음 |
| 입 | 닫힌 입의 위치·최소 연결선 | 임의의 웃음·슬픔 표현을 기본값으로 강제하지 않음 |

홍채·동공·반짝임은 눈 노출 마스크 안에 들어가고 눈꺼풀·앞털에 가려져야 한다. 반짝임은 기존 정본 규격의 작고 옅은 한 덩어리 범위를 유지한다. 미세 좌표 옵션을 보호자 필수 입력으로 노출하지 않는다.

### D. 털과 윤곽을 작화 패키지로 구성

부위 형상을 maker.py의 고정 좌표에서 버전 있는 패키지 정의로 옮긴다. 다만 좌표를 JSON으로 옮기는 것만으로 완성하지 않는다. 픽셀 작화자가 큰 실루엣·겹침·색면을 다듬고 실제 출력 크기에서 검수해야 한다.

- 첫 지원 부위: 정수리, 귀 끝, 볼/턱, 가슴, 발 둘레. 꼬리는 현재 자세의 큰 덩어리를 유지하며 별도 형태 확장은 보류한다.
- 털 옵션은 지원 부위 묶음으로 정의한다. 실제 털 관찰과 표시 선호를 분리하고, 아직 제작하지 않은 길이는 선택 목록에서 제외한다.
- 눈 가림에 영향을 주는 털 변경만 해당 마스크를 갱신한다. 털 길이를 바꿔 눈 간격·귀 부착점·다리 골격을 움직이지 않는다.
- 외곽선은 최종 실루엣과 필요한 겹침 경계에서 만든다. 모든 부품 둘레를 닫힌 선으로 노출하지 않는다.
- 외곽선·귀/다리 겹침선·눈/코/입의 핵심색을 분리한다. B2는 부드러운 유색 경계, C2는 더 짙은 경계를 적용하되 같은 개체 형상과 털 구조를 사용한다.
- 기본색+음영의 넓은 면을 유지한다. 줄무늬 같은 귀 내부선, 가슴의 반복 컬, 작은 명암 조각을 추가해 부품 연결 오류를 숨기지 않는다.
- 개체별 렌더 실행은 정의된 부품/마스크를 사용한다. 한 개체의 완성 그림을 숨겨 넣어 반환하는 방식은 금지한다.

## 4. 내부 수정·검수 화면

이번 화면의 대상은 제작자다. 제품의 사용자 3단계는 유지한다.

- 같은 개체의 얼굴/전신, B2/C2, 1배/정수 확대를 연결해 표시한다.
- 부위 선택, 허용된 제어값, 눈 노출/앞털/연결점 오버레이, 수정 전후 비교를 제공한다.
- 수정은 새 초안으로 저장하고 이전 revision으로 돌아갈 수 있게 한다. 검수 전 초안을 사용 중인 자산으로 자동 전환하지 않는다.
- 사용한 프로필·제작 상태·패키지 버전과 지원 밖 항목을 제작자 화면에서 확인한다.
- 초기에는 로컬 실행으로 한정한다. 공개 웹 서비스·외부 계정·새 서버 인프라는 이번 범위가 아니다.

기존 5개 자동 검사를 회귀 검사로 유지하고, 연결점·가림·변경 영향·지원 범위의 실제 오류를 잡는 검사를 추가한다. 모든 파라미터를 무작위로 섞어 지원한다고 주장하지 않는다. 선언한 조합과 경계 사례부터 검증한다.

시각 검수는 같은 개체의 수정 전후, 정본 B2/C2, 실제 사진의 해당 특징을 내부에서 대조한다. 96 원본 1배와 정수 확대를 모두 보고, 실제 제품 표시 크기가 미정이면 그 검수는 별도 미완료로 남긴다. 연결 결함이 없어도 닮음/정본 화풍이 부족하면 단계 2를 완료하지 않는다. 보호자 외형 수락과 내부 작화 검수는 별도 기록한다.

## 6. 이행과 버전 보존

- v0.1 입력과 렌더러는 고정된 커밋·의존성으로 재실행할 수 있게 보존한다. v0.2가 기존 snapshot을 조용히 다르게 해석하지 않게 한다.
- v0.2 스키마/패키지로 이동할 때는 원본 revision을 참조하는 새 제작 상태를 만든다. 변환한 값·사용한 기본값·미지원 필드와 이유를 기록한다.
- 패키지 버전과 해시를 함께 고정한다. 현재 0.1의 스타일 패키지 승인은 없다. 새로운 0.2 패키지도 정본의 시각 검수 전 승인 상태로 만들지 않는다.
- 생성 실패나 지원 밖 조합은 검수된 기존 결과를 덮어쓰지 않는다. 출력 폴더 덮어쓰기 거절을 유지하고, 완료된 산출물만 생성 기록에 등록한다.
- 실제 사진·프로필·개체 출력은 로컬 비공개 자료로 관리한다. 저장소의 자동 검증에는 합성 입력을 사용한다.

## 7. 실행 순서와 예상 공수

개발 1명과 픽셀 제작 역할을 확보한 경우의 순수 작업일 제안이다. 보호자 대기와 실제 표시 환경 검수는 별도다. v0.1의 제작 속도만으로 전체 완료 일정을 보장하지 않는다.

| 순서 | 작업 | 예상 | 완료 증거 |
| --- | --- | --- | --- |
| 1 | 기준 결함 목록·연결점·관찰/제작 상태 경계 정의 | 1일 | 변경 범위와 실패 사례, 입력/출력 계약 |
| 2 | 목·가슴·다리 연결과 외곽/겹침선 수정 | 1–2일 | V01/V02/V07 통과와 전신 출력 |
| 3 | 개체 얼굴 제어·눈/주둥이/앞털 가림 | 1–2일 | V03/V04, 같은 개체의 얼굴/전신 |
| 4 | 부위 털·작화 패키지·B2/C2 색 역할 | 1–2일 | V05/V06, 지원 길이/부위 목록 |
| 5 | 내부 수정 화면·버전 이행·회귀/시각 검수 | 1–2일 | V08/V09/V10, 결과 보고·미완료 목록 |

합계 5–9작업일 제안이다. 단계 2의 기술·시각 통과 전 동작이나 추가 개체 확대를 끼워 넣지 않는다. 다른 개체에는 현재 구조를 그대로 복제하지 않고, 후속 단계에서 재사용 범위를 검증한다.

## 8. 이번에 남길 산출물

1. 관찰 프로필과 제작 상태를 분리한 버전 계약, v0.1 보존·변환 기록.
2. 연결점 기반의 정면 얼굴/앉은 전신 제작기와 B2/C2 패키지.
3. 부위별 지원 털 옵션과 의미별 마스크·출력 메타데이터.
4. 내부 제작자용 수정·오버레이·전후 비교 화면.
5. 기술 검사 결과, 정본/개체 시각 검수표와 남은 지원 제한.

추가 시안 수를 완료 지표로 삼지 않는다. 결함 수정, 같은 입력 재현, 개체 특징 유지와 정본 미감의 충족 여부로 판단한다. 현재 이 문서는 기획만 완료됐고 v0.2 구현·검증은 시작하지 않았다.
