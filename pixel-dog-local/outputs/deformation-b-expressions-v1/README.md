# B 머리 여섯 가지 표정 적용

> 후속 사용자 평가 ‘괴물 같다, 입도 단순화 필요’로 이 분기의 입 표현은 거절됐다. 새 후보는 [입 단순화·품종별 벌림·혀 지지](../deformation-b-expressions-simple-v1/README.md)이며, 아래 구조 검토 통과는 미감 승인을 뜻하지 않는다.

2026-11-05 턱 구조 수정: 이전 결과는 아래턱이 위치마다 다른 각도로 휘고 입 양쪽 면이 열린 틈을 막아 사용자 거절됐다. 해당 코드는 `preview-mouth-rejected.py`에 보존한다. 이전 `review.md`의 통과는 현재 턱 구조의 검증 근거가 아니다.

사용자가 선택한 **기본·반쯤 감기·눈 감기·입 벌림·혀 내밀기·코 핥기**를 골든 리트리버·휘핏·닥스훈트에 적용했다. 기준은 긍정 피드백을 받은 `deformation-b-round-eyes-v1`의 머리이며 기존 B 머리 배율 1.70을 유지한다. 몸통은 이번 작업에 포함하지 않는다.

## 구현 범위

| 상태 | 적용 |
| --- | --- |
| 기본 | 기존 둥근 눈 머리의 표면·재질 그대로 |
| 반쯤 감기 | 눈 크기·중심은 유지하고 위쪽 눈꺼풀 경계로 눈동자와 반사광을 함께 덮음 |
| 눈 감기 | 눈동자·반사광을 덮고 짧은 눈꺼풀 접촉선 표시 |
| 입 벌림 | 윗머리와 아래턱을 분리하고 아래턱 전체를 같은 관절축 기준 14° 강체 회전 |
| 혀 내밀기 | 같은 턱 개방 + 입안 바닥을 따라 나온 뒤 앞쪽으로 내려가는 닫힌 혀 표면 |
| 코 핥기 | 8° 턱 개방 + 입안에서 나와 코앞을 돌아 실제 코 표면 정점에 혀끝이 닿는 정적 접촉 장면 |

입 곡선의 시작은 기존 사진 등록점이다. 아래턱은 입꼬리에서 끝내지 않고 기존 좌우 턱관절축 뒤까지 연장한다. 아래턱의 모든 정점에 동일한 회전을 적용하며 x 위치별 회전 가중치를 제거했다. 윗머리는 회전하지 않는다. 윗구개와 아래턱 바닥은 각각 만들고, 윗입술과 아랫입술을 전 길이에 걸쳐 잇던 양쪽 면은 제거했다. 측면에서 앞·중간 입 틈을 배경까지 관통해 볼 수 있다.

기존 입선은 일부에서 아래 윤곽에 너무 가까워 얇은 띠가 됐다. 이를 피하기 위해 단면 높이의 22%를 아래턱 최소 두께로 두되 관절 뒤에서 줄인다. 뒤쪽 연장 1.6 모델 단위, 두께, 7°·14° 비교 각도와 8° 코 핥기 각도는 **제작값**이다. 기존 등록점·골격 좌표를 실측 해부학으로 간주하지 않는다. 치아나 새 입술 외곽선은 추가하지 않았으며 기본 표정과 비교판의 닫힘 0° 칸은 기존 머리 그대로다. 닫힘 칸은 절단면을 겹쳐 그린 장면이 아니라 유지한 기본 표정이다.

해부학 참고: [BSAVA의 턱관절 설명](https://www.bsavalibrary.com/content/chapter/10.22233/9781910443286.chap25)은 아래턱 관절돌기와 측두골 사이의 경첩 관절을 설명한다. 이번 구현은 이 회전 관계를 단순화한 리그이며 근육·관절원판·연부조직까지 구현한 해부학 모델은 아니다.

혀는 입안 바닥 위에서 시작하는 폐단면 표면이다. 입안 구간과 밖으로 나오는 구간을 잇고, 코 핥기의 끝은 기존 코 윗면 정점으로 지정한다. 혀색은 별도 작화 재질이며 경로·폭·턱 각도는 실측값이 아닌 제작값이다. 코·눈·귀의 위치를 옮겨 표정을 만들지 않는다. 귀는 모든 상태에서 그대로다.

이는 [얼굴 동작 정책](../../docs/facial-motion-policy.md)의 관찰 가능한 동작을 적용한 정적 시안이다. 행복·슬픔 등 실제 감정을 추정한 결과, 공인 DogFACS 코딩, 헐떡임·호흡 애니메이션 또는 해당 개체의 습관 기록이 아니다. 현재 입안은 단순화한 면이며 정밀 해부학 모델이나 최종 애니메이션 자산으로 표시하지 않는다.

## 재생성

이 폴더에서 `python preview.py`를 실행한다. 원본 머리·골격·사진 프로필 파일은 수정하지 않는다. `recipe.json`에 입력 해시, 시점, 배율, 턱 개방 각도, 혀 시작점·끝점·코 접촉점을 기록한다. 기록한 혀 좌표는 1.70배 확대 전의 v3 머리 로컬 단위이며, 실제 렌더 좌표는 같은 배율을 곱한다. 현재 시안은 사용자 검토 대기다.
