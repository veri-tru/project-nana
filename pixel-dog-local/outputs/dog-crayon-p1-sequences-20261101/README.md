## 표현과 제작값

- P1 점눈·회색/흰색 무늬·짧게 늘어진 귀·수염·낮은 긴 털 꼬리를 참조했다. 후속 편집에는 사용자가 선택한 [약한 외곽선 A](../dog-crayon-outline-levels-20261101/A-weak.png)를 추가 참조했다. 원본 특징을 픽셀 단위로 고정한 편집은 아니며 닮음과 선 강도의 최종 정합성은 검수 대상이다.
- 점눈만 미끄러뜨리지 않고 머리의 방향과 높이로 대상 확인을 표현한다. 시선 방향은 장면상의 의도이며 실제 눈동자 추적이나 생물학적 시야 측정이 아니다.
- 세 장면의 기본 입 상태는 편안한 입 벌림·짧은 혀 보임이다. 시작 전부터 유지하던 제작 변형으로 선택했으며, 새로운 사건이 헐떡임·핥기를 유발했다는 뜻이 아니다. A 6번 프레임만 짧게 눈을 감는다. 혀 접촉 동작은 이번에 제작하지 않았다.
- 기본 간격 125ms(8fps). A의 1·12번은 500ms, 5·7번은 250ms. C의 1·12번은 500ms, 4·7·9번은 375ms. 나머지는 125ms. B는 모든 프레임을 125ms로 표시해 고개 확인 중 발 동작도 이어진다.
- 버튼으로 한 번 재생하고 마지막 프레임에서 멈춘다. 자동 반복은 없으며 다음 프레임 버튼은 수동 검토용이다. 동일 사건의 반복 재생을 보여주는 엔진이 아니다.
- 장난감·사람은 그림 밖의 가상 대상이며 실제 감지 기능이 없다. B는 제자리 걷기다. 화면 이동·동적 대상 변경·중단·상태 전환은 구현하지 않았다.
- 재생 시간과 대상 위치·순서는 모두 제작 기본값이다. 실제 개의 습관·반응 지연·감정·호흡 상태로 기록하지 않는다.

## 제작 및 보존

내장 image_gen으로 장면별 1차 시트를 생성하고, 현재 외곽선 기준으로 장면별 편집을 했다. B의 첫 수정은 정면 확인에 머물러 후측방을 보도록 한 번 더 수정했다. 1차 결과는 *-v1.png, B의 중간 결과는 B-walk-style-only.png로 보존했다. 최종 후보는 *-sheet.png다.

[전체 장면 요청·참조·스타일 편집](prompts.json), [B 고개 방향 보완 요청](walk-correction.json)에 실제 프롬프트를 기록했다. 생성 원본은 프로젝트에 복사했으며 외부 생성 경로에만 의존하지 않는다. [build.cjs](build.cjs)는 빈 경계 분리·여백 추가·평행 이동·명세·미리보기만 작성하며 신체를 절차적으로 다시 그리지 않는다. 기존 P1/P2 이미지와 조사 DB는 유지했다.

## 확인한 것과 남은 검수

완료: 최종 시트의 정적 육안 검토, 3×12 프레임 생성, 동일 출력 캔버스 크기, 빈 프레임 없음, 각 장면의 12개 파일 해시 구분, 원본 사각 영역 추출, 125ms 배수 시간표, [파일 검증](validation.json), [기존 자산·DB 보존](preservation.json), [조사 DB 출처 버전 검증](behavior-db-check.json).

정적 검토에서 머리 방향 변화와 A의 짧은 눈 감김, C의 낮은/높은 대상 확인을 확인했다. B는 후측방 고개와 발 자세 변화를 갖지만 목 회전 폭·보행 위상·지지발의 정합성은 재생 검수가 필요하다. A·C도 몸통·발·귀·무늬가 프레임마다 조금씩 다시 그려져 미세한 흔들림이 남을 수 있다. 시작과 끝은 같은 기본 방향을 의도했지만 동일한 그림은 아니며 반복 경계를 승인하지 않았다. 분리 경계는 인접 프레임의 꼬리 조각이 섞이지 않도록 빈 세로선을 사용했다. 전체 어두운 윤곽 최하단을 y=360에 평행 이동한 시각적 대리값이며 body-root·개별 발 접지점 정렬은 아니다. 피부·털의 밝은 잔여 획과 종이 경계는 재생 검수 대상이다.

남은 3단계: 8fps 실제 재생의 연속성, 실제 표시 크기의 방향·표정 식별, 목/턱/귀의 자연스러움, 발 미끄러짐, 고정 몸통의 흔들림, 전환·복귀 경계, 동적 사건의 중단과 복귀를 검수한다. 최종 해상도·실기기·보호자 닮음·사용자 자산 승인은 별도다.

정책 v1.0은 정본이며, 이 후보의 미검수 상태를 정책 승인으로 덮어쓰지 않는다.

미리보기의 36개 이미지 로딩·수동 다음 프레임·스크립트 오류 없음은 [기본 동작 확인](preview-check.json)에 기록했다. 이는 연속 재생 품질의 합격 판정이 아니다. [정책 연결 검증](policy-check.json)도 별도로 기록했다.
